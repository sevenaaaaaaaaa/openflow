# 一、定位屋

## 1. 一句话

> **别人的增长工具，默认你有一支团队。**
> **芭乐派做的，是给没有团队的人的那一套。**

产品名：**芭乐派**（主品牌）· **OpenFlow**（开源底座，MIT）

## 2. 这个定位是怎么来的（内部逻辑，不对外）

市面上的增长工具，本质是**协作工具**——它们解决的是"多个人怎么配合"：

| 工具 | 它隐含的前提 |
|---|---|
| HubSpot / Marketo | 你有市场团队 |
| Salesforce | 你有销售团队 |
| 神策 / GA4 | 你有数据分析师 |
| WordPress / Webflow | 你有人做开发和设计 |
| Segment | 你有人把这些系统接起来 |

一个人的公司把这五样都买齐，得到的不是一支团队，
而是**五个等着人来喂的系统**——每个都要配置、要维护、要有人看。

> **一人公司缺的从来不是"工具"，是"人"。**
> 而 AI 让"没有人"第一次不等于"做不了"。

这就是芭乐派存在的理由：不做第六个等人来喂的系统，
做一个**自己会干活**的系统。

## 3. 目标人群（按优先级）

| # | 人群 | 他们真实的一天 | 我们解决什么 |
|---|---|---|---|
| 1 | **一人公司 / 超级个体** | 上午写内容、下午回客户、晚上做交付，没人管数据也没人管跟进 | 内容自动产、访客自动认、该跟进的自动提醒 |
| 2 | **知识博主 / 个人品牌** | 内容发了就没了，不知道谁看了、谁该转化 | 从"发内容"到"内容带来成交" |
| 3 | **无团队的小组织** | 三五个人，谁都不是专职做增长的 | 一套系统覆盖内容到成交，不用拼五个工具 |

**不是我们的战场**（要诚实，也要写进文案里）：
已经有成熟市场团队和数据团队的中大型公司。对他们，我们是重复建设。
**主动说出边界，比含糊其辞更能赢得信任**——尤其是面向开发者的开源项目。

## 4. 三样筹码 → 三个可证明的承诺

筹码是内部语言，**对外要翻译成用户听得懂的承诺**：

| 内部筹码 | 对外承诺 | 怎么证明 |
|---|---|---|
| CDP 实时画像 | **你的网站认得出每一个访客是谁、来过几次、在看什么** | 后台实时画像页；匿名→登录自动合并 |
| 常驻 AI 增长引擎 | **它自己爬热点、写草稿、盯转化，你睡觉时它在干活** | 增长引擎五步流程可视；AI 没配也能跑（只是不写稿） |
| MCP / 知识底座 | **你的整个网站可以被 AI 直接调用**，不只是"网站里有个 AI 按钮" | 18 个 MCP 工具，Claude 等 Agent 可直连 |

## 5. 品牌关系（一句话讲清）

> **芭乐派**是增长方法论和门派社区，**OpenFlow** 是它的开源底座。
> 方法论告诉你怎么做，OpenFlow 让你真的能做。

出现规则：
- 站点、社区、课程、活动、方法论 → **芭乐派**
- 代码、部署、GitHub、技术文档、插件生态 → **OpenFlow**
- 页头永远是「芭乐派」，页脚和技术页注明「基于 OpenFlow · MIT 开源」

# 二、事实边界：可以说 / 不能说

> **这一节是所有文案的护栏。** 开源项目的信任成本极高——
> 一句查得出来的假话，损失的不是一个客户，是整个技术圈的口碑。
> 下面每条"可以说"都在代码里核过；每条"不能说"都是核完发现说不了的。

## ✅ 可以说（已核实）

| 说法 | 依据 |
|---|---|
| MIT 开源，可商用、可二次开发、可私有部署 | `LICENSE` |
| 纯 PHP + JSON + SQLite，零外部服务依赖 | 不需要 MySQL/Redis/Node |
| 数据 100% 在你自己的服务器 | 无云端回传；导出功能齐备 |
| 192 个后台功能页 · 92 个 API · 151 个功能模块 | 实际文件数 |
| 18 个 MCP 工具，AI Agent 可直接调用 | `mcp-server.php` |
| 32 个插件钩子，可扩展 | `PluginSystem` |
| 67 个自动化测试套件 | `tests/` |
| 支持 11 种语言界面 | `lib/I18n.php` 语言表 |
| 增长引擎：爬热点 → 总结 → 撰写 → 巡检 → 优化，五步可视 | `GrowthFlywheel` |
| **AI 没配置也能用**，只是不自动写稿——不会白屏 | 优雅降级已测试 |
| 自我体检：从错误日志、404、慢页面、空模块等六个来源自动产出改进建议清单 | `SelfEvolve` |
| 已接好的外部系统：飞书 / 企业微信 / WhatsApp 通知，Notion 双向同步，GitHub 仓库导入，SMTP / Ghost 邮件，虎皮椒支付，Google Search Console | `NotifyChannels` `NotionClient` `api/ingest` `MailChannel` `PaymentChannel` `SeoConsole` |

## ⛔ 不能说（旧文案里有，但站不住）

| 旧说法 | 为什么不能用 |
|---|---|
| 「Platform Intelligence 平台智能层」 | **代码里 0 处**。是个自造的营销名词，技术买家一搜就穿帮 |
| 「市面上**唯一**一个有自我进化能力的增长系统」 | 绝对最高级，无法证明。开源项目说这话是自伤 |
| 「甚至帮你**自动修**」 | `SelfEvolve` 只**产出建议清单**，不自动改代码。改成「自动体检、给出改进清单」 |
| 「每 6 小时自动爬热点写草稿」 | 周期取决于用户自己配的 cron，不是内置固定值。改成「按你设的周期自动运行」 |
| 任何"提升 X%"「帮客户增长 Y 倍」 | 没有真实客户数据之前，一个数都不能编 |
| 「400+ 内置连接器」、钉钉 / Slack / Salesforce / HubSpot / Google Sheets / PostgreSQL 连接器 | **代码里没有**。真实清单见上表「已接好的外部系统」；其余一律说「Webhook / OpenAPI / MCP 自定义接入」 |

> **替代写法**：把"唯一"换成**具体的、可验证的差异**。
> 不说「唯一有自我进化的系统」，说「**它会自己体检，把该修的列给你**——
> 这件事你可以现在就去代码里翻 `SelfEvolve`」。
> **可验证 > 最高级。**

# 五、转化路径与 CTA 体系

## 三条路径，各自的下一步

```
路径 A · 开发者/自部署（主路径）
  首页 → GitHub → 自己装 → 社区 → （需要托管时）托管版

路径 B · 不想碰服务器
  首页/定价 → 托管版试用 → 订阅

路径 C · 有合规要求的组织
  企业版页 → 申请方案 → 人工跟进 → 私有化/定制
```

## CTA 用词统一

| 场景 | 用这个 | 不要用 |
|---|---|---|
| 主 CTA | `在 GitHub 上开始` | 「立即体验」「马上开启」 |
| 托管版 | `开始免费试用` | 「立即购买」 |
| 企业 | `申请方案` | 「联系销售」 |
| 内容页 | `订阅更新` | 「了解更多」 |

> **「了解更多」是最差的 CTA**——它不告诉用户会发生什么。
> 每个 CTA 都要能补完这句话："点了之后我会……"

## ⚠️ 静态页的两条硬约束（踩过一次）

**1. `<meta charset="UTF-8">` 必须有，且必须在文件前 1024 字节内。**
浏览器只扫描开头 1KB 找编码声明；找不到就按 `windows-1252` 猜，中文全变
`èŠ­ä¹æ´¾`。服务器 `Content-Type` 带不带 charset 不能指望——Nginx 默认不带。
`gtm-deck.html` / `gtm-onepager.html` 就是因为缺这行显示乱码，已修。

**2. 前两份带 `noindex, nofollow`。**
它们是发给具体的人看的销售物料，不是要被搜索引擎收录的页面。
如果哪天想让它们进搜索，删掉那行 meta 即可——但先把占位符填完。
