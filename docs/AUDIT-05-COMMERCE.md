# 深度竞品对标 · 05 电商 / 交易（→ 平台运营与商业化）

> 坐标系见 `docs/VISION.md`。评级：🟢 达到主流 / 🟡 能用但浅 / 🔴 缺失或撞墙。
> 对标两类：**单商户卖货**（Shopify / 有赞 / Gumroad）与**双边平台**
> （Whop / Teachable / 各类 App Store / 插件市场）。

## 一句话结论

「电商」在我们这里有**两张脸**，必须先分开，否则会把力气用错地方：

- **第一张脸 · 单商户卖货**（一个人卖自己的东西：课程、付费内容、服务、实物）——
  这块交易管道其实**不弱**：订单/在线付/退款/分销/积分商城/会员余额/作者分成，
  基础都在，对「一人公司卖自己的货」够用（🟢/🟡）。
- **第二张脸 · 双边平台运营与商业化**（skills / 插件 / 主题 / 打包商品 / 课程 /
  付费内容，来自**多个创作者**，平台居中撮合、抽成、治理、赋能）——
  **这块是几乎空的（🔴），也是你点破的「最大的坑、当下最不利的存在」。**

根因不是「缺功能」，是**缺一个平台层**：交易的水管都铺好了
（`ShopSystem`/`CommerceSystem`/`MallSystem`），但没有一个「平台」站在这些水管上
**经营一门生意**——没有统一的商品目录治理、没有运营台（选品/发现/排序/审核/治理）、
没有对创作者的经营赋能（人均分析/营销工具/成长），更没有帮商品和创作者
**做营销**的引擎。三套交易系统各自为岛，连**抽成规则都不统一**
（Mall 20% / Commerce 10% / 分销 20%，散落三处硬编码）。

但真正值得写这份审计的，不是「补一个应用商店」。**在位的应用商店/创作者平台
（App Store / Whop / Teachable）本质是「更好的货架 + 结算」——它们撮合交易，
却不为每个创作者的增长负责。** 而我们整套系统本身**就是一台增长引擎**。
于是有一个别人结构上给不了的东西：**把平台做成「给每个入驻创作者配一支 AI 增长团队」——
不是更好的货架，是让每个上架的人都自动获得选品建议、定价洞察、千人千面的分发
与营销闭环。** 这是把前四个模块的「增长大脑」从**服务一个站长**，
放大到**服务平台上每一个创作者**。

---

## 定位裁剪刀（承接 VISION）

不卷 Shopify 的电商功能全度（多规格/物流/税务/多店铺——那是给专职电商团队的），
也不卷 App Store 的审核工业化与合规体系。我们卷的是两条，且都压在筹码上：

- **单商户**：一个没有运营团队的人，把「有货 → 上架 → 卖出 → 交付 → 复购」
  几分钟跑完，且交易数据**直接回流增长大脑**（成交反哺 CDP/MA/Content，见 Sales）。
- **双边平台**：让平台方（也常常就是一个人 / 一个小团队）**不靠运营团队，
  也能经营一个创作者市场**——选品、分发、抽成、治理、给创作者赋能，
  由 Agent 顶上「平台运营」这个不存在的岗位。

凡「让商品字段/结算规则更全」的先怀疑；凡「让 Agent 替代平台运营、
让平台自动为每个创作者的增长负责」的才是主战场。

## 逐能力对标（先诚实评现状）

### 1. 交易水管：下单 / 支付 / 退款 — 🟢 够扎实

**我们的实现**：`ShopSystem` 有订单、在线支付、退款（含积分/分成的对称回收，
上轮补的）、分销佣金、平台抽成、会员余额、最低提现门槛；`MallSystem` 管实物/
积分商城（下单、扣库存、积分兑换）；`CommerceSystem` 管数字商品
（skill/插件/主题/**组合包 bundle**、佣金率、分销、促销、库存、`publishSkill`、
`deliverOnPaid` 付款即交付）。

**判断**：**交易原语齐全**，对「一个人卖自己的数字/实物货」够用，退款对称性
这种容易埋雷的地方也补过了。这是这块的**底子，是真资产**。

**竞品标杆**：Shopify / 有赞（交易全流程 + 物流 + 营销 + 多渠道）。

**差距**：单商户维度缺的是「电商深度」（多规格 SKU、物流对接、发票税务）——
按裁剪刀**不该卷**。真正的坑不在这条水管，在下面「谁来经营这些水管」。

### 2. 商品目录：跨类型统一管理 — 🔴 三套系统，各自为岛

**我们的实现**：数字商品在 `CommerceSystem`（products.json）、实物/积分在
`MallSystem`（shop/products.json）、聚合浏览在 `MarketplaceSystem`（**只读**
拼装 plugin/skill/theme）。三套各有各的存储、各有各的后台
（`admin/commerce.php` / `admin/mall.php` / `admin/marketplace.php`）。

**判断**：**没有「一个平台的统一商品目录」**。同样是「一件在卖的东西」，
数字货和实物货是两个世界，跨类型的「所有在售商品」根本没有一处能统一看、
统一管、统一治理。这是「岛」的问题，不是「缺字段」的问题。

**最刺眼的证据 · 抽成规则不统一**：
`MallSystem` 佣金 20%（写死 `commission_rate => 20`）、
`CommerceSystem` 平台费 10%（`commerce_platform_fee_rate()` 返回 `0.1`，
`commission_rate` 默认 0.9、`publishSkill` 传 0.7）、
分销佣金又是 20%。**同一个平台，三种抽法，散在三个文件里硬编码。**
一个真的在「经营平台」的人，第一天就会被这个绊倒——他没有一处能设定
「我的平台怎么抽成、怎么分账」。

**竞品标杆**：App Store / Whop（统一目录 + 统一分成政策 + 统一结算）。

**建议（守，P1）**：先做一个**统一商品目录 + 统一分成政策层**——把三套系统
的商品抽象成一个只读统一视图 + 一处可配的分成/抽成策略（platform take rate、
分销率、创作者分成，一处定义、各处引用）。这是「平台」这个词能成立的地基。

### 3. 平台运营台：选品 / 发现 / 排序 / 审核治理 — 🔴 基本空白

**我们的实现**：`FeaturedSystem` 有「置顶/推荐位」——但它是**内容位**
（首页推荐文章那种），**不是市场选品**。`MarketplaceSystem` 有 `mkt_search`
（关键词/类型/排序 popular）和 `mkt_stats`，但**排序是固定规则**（按热度），
没有人工选品、没有编辑推荐、没有分类运营、没有上架审核流、没有违规下架/治理。

**判断**：**没有「平台运营」这个岗位对应的工具**。一个平台方要做的日常——
「这周推谁上首页、这个新插件质量够不够能上架、这个卖得差要不要换位、
这个创作者违规要不要下架」——**一件都没有工具支撑**。这正是你说的
「没有平台运营的功能」。

**竞品标杆**：App Store（编辑推荐 + 审核 + 榜单 + 治理）、
Whop（发现页 + 排序 + 商户治理）。

**建议**：**别去做一套工业化审核后台**（那是给有审核团队的平台）。
AI-native 的运营台见创新层——**Agent 当那个不存在的运营编辑与审核员**。

### 4. 创作者赋能：分析 / 营销工具 / 成长 — 🔴 只有「提现」，没有「经营」

**我们的实现**：`member.php:760` 有创作者收益面板（余额 + 累计销售分成）、
`admin/distribution.php` 有提现审核、`authors.php`（上轮做的作者实体）。

**判断**：创作者能**看到钱、能提现**，但**得不到任何「怎么把货卖得更好」的帮助**——
没有人均销售分析（谁在看、卡在哪、为什么不买）、没有给创作者的营销工具
（他不能对自己的买家做触达/复购/个性化）、没有成长建议。**平台对创作者是
「收银台 + 提现口」，不是「经营伙伴」。** 这正是你说的「无法对创作者进行赋能，
也没办法帮助他们进行进一步的营销动作」。

**竞品标杆**：Teachable / Gumroad（给创作者基础分析 + 邮件营销 + 优惠券）、
Whop（给商户 affiliate + 营销位）。

**建议**：见创新层——**这是我们最大的结构性机会**：我们整个系统就是增长引擎，
把它**多租户化**下放给每个创作者，别人给不了。

### 5. 商品营销引擎：帮货和创作者卖 — 🔴 缺（散点促销 ≠ 营销）

**我们的实现**：`CommerceSystem` 商品上有 `promo` 字段（单品促销）、
上轮的 `PromoSystem` 是**站内营销位**（站长自己投放），`MallSystem` 有积分/券。

**判断**：这些是**孤立的促销开关**，不是「平台帮所有商品做营销」的引擎——
没有跨商品的活动（大促/榜单/捆绑推荐）、没有把某个商品接进 CDP/MA 做定向分发、
没有「买了 A 的人推 B」的平台级推荐。你要的「帮助他们进行进一步的营销动作」，
现在只能靠创作者自己在单品上填个促销价。

**竞品标杆**：有赞（平台营销中心：满减/拼团/分销/直播）、
App Store（编辑推荐即分发）。

**建议**：见创新层——**平台级分发本就是我们 CDP+MA 的天然延伸**，
把「站长给自己投放」升级为「平台为每个商品找到对的人」。

## 创新层：平台 = 给每个创作者配一支 AI 增长团队

> 这一节是这份审计的意义所在。前四个模块把「增长大脑」建给**一个站长**；
> 电商这块的机会，是把同一个大脑**放大成一个双边平台的操作系统**——
> 让平台上**每一个创作者**都自动获得他本来请不起的增长团队。

### 洞察：在位平台是「货架」，我们能做「增长引擎」

App Store / Whop / Teachable 的本质是**更好的货架 + 结算 + 流量入口**——
它们撮合交易，但**不为每个创作者的增长负责**：创作者上架后卖得好不好，
平台只在乎抽成，营销/分析/复购要创作者自己想办法（或另买工具）。
**这是所有创作者平台的共同天花板：平台只做撮合，不做增长。**

而我们不一样——**我们本身就是一台跑给「一个人」的完整增长引擎**
（CDP 画像 + 常驻 AI 引擎 + MA 决策 + 内容生成 + Sales 成交）。
把这台引擎**多租户化**，就得到一个别人结构上给不了的平台：
**不是货架，是「每个入驻创作者都自带一支 AI 增长团队」的平台。**

### 创新一：平台把「增长大脑」下放给每个创作者（多租户增长引擎）

**做什么**：创作者上架商品，平台不只给他一个收银台，而是给他一套**属于他自己
买家的**增长能力——都由已有系统多租户切片而来：
- **他的 CDP 切片**：谁看了他的课/插件、看到哪一步走了、谁复购——他自己的画像。
- **他的 AI 增长引擎**：Agent 自动给他选题（「你的买家常问 X，写篇内容」）、
  定价建议（「同类卖 Y，你可以试 Z」）、复购触达（「这批人 30 天没回来」）。
- **他的营销闭环**：对自己的买家做个性化分发/复购/追加销售，用的是平台的 MA/内容。

**为什么在位者做不到**：App Store/Teachable 的产品形态是「货架」，
给每个商户配一台增长引擎不在它的架构里，也不在它的商业模式里
（它靠抽成，不靠让每个商户增长）。**我们的产品形态本就是增长引擎，
下放它是自然延伸，不是重造。** 这是「新产品对在位者的结构性机会」在电商这块的落点。

**第一步**：创作者后台从「收益 + 提现」升级为「我的买家画像 + Agent 给我的
3 条本周增长动作（选题/定价/复购各一条）」——CDP 切片 + GrowthEngine 现成，
先只读建议、一键采纳。

### 创新二：Agent 当平台运营编辑与审核员（补运营台空白）

**做什么**：平台方（常常一个人）请不起运营团队，让 Agent 顶上：
- **选品/发现**：Agent 读全平台成交 + 画像，产出「本周该推谁上首页、
  该给哪个新品曝光、哪个在掉要换位」——带理由，人一键采纳（对齐 Sales
  的「Agent 当销售经理」，这里是「Agent 当运营总监」）。
- **质量/审核**：新品上架，Agent 先做一轮质量/合规体检（描述是否夸大、
  资产是否完整、定价是否异常），给人一个「建议通过/需改/建议拒」的初判 +
  理由，人做最终关口（护栏内自治，高风险留人）。
- **排序不再是死规则**：从固定 `popular` 升级为「Agent 按平台目标 + 实时表现
  动态排」，且可解释（为什么这个排前面）。

**为什么在位者做不到**：App Store 的审核/编辑是**工业化人力**（成百上千审核员），
中小平台学不起、也养不起。我们用**已有的画像 + 成交数据 + AI**，
做一个**轻量但实时**的运营 Agent，正好落在「无运营团队也想开个市场」的空白里。

### 创新三：平台级分发 = 让 CDP/MA 为「对的人」找「对的商品」

**做什么**：把上轮的「站长给自己投放」升级为**平台为每个商品找到对的人**：
Agent 把每个上架商品当作一个「可分发的动作」，接进平台的 CDP/MA——
对「买了 A 的人推 B」、对「某分群」定向曝光某创作者的课、
在个性化内容/CTA 里现场推荐此刻这个人最可能买的商品。
**创作者什么都不用配，平台的增长大脑替他把货送到对的人面前。**

**为什么在位者做不到**：有赞的营销中心是「给商户一堆工具自己配」，
App Store 是「编辑人肉推荐」——都不是「平台的 AI 逐人决策把每个商品分发出去」。
我们的 CDP+MA 本就在做逐人决策（MA 创新），把商品接进去是同一套大脑的延伸。

**第一步**：结账/内容页的个性化推荐位，从「规则/热度」升级为「Agent 按当前
访客画像，从全平台商品里现选最可能成交的一件」——CDP + Personalizer + 商品目录
现成。

### 创新四：统一分成与结算政策（守，但缺了平台不成立）

**做什么**：把散在三处的抽成（Mall 20 / Commerce 10 / 分销 20）收进**一处
可配的平台分账政策**——平台 take rate、创作者分成、分销/联盟佣金，
一处定义、各交易系统引用；结算/提现走统一账本。这是「守」，但**没有它，
平台方连「我这个市场怎么抽成」都设不了，上面三个创新都无处落。**

## 我们能做什么 · 按可行性排

**现成筹码、近可落地：**
1. **统一分成/结算政策层**（创新四）：把三处硬编码的抽成收成一处可配策略 +
   统一账本。守，但**是平台成立的地基**。**P1**。
2. **创作者增长后台 v1**（创新一第一步）：把「收益+提现」升级为「我的买家画像 +
   Agent 三条本周增长动作」。CDP 切片 + GrowthEngine 现成。**攻，P1**。
3. **平台运营 Agent · 选品驾驶舱**（创新二）：Agent 出「本周推谁/曝光谁/换谁」+
   新品上架质量初判。成交数据 + 画像 + AI 现成。**攻，P1**。

**要更多投入：**
4. 统一商品目录（跨 Mall/Commerce 的只读统一视图 + 统一管理）。守，P1–P2。
5. 平台级 AI 分发（创新三）：商品接进 CDP/MA，逐人推荐/定向曝光。攻，P2。
6. 渐进自治的运营护栏（审核关口、异常下架、可解释排序）。P2。

## 小结

- **先分两张脸**：单商户卖货（交易水管🟢，够用，不该卷电商深度）
  vs 双边平台运营与商业化（🔴，你点的「最大的坑」）。力气全压在第二张脸。
- **坑的根不是缺功能，是缺平台层**：水管都铺好了，却没有一个平台站在上面
  经营生意——无统一目录、无运营台、无创作者赋能、无商品营销引擎，
  连抽成都三套各抽各的。
- **别做「更好的货架」**：在位创作者平台（App Store/Whop/Teachable）只做撮合，
  不为每个创作者的增长负责——这是它们的结构天花板。
- **我们的结构机会 = 增长引擎多租户化**：我们本身就是一台跑给一个人的增长引擎，
  把它下放给平台上每一个创作者，就是「给每个入驻者配一支 AI 增长团队」的平台。
  Agent 同时顶上创作者缺的增长团队、平台缺的运营总监、以及把每个商品分发给
  对的人的决策位。
- **收束**：Sales 是增长大脑离钱最近的器官；电商这块是把这颗大脑**从服务一个站长，
  复制成服务一群创作者**——同一个「懂每个人、会判断、会行动」的增长大脑，
  在双边平台上跑成 N 份。至此产品的野心清晰了：不是又一个建站/电商工具，
  是**一台可以下放给无数人的增长引擎**。
