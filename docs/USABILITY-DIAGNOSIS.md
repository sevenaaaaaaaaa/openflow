# 可用性诊断（2026-09-20）

> 这份文档不是"我觉得哪里不好用"，而是**先算清楚，再谈改什么**。
> 所有数字都能用一条命令复现（见 §1），口径写在脚本里，改口径要一起改测试。

---

## 1. 方法与可复现证据

```bash
php scripts/usability-audit.php          # 人读报告
php scripts/usability-audit.php --json   # 机器可读（诊断/CI 都用它）
php tests/usability_ratchet_test.php     # 棘轮门禁：只许变好
```

**为什么要绕权限**：本地没有服务器真源的角色定义，导航会被权限过滤成空。
脚本临时造一个"全权限"角色（临时 `OF_DATA_DIR`）**只用于枚举结构**，不碰真实数据。

**四类入口来源**（口径明确，避免把"藏在 tab 里"误判成"没有入口"）：
侧栏导航树 / 命令面板（⌘K）/ 站内代码引用（任何 `/xmp/<页>` 链接，排除自身）/
默认落地页。另外单独识别：`.htaccess` 里的 **301 旧地址别名**、被 include 的**片段文件**（非页面）、
以及"疑似 tab 页的独立版本"。

## 3. 关于"真实用户卡在哪"：**目前没有数据，所以不下结论**

诚实说明（这是本诊断最重要的部分）：

| 数据源 | 线上现状 | 含义 |
|---|---|---|
| 404 记录 | **无记录** | 没有真实用户在踩空（或没被记录） |
| 前端 JS 报错 | 1 条（测试数据） | 无法据此判断交互故障 |
| 管理员操作审计 | **空** | 不知道他们实际在做什么、顺序如何 |
| 体检建议（交互/路由/性能类） | **无** | 自动体检也没抓到交互问题 |

**结论**：现在任何"用户在某一步卡住"的说法都是**假设**，不是证据。
所以下面把卡点分成"结构性（可算，已成立）"与"假设性（需验证，附验证方法）"两块。

---

## 4. 结构性卡点（不需要用户数据即成立）

**S1｜入口过载 + 搜索失效（影响面最大）**
- 证据：150 个侧栏入口（65 直达 + 85 二级）；96 个页面**只有**侧栏入口；⌘K 只索引 41/222（18%）
- 为什么是卡点：新手面对 150 个未知选项无法决策；老手想"直接跳到某页"时，78% 的页面搜不到
- **最小干预**：把 ⌘K 从"手工登记"改成**自动索引全部后台页**（导航树 + 各页 `admin_header('标题')`
  作为索引源）。不新增入口、不改导航结构，只让"已经存在的页面"可达。
- 可测：`palette_indexed` 41 → 222；棘轮门禁守住只增不减

**S2｜空态不给出路**
- 证据：82 个页面空的时候只写「暂无」，没有"下一步做什么"
- 为什么是卡点：新站/新模块大量处于空态（内容、课程、活动、表单…），
  用户第一次进来看不到任何可做的事，只能退出
- **最小干预**：先改**被引用最多**的 10 个列表页（articles/content-hub/courses/orders/leads/forms/
  events/downloads/podcasts/reviews），每页空态加一句"下一步" + 一个直达按钮
- 可测：`without_next_action` 82 → ≤72；棘轮守住

**S3｜后台没有窄屏兜底**
- 证据：109 个页面无任何 media query / 横向滚动处理
- 为什么是卡点：一个人做公司常在手机上处理"看一眼/批一下"，而现在手机上大概率是横向溢出
- **最小干预**：先做**全局兜底**（`admin-ui.css` 里给 `.main/.panel/表格` 加溢出与卡片降级），
  再按真实使用频次逐页优化——不要一上来逐页改 109 个文件
- 可测：`with_hint` 113 → 上升；再用 `scripts/audit-devices.py` 加后台页宽度扫描

**S4｜两个真孤岛 + 地址重复**
- 证据：`languages`、`notion-sync` 无入口；11 个页面是 301 别名（同屏两套地址）
- **最小干预**：孤岛二选一（给入口 或 删文件）；别名统一为"父页 ?tab= 唯一地址"，
  旧地址只保留 301

## 5. 假设性卡点（需要先埋点验证，不要先改界面）

| # | 假设 | 为什么怀疑 | 怎么验证（埋点/留痕） | 若成立的最小干预 |
|---|---|---|---|---|
| H1 | 新管理员首登后在"选角色"这步流失 | 有角色浮层，但没有后续转化数据 | 记录 `role_pick`（选了/跳过）与之后 24h 内的首个动作 | 让浮层直接跳到一个具体任务（而不是只改文案） |
| H2 | 多数人只用 5-10 个页面，其余从不打开 | 222 页 vs 审计日志为空 | 打开审计日志（已有 `audit_auto`），按页统计 PV/UV | 按真实使用**裁剪导航**（把低频页收进"更多"），而不是继续加 |
| H3 | 空态是主要退出点 | 82 页只有「暂无」 | 在空态上加"从这里离开/停留时长"事件 | 即 S2（所以 S2 值得先做，无论 H3 成立与否） |
| H4 | 长表单/多步流程是流失点 | 无数据 | 记录步骤级事件（开始/放弃/完成） | 拆步 + 保存草稿 |

**原则**：H1/H2/H4 在拿到数据前不要动界面——否则就是"凭感觉改 UI"，正是要避免的。

---

## 6. 建议的执行顺序（按"证据强度 × 影响面"）

1. **S1 ⌘K 自动索引**（证据最硬、改动最小、立刻可测：18% → 100%）
2. **S2 空态补下一步**（先 10 个高频列表页，配 CI 棘轮）
3. **补埋点**（审计日志已存在但为空 → 先让它真的记录页面访问；这是 H2/H4 的前提）
4. **S3 后台窄屏全局兜底**（一处生效，再逐页）
5. **S4 孤岛/别名清理**（一次收口）
6. H1/H4 等数据回来再谈

---

## 7. 明确不做（现在）

- **不加"首次使用向导"**：在没有数据证明用户卡在第一步之前，加向导只会增加一层要维护的界面
- **不重排导航结构**：在不知道真实使用分布之前重排，等于用猜测替换现状
- **不做"一键体验数据"**：先看空态到底是不是退出点（H3）再决定

---

## 8. 门禁（防止变回原样）

`tests/usability_ratchet_test.php` 已把四个指标钉住（棘轮：只许变好）：

| 指标 | 基线 | 方向 |
|---|---|---|
| 命令面板覆盖页数 | 41 | ≥ |
| 可疑孤岛 | 2 | ≤ |
| 空态只写「暂无」 | 82 | ≤ |
| 无窄屏线索 | 109 | ≤ |

后续每次改善（如 S1 做完覆盖变 222），**同步抬高基线**，这就是"更易用"的定量推进方式。
