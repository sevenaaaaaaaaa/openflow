# 芭乐派产品矩阵 · 差异化定位 brief（v1）

> 本文档是发给五个产品项目的定位共识。每个产品是**独立产品**，靠差异化收割各自的人群；
> 产品之间是 **API 互通的协作关系**，不是母子依赖关系。任何一页宣传语都不得把其他产品
> 写成「本产品的某个模块」。

---

## 一、矩阵总览

| 产品 | 一句话定位 | 对 CMS/CDP 依赖 | 核心场景 | 收割人群 |
|---|---|---|---|---|
| **OpenFlow** | 全站增长操作系统（内容·数据·触达·销售四力合一） | 深度依赖（自家 CMS + CDP） | 一人公司/企业要一整套增长系统 | 要 all-in-one、愿意整套采用的用户 |
| **MFlow** | 轻量版 OpenFlow：内容生产 → 分发 → 触达 | **低**（不要求 CDP，CMS 兼容现成的） | 内容生产、多平台分发、轻触达 | 内容营销者、创作者、电商卖家——已有网站/CMS/公众号，缺「生成与分发」 |
| **Webs Flow** | 落地页专精工具 | **无**（不需要 CMS） | 投放承接页、活动页、广告落地页 | Meta/TikTok/Google 投手、独立站卖家、活动运营 |
| **UserLoop** | 独立的全域营销数据中枢 | **无**（不依赖 OpenFlow CDP，向外打通更多数据源与 MA） | 全域用户数据打通、跨平台 MA 对接 | 多平台/多品牌运营团队、代理商 |
| **inFlow** | 情报增长站（外部数据驱动） | **无**（依赖的是外部平台数据：媒体/社媒/搜索/舆情） | 趋势、竞品、舆情、选题情报 | 品牌方、市场研究、内容策划、投研型增长 |

**记忆锚点**：
- OpenFlow = 全家桶（深水区）
- MFlow = 生成+分发轻量机（内容人群）
- Webs Flow = 单点极致：落地页（投放人群）
- UserLoop = 全域数据中枢（数据人群）
- inFlow = 外部情报站（情报人群）

## 二、每个产品的差异化任务书

### 2.1 inFlow（Insight Flow）— 情报增长

**独立价值主张**：不需要你部署 CMS/CDP，只需要你的关键词、竞品和行业——
inFlow 替你盯外部世界：媒体、社媒、搜索趋势、舆情、竞品动态。

**必须做出来的成绩**：
- 情报采集：搜索 API（Google/Bing/百度/SerpAPI）+ RSS + 社媒多源
- 舆情监测：主题订阅 → 情感分析 → 预警
- 竞品情报：竞品内容节奏、渠道动作、产品更新追踪
- 交付物：晨报/周报/选题雷达——「今天该做什么」的情报出口

**与 OpenFlow 的交集与边界**：
- OpenFlow 的 insight 面向**自己站点**的内容增长（采集→选题→发布→效果）
- inFlow 面向**外部世界**的情报（趋势→机会→预警）
- **API 互通约定**：inFlow 情报经 API 回填 OpenFlow 选题库；
  OpenFlow 内容表现数据回传 inFlow 做效果校准。
  已有落地：`plugins/insight-flow/`（HMAC 出站 + API 回读双向通道）。

### 2.2 MFlow — 轻量内容生产与分发机

**独立价值主张**：专门解决「内容生产、分发、触达」，是轻量版 OpenFlow。

**必须做出来的成绩**：
- 生成兼容度：接多家模型产文/产图/产脚本，不锁供应商
- 分发兼容度：公众号、知乎、小红书、邮件列表等渠道适配器
- 轻依赖：不要求用户上 OpenFlow CMS/CDP——用现成 CMS、Shopify、公众号后台都行
- 触达轻量：邮件/社群通知即可起步，不强推工作流编排

**收割人群**：内容创作者、独立电商卖家、公众号矩阵运营——他们要的不是操作系统，是「帮我写完并分发出去」。

### 2.3 Webs Flow — 落地页专精

**独立价值主张**：专精落地页制作（与 OpenFlow 面向全站的建站有本质区别）。

**必须做出来的成绩**：
- 投放承接页速度战：从素材到上线以小时计
- 35 种展示区块 + 组件工厂直接服务「一个活动一套页面」
- 投放原生：UTM 归因、广告平台像素、A/B 分流、表单直连 MA
- 无头 API：投放团队的工程师可以自己接管渲染

**收割人群**：投手、DTC、活动运营——他们不用全站 CMS，只要能赢的落地页。

### 2.4 UserLoop — 独立的全域营销数据中枢

**独立价值主张**：不是「OpenFlow CDP 的赋能件」，而是独立的全域营销工具：
打通更多数据源、对接更多 MA。

**必须做出来的成绩**：
- 全域埋点：一行 JS + 插件级接入 + 服务端 API 直推
- 外部数据打通：广告平台、电商平台、社媒平台的数据接入
- MA 对接器：不只对接 OpenFlow——对接用户现有的第三方 MA（Webhook/API 适配器）
- 身份合并与画像分群保持独立完备（这是它自己的硬本事）

**收割人群**：多平台运营团队、代理商——他们要的是「数据一处清、MA 随便接」。

### 2.5 OpenFlow — 全站增长操作系统

**定位不变**：四力合一的底座，all-in-one 人群的答案。
**与矩阵关系**：是矩阵中最重的一件；其余四件是它在不同人群、不同依赖假设下的
产品化变体。用户从轻量产品进入后，想升级全家桶时无缝迁移。

## 三、互通关系（API 层面，谁都不依赖谁）

```
inFlow（外部情报）──情报回填选题──▶ OpenFlow / MFlow
OpenFlow / MFlow（内容表现）──效果校准──▶ inFlow
UserLoop（全域数据）──人群/事件──▶ 任何 MA（含 MFlow、OpenFlow、第三方）
Webs Flow（落地页表单/转化）──事件──▶ UserLoop / 任何 MA
OpenFlow（底座）──想引入情报/落地页/全域数据──▶ inFlow / Webs Flow / UserLoop
```

**互通原则**：
1. 一切互通走公开 API（HMAC 签名 / API Key），不共享数据库
2. 每个产品独立可用——拔掉任何一个，其余照常运行
3. 互通是**增益**而非**依赖**：宣传页不得出现「必须先装 X」

## 四、对外话术红线（防内耗）

- ❌ 「MFlow 是 OpenFlow 的营销模块」→ ✅ 「MFlow 是轻量的内容生产与分发引擎」
- ❌ 「UserLoop 需要 OpenFlow CDP」→ ✅ 「UserLoop 独立运行，能对接你现有的任何 MA」
- ❌ 「Webs Flow 是 OpenFlow 的建站功能」→ ✅ 「Webs Flow 专精落地页，从素材到上线以小时计」
- ❌ 「inFlow 是 OpenFlow 的洞察功能」→ ✅ 「inFlow 盯外部世界：趋势、舆情、竞品」
