# 深度竞品对标 · 04 销售 Sales（CRM + 在线成交 + 客服）

> 坐标系见 `docs/VISION.md`。评级：🟢 达到主流 / 🟡 能用但浅 / 🔴 缺失或撞墙。
> 对标：Salesforce、HubSpot Sales、有赞（交易+客户）、Intercom（对话式客服/销售）。

## 一句话结论

Sales 的三块里，**CRM 管道**这几轮补得不错（阶段/看板/公海/分配/评分/预测/ARR +
收款链接 + 交付跟踪），对一人公司够用；**在线成交**（收款链接→自动成交入管道）
是我们独有的轻量优势；但**客服是散的**（咨询预约 + 站内信 + 微信各一摊，
没有统一会话/在线聊天），**管理者↔销售之间没有数据共鸣**（无全员战报/教练）。

更根本的问题你已经点破：**Sales 现在仍是很重的"CRM 痕迹"——一个记录系统**
（录线索、挪阶段、填跟进）。CRM 这个品类的原罪就是"**人把信息录进去，
再靠人去看、去判断、去行动**"，数据录进去就死在记录里。AI-native 的 Sales
不该是"更好用的记录本"，而该做两件现有 CRM 结构上做不到的事：
① **把 Sales 变成增长大脑的双向节点**——CRM 是全公司离钱最近的真相来源，
把它反哺 CDP/MA/Content，给出营销动作需求；
② **让 Agent 当那个不存在的销售管理者/教练**——实时汇总所有销售进度，
基于全局给管理者和销售各自的下一步动作，连物料和话术都备好。

---

## 定位裁剪刀（承接 VISION）

不卷 Salesforce 的配置深度（自定义对象/工作流/报表——那是给有销售运营团队的
大厂配的）。我们卷的是：**没有销售运营、没有销售经理、甚至就一个人**，
也能像有一整个销售团队 + 一个好教练那样运转。凡"让 CRM 字段/流程更强大"的
先怀疑；凡"让 Agent 替代销售运营与管理"的才是主战场。

## 逐能力对标（先诚实评现状）

### 1. 线索与管道（Pipeline）— 🟢 对目标人群够扎实

**我们的实现**：`CrmSystem` 有阶段（new→…→won/lost）、看板、公海（未分配池）、
分配/交接、评分（自动+手动）、跟进记录、重复查重、加权管道金额、
销售预测、ARR、客户生命周期；上轮又加了未跟进自动提醒、阶段变化接事件总线。

**判断**：管道这块**达到中小团队 CRM 水准**，且比多数自建强（有预测/ARR/查重/
公海）。对一人公司/小团队，够用。

**竞品标杆**：Salesforce/HubSpot（自定义管道 + 工作流 + 报表 + 权限，为大团队）。

**差距**：(a) 无多管道（不同业务线不同阶段）；(b) 无字段级自定义；(c) 权限粗。
但这些都是"大团队配置深度"，按裁剪刀**不该卷**。真正的短板不在这里，在下面。

### 2. 在线成交（Quote→Pay）— 🟢 我们独有的轻优势

**我们的实现**：收款链接/报价单 → 客户在线付 → 自动推进 CRM 为已成交、
金额进管道；交付阶段 + 待办盯"钱到活没完/该催尾款"（前几轮做的）。

**判断**：**这是差异化**——把"销售管理"和"实际收钱+交付"焊在一条记录上，
Salesforce 到"赢单"就交给别的系统，有赞偏电商标品交易。对一人公司
"聊单→收款→交付"一条龙，是我们的甜点。

**差距**：缺合同/电子签、分期/订金尾款的结构化（现在靠待办凑）、发票。

**建议**：P1 补"订金+尾款"结构化与简单合同/电子签占位——都在"一个人做项目制
生意"的刚需上。

### 3. 客服 / 对话（Service）— 🔴 散，无统一会话

**我们的实现**：`consultation`（1v1 预约，不是聊天）、`messages`（站内信/广播）、
`wechat-messages`（微信）。**没有统一会话收件箱、没有网站在线聊天、没有工单**。

**判断**：这是明显缺口。访客想问一句话找不到人；表单/评论/私信/微信分散在
各处，无一处汇总。对"官网获客+转化"，这是直接的漏斗流失。

**竞品标杆**：Intercom/有赞客服（统一会话 + 在线聊天 + 机器人 + 工单 + 转人工）。

**建议**：**不去做一个传统 Intercom**（工单系统重）。AI-native 的客服就是
前面内容/CDP 创新里的**站点 Agent**——从本站内容现答、带画像、答完顺势成交、
搞不定转人工并落一条会话。见创新层。

### 4. 管理者 ↔ 销售（Team）— 🔴 无数据共鸣（你点的）

**我们的实现**：有 owner/分配/公海，能看单个销售名下的线索。但**没有管理者
视角**——没有全员战报、没有"谁的管道健康/谁在掉单"、没有给销售的教练建议。

**判断**：这正是你说的"个人销售和管理者之间没有任何有效的数据共鸣"。数据
录进去了，管理者要靠自己一个个翻；销售也得不到"我下一步该干嘛"的指引。

**竞品标杆**：Salesforce（管道审阅/预测/仪表盘，但要人配、要人看）、
Gong/Clari（对话智能 + 预测，重、贵、面向大销售团队）。

**建议**：见创新层——**让 Agent 当那个不存在的销售经理**。

## 你的两个想法 = Sales 的 AI-native 内核

你说"如何加 AI Agent 驱动还没想好"。先分清两层：

- **桌面级 AI（别的 CRM 也在做，是守不是攻）**：自动提醒推进度、总结当前分数、
  给下一阶段重点。这些要做（体验好），但**不构成差异化**——HubSpot/Salesforce
  的 Einstein/AI 也在做。
- **真正 AI-native 的两件事（你点的，是攻）**：下面两条，是现有 CRM **结构上**
  做不到、且正压在我们"增长大脑"筹码上的。

### 创新一：Sales 作为增长大脑的**双向节点**（CRM 反哺 CDP/MA/Content）

**洞察**：CRM 是**全公司离钱最近的真相来源**——什么话打动了客户、什么异议卡住
成交、哪个来源/分群的线索**真的成交**（而非只是访问多）。现有 CRM 把这些
埋在跟进记录和赢单/丢单里**死掉**了，最多做个报表给人看。

**AI-native**：Agent 持续挖 CRM 里的成交/丢单信号，**反向喂给另外三个模块，
并给出具体营销动作需求**：
- **→ CDP**：哪个分群真成交、真值钱 → 修正打分/生命周期/人群定义（纠正
  "访问多≠值钱"的偏差）。
- **→ MA/个性化**：赢单话术、高频异议的破解 → 变成个性化文案与 NBA 的素材
  （"对这类人，用这个说法"）。
- **→ Content**：反复出现的异议/问题 → 选题需求（"该写一篇讲清 XX 的文章/
  FAQ"），补进内容池，也喂站点 Agent。

**为什么现有 CRM 做不到**：它们是**终端筒仓**——线索进来、赢单结束，数据不回流。
而我们四个模块本就在一个系统里、共享 CDP 与事件总线，**回流是天然的**。
这把 Sales 从"消费线索的终点"变成"给全增长系统供真相的源头"。**没有任何
CRM 给得了这个闭环。**

**第一步**：赢单/丢单时，Agent 生成一条结构化信号（打动点/异议/来源/分群），
写回 CDP 画像标签 + 产出一条"营销动作建议"（给 MA/Content 各一条）。

### 创新二：Agent 当**实时销售经理 + 教练**（补上管理者↔销售的共鸣）

**洞察**：无团队的用户没有销售经理；有小团队的，经理也顾不过来实时看每个人。
这个"经理"角色,人做既慢又主观,正是 Agent 该顶上的位置。

**AI-native**：一个常驻的销售 Agent，实时做三件事：
- **对销售**：基于这条线索的画像 + 历史 + 全局赢单模式，给"这一单下一步该干嘛"——
  而且**把物料和话术都备好**（该发哪个案例、用什么说法破这个异议、报价单
  草稿）。销售拿来即用，不用自己想。
- **对管理者**：实时汇总**所有销售的进度**——总管道、谁健康/谁掉单、哪些大单
  该介入、整体预测；并基于全局给管理者下一步动作（"这三个人的 A 类单卡在
  报价，统一给个折扣策略"）。
- **对齐两端**：管理者的策略与销售的执行由同一个 Agent 串起来，数据共鸣实时
  发生——不再是"经理翻 CRM、销售填 CRM"两张皮。

**为什么现有 CRM 做不到**：Gong/Clari 这类"收入智能"重、贵、要接会议录音，
面向大销售团队；中小客户用不起、也没数据量。我们用**已有的画像 + 事件 +
AI**，做一个**轻量但实时**的销售教练，正好落在无团队/小团队的空白里。

**第一步**：一个"销售驾驶舱"——Agent 每日（或实时）产出：全员管道快照 +
每条重点单的下一步动作 + 现成话术/物料草稿；单人视图给销售，汇总视图给管理者。

### 创新三：AI-native 客服 = 会卖的站点 Agent（顺带补客服缺口）

**洞察**：传统客服（工单/在线聊天）是成本中心；AI 时代的客服该是**收入触点**。

**AI-native**：把散落的客服收进一个**站点 Agent**（与内容/CDP 创新同一个）——
从本站内容现答、带画像答、答完顺势给收款链接/留资、搞不定转人工并把整条
会话 + 画像交接给销售（直接进 CRM）。**客服、售前、成交在一个对话里闭环。**

**第一步**：统一会话收件箱（先把表单/评论/私信/微信汇一处）+ 站点 Agent 现答，
未解决一键转人工并建 CRM 线索。

## 我们能做什么 · 按可行性排

**现成筹码、近可落地：**
1. **销售教练/驾驶舱**（创新二）：Agent 出全员管道快照 + 每单下一步 + 话术物料
   草稿。画像 + 事件 + AI 全现成，直接补"管理者↔销售无共鸣"的空白。**攻，P1**。
2. **赢单/丢单信号反哺**（创新一第一步）：成交时产出结构化信号，写回 CDP +
   给 MA/Content 一条营销动作建议。**攻，P1**。
3. **桌面级 AI**（守）：自动提醒推进度、总结分数、下一阶段重点。体验必需，
   但明确是守不是攻。**P1**。

**要更多投入：**
4. 统一会话收件箱 + 站点 Agent 客服（创新三，也补客服硬缺口）。**P1–P2**。
5. 订金/尾款结构化 + 简单合同/电子签（在线成交深化）。**P2**。

## 小结

- **CRM 痕迹的病根**：它是记录系统——人录、人看、人判断、人行动，数据死在
  记录里。AI-native 不是"更好用的记录本"，是让数据**回流**（反哺增长大脑）
  和让 Agent **替人判断与行动**（当销售经理/教练）。
- **两件真正 AI-native 的事（你点的）**：① Sales 反哺 CDP/MA/Content，给营销
  动作需求——把 Sales 从终点变成真相之源；② Agent 当实时销售经理，实时汇总
  全员、给管理者与销售各自的下一步 + 备好物料话术——补上管理者与销售的数据共鸣。
- **客服**别做传统 Intercom，用会卖的站点 Agent 补，顺带把客服从成本中心
  变成收入触点。
- **收束**：Sales 是增长大脑离钱最近的那个器官——它既向大脑供真相（成交信号），
  又受大脑指挥（Agent 决策落到成交动作）。至此，内容/CDP/MA/Sales 四个模块的
  创新完全指向同一个东西：**一个懂每个人、会判断、会行动、还会自我校准的
  增长大脑。**
