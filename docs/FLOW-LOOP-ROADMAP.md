# Flow / Loop 产品开发路线

> 状态：规划。本文只描述新方向如何渐进落地，不将规划能力表述为现状。

## 总原则

不重写现有 AITIPS，不一次性切换用户心智，不建设第二套业务实现。先建立共享契约，再用一个真实闭环验证 Loop；每一步都可独立发布、关闭和回退。

## 成功标准

- Flow 原有路径与数据兼容，关键回归测试不下降。
- Loop 产生的对象可以在 Flow 中查看、编辑、暂停和接管。
- AI 不可用时，Flow 完整可用，Loop 保留状态并明确降级。
- 每次 Loop 运行有输入、证据、步骤、成本、审批、输出和结果记录。
- 自治按单条工作流提升，不使用全局“全自动”开关。
- 第一个闭环以真实成交结果完成验证，而不是以页面或接口完成计数。

## 阶段 0：建立基线与事实源（工程基线已完成）

目标：开始开发前先让现状可测、文档可信。

- 将功能状态统一为 Built / Integrated / Used / Proven。
- 核心契约测试改为 CI 阻断，慢测试与视觉测试单独运行。
- 建立干净安装、初始化、内容发布、留资、跟进、成交的端到端基线。
- 记录 Flow 当前成功率、运行耗时、失败恢复和用户操作步数。
- README、VISION、路线图和 GTM 共用同一事实边界。

已落地：

- PHPUnit 不再允许失败继续；
- 全部独立契约测试进入阻断任务（阶段 0 建立时 77 个，后续新增测试自动纳入）；
- `tests/flow_baseline.php` 可重复生成 AITIPS Flow JSON 基线；
- CI 保存每个提交的 Flow 基线报告；
- 当前测量范围和未自动化指标见 `FLOW-BASELINE.md`。

验收：本地等价测试已通过；主分支核心 CI 在推送后必须真实通过。

## 阶段 1：定义共享领域契约

目标：让 Flow 与 Loop 使用同一套对象，不先做大界面。

领域边界与首批兼容契约见 `ADR-001-SHARED-DOMAIN-CONTRACTS.md`；任何数据库迁移仍需单独 ADR 和回滚方案。

当前进展：`ActionProposal`、`Goal`、`SkillDefinition`、`FlowRun`、`Approval`、`Execution`、`Evaluation` 兼容契约和测试已落地，不接管存储、不改变现有 Flow 写路径；其余对象仍需逐个核查后进入契约。

只读 `EvidenceProjection` 已用于验证现有数据可投影范围，并把缺少运行边界、执行回执和逐笔归因明确报告为 gap；ADR-002 已开始实施，当前只覆盖带稳定事件键的单节点 `add_tag` Flow 影子日志。

最小对象：

- `Goal`：指标、基线、目标值、周期、预算和边界；
- `FlowDefinition` / `FlowRun`：确定性流程及单次运行；
- `SkillDefinition` / `SkillInvocation`：可调用能力及调用记录；
- `LoopDefinition` / `LoopRun`：循环策略及单轮状态；
- `ActionProposal` / `Approval` / `Execution`：建议、审批和执行分离；
- `Evaluation`：指标、基线、样本、结果和判断；
- `Memory`：事实、结果和人的纠正，不存不可解释的自由文本黑箱；
- `Policy`：权限、预算、频控、同意和风险等级。

优先以现有 GrowthGoal、GrowthAction、GrowthMemory、DecisionTrace、AutomationSystem、CanvasSystem 和 SkillSystem 为迁移来源，避免新增平行实现。

验收：同一行动在 Flow/Loop 两侧具有相同 ID、权限、状态和审计记录。

## 阶段 2：让 Flow 成为 Agent 可调用能力

目标：Agent 复用成熟能力，而不是直接操作底层文件或临场生成执行逻辑。

- 为常用 Flow 建立稳定输入/输出契约、版本和风险声明；
- 为 Skill 增加 TIPS 归属、权限、成本、幂等与回滚信息；
- 建立统一 Action Gateway，所有写操作继续复用现有权限和事务；
- 增加 dry-run：运行前显示命中对象、预计动作、成本和风险；
- 明确模型只负责策略与结构化参数，确定性执行交给业务模块。

验收：Agent 能在测试环境调用一条成熟 Flow；重复调用幂等；无权限、超预算和 AI 超时均安全失败。

## 阶段 3：Loop Runtime v1

目标：实现受控循环，不追求全自治。

每一轮固定经过：

```text
Observe → TIPS Plan → Select Skills/Flows → Policy Check
→ Dry Run → Approve/Execute → Evaluate → Memory → Stop/Next
```

v1 约束：

- 默认最多一轮一个外部业务动作；
- 有最大步骤、模型调用、Token、金额和时间预算；
- 状态持久化，可暂停、恢复和人工接管；
- 每一步使用结构化输入输出和幂等键；
- 发布、群发、报价、价格、支付、退款、删除和外部写入默认审批；
- 模型失败不丢状态，不把“未评估”记为“通过”。

验收：断网、模型超时、工具失败、重复回调和进程中断后，Loop 状态一致且可恢复。

## 阶段 4：第一个黄金 Loop

目标：只跑通“高意向线索 → 成交”，不同时扩展所有场景。

TIPS 路径：

1. Touch：识别访问咨询、价格和高意向内容的用户；
2. Insight：根据行为、来源、历史互动和成交真相形成证据；
3. Personalize：生成分群、跟进时机和差异化培育方案；
4. Sell：准备销售任务、话术、物料或报价；
5. Feedback：记录回复、拒绝、成交、金额、成本和用户纠正。

发布顺序：沙盘 → 内部数据陪跑 → 小样本人工审批 → 多轮稳定 → 有限托管。

验收指标：建议采纳率、执行率、有效回复率、成交率、增量收入、AI/渠道成本、撤销率、错误触达率。至少连续多轮优于基线后，才标记 Proven。

## 阶段 5：双工作台

目标：在底层契约和黄金 Loop 验证后再建设完整交互。

### Flow 工作台

- TIPS 导航、节点、画布、规则和运行记录；
- Copilot 负责生成草稿、检查、解释和优化建议；
- 可查看哪些 Flow 被 Loop 调用，以及对应结果。

### Loop 工作台

- 仍按 Touch、Insight、Personalize、Sell 展示策略；
- 展示当前假设、证据、调用的 Skills/Flows、审批点和结果；
- 支持沙盘、暂停、接管、回退和固化为 Flow；
- 不以聊天记录或通用待办列表代替业务运行视图。

切换是用户级视图偏好，不改变数据、权限和运行状态。

验收：老用户不切换即可完成原任务；Loop 用户可一键进入对应 Flow 查看和接管真实业务对象。

## 阶段 6：工作流复利

- 稳定 Loop 一键固化为版本化 Flow；
- Flow 可声明为 Loop 的可靠 Skill；
- 比较工作流版本的业务效果、成本和风险；
- 形成官方基础工作流、用户专属工作流和可分享行业模板；
- 分享前必须脱敏、移除凭据，并重新声明权限和兼容版本。

只有单站点工作流被真实验证后，再考虑多租户聚合、联邦智能和规模化市场。

## 明确暂缓

- 全量重写后台或强制用户切换；
- 用聊天框替代 TIPS 业务界面；
- 全局全自动开关；
- 没有评估与停止条件的开放式 Agent；
- 在黄金 Loop 验证前扩张联邦智能、双边市场或大量新连接器；
- 为 Loop 复制内容、CDP、MA、CRM、订单等业务实现。

## 首批建议施工切片

1. 状态与 CI 基线；
2. 共享对象 ADR 和数据库迁移设计；
3. Action Gateway + dry-run；
4. 一个只读 Observe/TIPS Plan 循环；
5. 高意向线索沙盘；
6. 人工审批执行与结果回流；
7. 多轮评估后再做双工作台 UI。

每个切片都应能单独验收，不以后续大改才能成立。
