## 二、演化路径（版本脉络）

完整记录见 `md-docs/CHANGELOG.md`（v0.x → v2.2.0）。主线：

```
v1.0 品牌升级 ──→ v1.1 自我进化 ──→ v1.2 生态与商业化（分销/会员/ToB/迁移）
    │
v1.3 商业闭环修复（订单三源/分成/课程审核）──→ v1.4 智能增长OS（Copilot/邮件闭环/隐私）
    │
v1.5 规模化（11语言/CF加速/Notion同步/内容规模化）──→ v2.0 设计系统统一 + Flow/Loop契约 + Studio
    │
v2.0.1 死功能可用化 + AI渗透 ──→ v2.1 OPC商业化三闭环（会员/分销/生态）
    │
v2.2 证据化表达 + 插件平台开放（本次）
```

**演化规律**：每个大版本都有一个明确主题；但 v1.5 之后 CHANGELOG 断更，
四个版本（v1.5/v2.0/v2.0.1/v2.1）160+ 提交没有入档——「迭代信息不完整」的实证，
已在批D2 补齐。

## 三、死功能审计结论（批D1/D3 · 2026-09-10）

### 处置汇总

| 类别 | 数量 | 处置 |
|---|---|---|
| 零引用死文件 | 3 | 删除（lead-form.js / dynamic-content.js / 根 reset-password.php） |
| 死函数 | 1 | 删除（get_category_options） |
| 半建成品（有后端没入口） | 1 | **接通**：忘记密码流程（reset 令牌页一直存在但无法生成令牌） |
| 重复页面 | 2 | export-all → 301 合并；命令面板 leads 指向 CRM |
| 孤儿页（功能完整无入口） | 6 | 补入口：studio 加 4 卡（brain/ai-config/ai-usage/knowledge），workspace 加 4 链接（flow/evolution/safefix/demo-growth） |
| 误判（疑似实为活功能） | 多数 | 保留：后台专用 API、外部回调端点、预览页、子 tab 嵌入页 |

### 典型病例

1. **忘记密码**：`reset-password.php`（令牌验证）和 `user_send_reset_email()`（令牌生成）
   各自完好，但登录页没有入口 → 整条链路从上线起不可用。**教训：功能 = 链路，不是文件。**
2. **导航收录申请**：`api/nav-submit.php` 上线数日，前台表单页不存在 → 404。
   **教训：API 完成 ≠ 功能完成。**
3. **export-all / export / data-export 三页并存**：同一需求三次迭代都没删旧版。
   **教训：迭代必须带「旧版处置」动作。**

## 四、防复发机制（产品规划纪律）

从今往后，每个新功能开发必须同时交付四件套，缺一不算完成：

1. **入口**：导航 / 按钮 / 路由，用户能到达。（对应病例 1、2）
2. **数据流**：读谁的数据、写到哪里去，链路闭环。（对应病例 1）
3. **旧版处置**：替代了谁？删除 / 301 / 合并，写进提交说明。（对应病例 3）
4. **入档**：CHANGELOG 对应版本段落 + 功能地图更新。（对应断更问题）

契约测试已覆盖：后台页必须在导航树可定位（admin_contract_test）、设计 token
（design_contract_test）。建议下一步把「根目录新页面必须有 .htaccess 规则或导航链接」
也写成契约。

## 五、结论

OpenFlow 的问题不是「功能不够」，而是**功能密度已经超过了产品规划的承载力**。
428 个提交、9 大能力域、200+ 后台页，却只有断续的迭代记录。这次批D 做了三件事：
**补齐脉络**（CHANGELOG v1.5~v2.2）、**清理存量**（D3 处置清单）、**立下纪律**（四件套）。
下一步的功能演进（E 批：产品发现 Loop / 统一创作台 / 直播 / 看板娘衣橱）将按此纪律执行。
