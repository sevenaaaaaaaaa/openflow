# 深度竞品对标 · 01 内容 / CMS

> 方法：先读代码判断**做到什么程度**（好不好），再与主流竞品逐条比，
> 给出差距与建议。评级用 🟢 达到主流 / 🟡 能用但浅 / 🔴 缺失或形同虚设。
> 对标对象：WordPress(+Gutenberg/Yoast/WPML/ACF)、Ghost、Webflow、
> HubSpot CMS、Contentful/Sanity、Substack/beehiiv、Strapi。

## 一句话结论

内容模块的**广度**在开源自建阵营里罕见，而且有两处真实亮点（AI 原生写作、
内容集群），不是花架子。但深度上有三个硬缺口拖后腿：**没有自定义内容类型**、
**内容不能多语言**、**站内搜索是子串匹配**。这三个是"客户上量后一定撞墙"的，
应优先补。同时有一个别人都做不好、而我们天然占位的机会：**内容与增长闭环
（CDP/个性化/成交）长在一个系统里**——这是该重仓的差异化，不是补短板。

## 逐能力对标

### 1. 文章写作与编辑器 — 🟡 能用，但编辑器内核偏旧

**我们的实现**：`article-edit.php` 基于 `contenteditable` 的富文本 + Markdown
双模式，带代码高亮、30 秒自动保存、AI 辅助对话（生成/改写）、定时发布、
修订历史（最多 20 版、可恢复）、审核工作流（命中规则自动转待审）、
SEO 字段（title/desc/keywords/结构化数据）、分享卡生成、一键推送多平台草稿箱。

**判断**：功能项其实很全，自动保存 + 修订 + 定时 + AI 都在，这比大多数自建
CMS 强。真正的短板是**编辑器内核是 contenteditable**，不是块编辑器
（block editor）。意味着：复制粘贴排版易乱、无法结构化地插入"可复用区块/
嵌入卡片/分栏/图集"、协作与结构化输出弱。

**竞品标杆**：WordPress Gutenberg / Notion / 语雀都是**块编辑器**——每段内容
是结构化的块，能拖动、能插入富组件（表格/看板/嵌入/公式）、能存成可复用块。

**差距**：内核代差。不是缺功能按钮，是数据结构层面文章正文只是一坨 HTML，
而非块数组，限制了后续所有结构化玩法（包括把一篇文章自动拆成 newsletter、
社媒卡片——AI 重排的原料就更差）。

**建议**：中长期把正文迁到**块模型**（哪怕轻量：段落/标题/图/引用/嵌入/CTA/
可复用块）。短期先把"可复用区块"引进正文（复用已有 page-modules 的块库），
让文章能插入 CTA/表单/产品卡——这一步小、和"投放/成交"闭环直接挂钩。

### 2. 自定义内容类型 — 🔴 缺失（硬伤）

**我们的实现**：内容类型写死——文章、页面、下载、播客、课程。没有自定义
内容类型（custom post type）与自定义字段（custom fields）。

**竞品标杆**：WordPress 的 CPT + ACF、Contentful/Sanity/Strapi 的 content model
是这些系统的**立身之本**——用户能自己定义"案例/职位/房源/菜品/活动"等任意
结构化内容类型，带自定义字段、列表、详情模板。

**差距**：这是最影响"能不能长期用"的一条。任何稍微不标准的站（作品集、
目录站、知识库、产品库）都会在这里撞墙，只能硬塞进文章或改代码。

**建议**：做一个**轻量 CPT**：后台可定义内容类型（名称/slug/字段集：
文本/富文本/图片/日期/选择/关联），自动生成列表 + 详情路由 + SEO。
不必做到 WordPress 那么重，但要能让用户不改代码就建一种新内容。
性价比极高，且直接支撑"生态"里创作者建各种内容主页。

### 3. 页面与建站 — 🟢 意外地不错

**我们的实现**：`page-builder` 支持**拖拽**、13 种区块（Hero/CTA/表单等）；
区分基础页（模板）/模块化页/落地页；另有 `site-builder`、`front-builder`、
`page-modules`（可复用模块库）、`landing-pages`。

**判断**：这块比我上次"只看有没有"时低估了——是真·可视化拖拽 + 区块化，
落地页/广告页够用。相比 Webflow 的像素级自由度当然浅，但对"快速拼一个
高转化落地页"的目标人群是合适的。

**竞品标杆**：Webflow（像素级 + 响应式断点 + 交互动画 + CMS 集合绑定）、
HubSpot（智能内容/个性化模块）。

**差距**：(a) 响应式断点/精细样式弱；(b) 区块是**平铺**的，缺"分栏/嵌套容器"；
(c) 最可惜——区块内容**不能按人群变**（HubSpot smart content 的核心）。

**建议**：不追 Webflow 的自由度（不是我们的战场）。补两点高价值：
**分栏/容器嵌套**，以及**区块级人群定向**（复用刚做的 PromoSystem 定向模型，
让落地页区块也能"对老客户显示 A、对新访客显示 B"）——这就把"建站"和
"个性化增长"缝在了一起，是别人给不了的组合。

### 4. 分类 / 标签 / 专题 / 内容集群 — 🟢 强，且有 SEO 心智

**我们的实现**：分类**支持父子层级**、标签、专题（topics），另有
**内容集群（cluster）** —— 按规则把文章聚成主题集群。

**判断**：这是个亮点。内容集群 = pillar/cluster 内容策略的产品化，多数 CMS
要靠插件或人工。层级分类也到位。

**竞品标杆**：WordPress（分类层级 + 标签，集群靠 Yoast/插件）、
HubSpot（topic cluster 工具，付费高档才有）。

**差距**：集群目前偏"聚合展示"，缺"集群健康度/内链建议"（哪篇缺内链、
哪个子主题内容单薄）。

**建议**：把集群从"聚合"升级为"策略助手"：给每个集群算覆盖度、
自动建议内链与选题缺口。这条和 SEO 中心天然合流，工作量不大、很出彩。

### 5. 媒体 / DAM — 🟡 基础够用，缺自动处理

**我们的实现**：`dam.php` 上传、按类型分目录、`ImageMeta` 管 alt/title；
`image-seo` 批量补 alt。

**判断**：能存能标 alt（SEO 友好），但**没有自动图片处理**：无自动生成
webp/多尺寸、无裁剪、无 CDN 变换、无以图搜图/去重。资源多了不好找。

**竞品标杆**：WordPress（自动多尺寸 + 插件 webp）、Cloudinary/Contentful
（上传即变换、按需裁剪、CDN、AI 打标签检索）。

**差距**：性能与工作流。大图直接用原图拖慢前台；找图靠肉眼翻。

**建议**：接一个**上传即转 webp + 生成 2-3 个尺寸**（GD/Imagick 本地即可，
零外部依赖），前台按容器取合适尺寸。这对"网站增长"是实打实的 LCP/SEO 收益。
检索可后置。

### 6. 多语言内容 — 🔴 只有界面语言，内容不能翻译

**我们的实现**：`I18n` 是 UI 文案多语言（`__()` + lang 包），文章/页面**没有
per-locale 译文**——一篇文章无法有中/英两版并按语言呈现。

**竞品标杆**：WPML/Polylang（每篇内容多语言版本 + hreflang）、
Contentful/Sanity（locale 是一等公民，字段级本地化）。

**差距**：做外贸站、出海内容站直接不可用。而 OpenFlow 讲"GEO/出海"，
这个缺口和定位矛盾。

**建议**：给文章/页面加**语言版本**（同一内容的 zh/en 关联组 + hreflang 输出 +
语言切换）。可结合 AI 一键生成译稿初版——这又是"AI 原生"能落地的点。
优先级高，因为它和产品对外宣称的出海能力直接相关。

### 7. Newsletter / 博客 — 🟡 能发能追踪，深度靠外部

**我们的实现**：`email.php` 有订阅者库、模板、退订链接、**打开/点击追踪
（pixel + 链接包装）**，可把文章一键发成 newsletter；自动化序列/分群
交给 Mautic/BillionMail。博客即文章体系（无需单独一套）。

**判断**：原生能发、能测打开点击，这已经超过"能不能用"。但**原生的
分群群发、A/B 主题行、drip 序列、送达治理（退信/抑制名单）弱**，重度依赖
接外部 MA。对"一个人运营"来说，外部 MA 是额外心智负担。

**竞品标杆**：Substack/beehiiv（订阅、付费墙、推荐网络、原生分析一体）、
Mailchimp（分群 + A/B + 自动化 + 送达治理）。

**差距**：原生 newsletter 的"运营闭环"不完整——尤其**付费订阅/会员通讯**
（Ghost/Substack 的杀手锏）完全没有。

**建议**：因为我们已有会员/订阅/支付体系，**付费 newsletter/会员专享内容**
是低成本高价值的组合（内容 + membership 已有零件一拼即得），这是 Ghost
的核心而多数自建 CMS 给不了。原生分群群发 + 主题行 A/B 次之。

### 8. 版本 / 协作 / 审核 — 🟡 有版本有审核，无实时协作

**我们的实现**：修订历史（20 版可恢复）+ `version-diff`（LCS 逐字 diff）+
审核工作流（自动/人工）。

**判断**：单人或小团队够用，diff + 恢复 + 审核这套是完整的。缺的是**多人
实时协同编辑、评论/批注、锁定**。

**竞品标杆**：Google Docs/Notion/语雀（实时协同 + 批注）、
WordPress（锁定 + 修订，无实时）。

**差距**：多人同时编辑会互相覆盖（无锁）。

**建议**：目标人群是一人公司，实时协同**优先级低**。补一个便宜的**编辑锁**
（有人在编就提示）即可防覆盖，不必上实时协同。

### 9. 站内搜索 — 🔴 子串匹配（已在上一份报告标注）

**我们的实现**：`SearchEngine` 用 `mb_stripos` 逐条扫（`FTS/MATCH` 计数为 0，
已复核）。无相关性排序、无分词、无高亮。

**竞品标杆**：WordPress（内置 + 插件走 Elasticsearch）、
Ghost（内置全文）、Algolia（即时 + 容错 + 高亮）。

**差距**：内容一多搜索基本不可用。SQLite 自带 FTS5 没用上。

**建议**：升级 FTS5（建虚拟表 + MATCH + rank + 高亮），零外部依赖。
优先级高，属于"数据一多就废"的硬伤。

### 10. AI 内容能力 — 🟢 真亮点，且是定位所在

**我们的实现**：编辑器内置 AI 辅助（生成/改写），另有 `ai-config`、
`knowledge`（知识库）、`GrowthEngine`（每 6 小时自动爬热点/写草稿/做 SEO）。

**判断**：这是真差异化——"AI 每天自动产内容 + 编辑器内 AI 协作"，
多数 CMS 是把 AI 当外挂按钮，我们是把它做进增长引擎。

**竞品标杆**：多数 CMS 的 AI 是"帮你写一段"的插件；HubSpot/Jasper 强在营销文案。

**差距**：AI 目前偏"写"，缺"repurpose（一篇拆成 newsletter/社媒/短视频脚本）"
和"基于本站数据的选题建议"（用 CDP/SEO 数据反哺选题）。

**建议**：把 AI 从"写作助手"推进到"内容运营助手"：一键把文章重排成
newsletter/社媒多版本（这又倒逼第 1 条的块模型）、结合站内搜索词与 SEO
缺口给选题。这是把已有 AI 引擎 + CDP + SEO 拧成一股绳的高价值方向。

## 该补的优势（从竞品，结合自身）· 按优先级

1. **自定义内容类型（轻量 CPT）** 🔴 —— 解"长期能不能用"的最大硬伤，
   且直接支撑创作者生态。**P0**
2. **多语言内容** 🔴 —— 和对外宣称的出海/GEO 定位直接挂钩，可 AI 一键初译。**P0**
3. **站内搜索 FTS5** 🔴 —— 数据一多就废的硬伤，零依赖。**P0**
4. **付费 Newsletter / 会员专享内容** 🟢机会 —— 内容 × 已有 membership/支付，
   一拼即得 Ghost 的杀手锏。**P1**
5. **图片自动 webp/多尺寸** 🟡 —— 实打实的 LCP/SEO 收益，本地零依赖。**P1**
6. **落地页区块级人群定向** 🟢组合 —— 复用 PromoSystem 定向，把建站和
   个性化增长缝合。**P1**
7. **正文块模型 + 可复用区块** 🟡 —— 内核升级，撬动结构化/repurpose，
   工作量大，**P2** 但方向明确。

## 客户很需要、但都没有的（我们的独特占位）

- **内容即增长闭环**：别的 CMS 到"发布"就结束；我们能让一篇内容天然接上
  CDP 画像 → 个性化投放 → 成交（收款链接）。把"这篇文章带来了多少线索/
  多少成交"做成内容的一等指标——**没有任何自建 CMS 给得了这个**，这是
  最该重仓的差异化，而不是去追 Webflow 的像素自由度。
- **AI 内容运营（不是 AI 写作）**：结合本站 SEO 缺口 + 搜索词 + CDP 热度
  自动给选题，并把一篇 repurpose 成多渠道多版本。竞品的 AI 停在"帮写一段"。
- **创作者一体化主页**：作者档案（已做）× 自定义内容类型 × 付费内容，
  让创作者在平台上零服务器搭起自己的内容+变现主页——这是"生态"的地基。

## 创新方向：现有 CMS 都没解、但 AI 让它必然到来

> 前面都是"比较优势"——做得比别人好一点，是防守。新产品的存在理由是创新。
> 这一节换一个坐标系：不问"比 WordPress 强在哪"，问"**内容这件事正在被 AI
> 重新定义成什么**"。判据有两条：(1) 现有 CMS 结构上解不了（不是没做，是
> 范式不对）；(2) 已经在发生或 AI 发展下必然到来。每条都落到我们**独有的
> 筹码**上——空谈趋势没意义，能不能赢看手里有没有别人没有的零件。

### 核心判断：内容的"消费者"正在从人变成 AI

过去二十年，CMS 的产物是"给人读的页面"。但今天越来越多的内容是**被机器消费**
的——被 ChatGPT/Perplexity 引用、被 Agent 抓取执行、被推荐系统喂给算法。
所有现有 CMS 仍在"排版一个页面"，这是范式错位。谁先把 CMS 的产物从"页面"
重新定义为"**活的、可被 Agent 消费的、会自己达成目标的知识**"，谁就重画了赛道。
下面六条，是这个判断的具体展开。

### 创新一：内容即 Agent 底座（答案引擎 & MCP 原生）— 最大的一张牌

**趋势**：搜索正从"给你十个蓝链接"变成"直接给你一个答案"。用户越来越少
点进网站，而是问 AI，AI 去引用网站。GEO（生成引擎优化）是先兆，终局是
**你的内容要能被 AI Agent 直接查询和引用**，而不只是被人浏览。

**为什么现有 CMS 解不了**：它们的产物是 HTML 页面，是给浏览器渲染的，不是
给 Agent 查询的结构化知识；没有 provenance（出处）、freshness（新鲜度）、
claim（可引用的事实单元）这些 Agent 需要的信号。加个 sitemap 不解决本质。

**我们独有的筹码**：仓里已经有 `mcp-server.php` 和 `knowledge` 知识库——
这意味着我们可以让"发布内容"同时产出三种形态：给人看的**页面**、
本站自己的**问答 Agent**、以及一个**对外的 MCP/知识 API**，让外部 AI（甚至
客户装的 Agent）直接查询、带出处引用你的内容。**没有任何 CMS 这么定义产物**。

**第一步**：把已发布内容自动抽成"可引用知识单元"（标题+事实+出处+更新时间），
经现有 mcp-server 暴露成一个查询端点；顺带生成 llms.txt/answer-ready 结构。
一句话：**让你的网站成为一个 AI 能调用的知识源，而不只是一堆网页。**

### 创新二：站点即对话体（内容的默认出口是"问"，不是"翻"）

**趋势**：访客会越来越多地"问网站"而不是"逛网站"。落地页、文档、FAQ 的
终极形态是一个**能对话的站点 Agent**，从你的内容里现答，而不是让人自己找。

**为什么现有 CMS 解不了**：它们把"页面树 + 导航"当作内容的唯一出口，
"站内搜索框"是极限。把整站内容变成一个可对话、会转化的 Agent，是另一种产物。

**我们独有的筹码**：内容 + `knowledge` + AI 引擎 + **CDP 画像**——别人的站内
问答只会答问题，我们的能**带着画像答**：知道来的是谁、在什么阶段，答完顺势
给收款链接/留资/推课。这是"会销售的站点 Agent"，是问答 + CDP + 成交的合体。

**第一步**：一个挂件式站点 Agent，答案只从本站已发布内容检索（防幻觉），
答完根据 CDP 画像触发一个下一步动作（收款链接/表单/订阅）。

### 创新三：渲染时生成式个性化（AI 现场为"这个人"组装页面）

**趋势**：个性化的终点不是"从 3 个 A/B 版本里挑一个"，而是**这一次请求，
AI 根据这个访客的画像/意图/旅程阶段，现场生成/重排页面内容**。生成式 UI
（generative UI）已经在冒头，内容层必然跟上。

**为什么现有 CMS 解不了**：静态 CMS + 模板，个性化最多做到"规则挑变体"
（我们刚做的 PromoSystem 也还在这一层）。**渲染时 AI 组装**需要三样东西：
结构化内容源 + 实时画像 + 生成能力，缺一不可，所以没人做成。

**我们独有的筹码**：**三样我们都有**——块模型（P2 一旦落地）、CDP 实时画像、
AI 引擎。这是极少数产品能凑齐的组合。可以先在"落地页某个区块"上试：
同一个位置，AI 按画像现写标题/卖点/CTA，而不是从固定库里挑。

**第一步**：落地页加一种"AI 区块"——渲染时把访客画像喂给模型，现生成这一段
文案（带缓存与人工兜底）。这是创新六里"区块级定向"的生成式升级版。

### 创新四：目标制内容（内容是会自己达成 KPI 的 Agent，不是文档）

**趋势**：内容会像广告投放一样被管理——每一篇有一个**目标**（拉新/转化/
留资），和一个**自主优化回路**：AI 盯数据，自动 repurpose、改标题、换分发、
更新过时信息，去逼近目标。内容从"文档库"变成"一组会自己干活的 Agent"。

**为什么现有 CMS 解不了**：它们把内容当静态资产，发布即终点；分析是旁观，
不闭环。没有"目标 → 自主行动 → 复盘"的机制。

**我们独有的筹码**：`GrowthEngine` 已经每 6 小时自动产内容——这是"内容会自己
动"的种子。把它从"自动写新的"推进到"**自动优化已有的**"：给每篇内容设目标，
引擎监控转化、自动提出（或执行）改写/重投/更新。这是把内容管理变成
内容运营 Agent 的关键一跃。

**第一步**：给文章加"目标 + 目标达成度"字段，让 GrowthEngine 每轮巡检时对
未达标内容生成一条具体改进建议（标题太长/缺内链/该 repurpose 成 newsletter）。

### 创新五：活内容——会自我保鲜的内容

**趋势**：evergreen 内容（"2026 最佳 X"、价格、榜单、统计数字）会过时，
未来 AI 会**盯着源、主动提出更新**，人只需批准。内容从"发布即定格"变成
"持续保鲜的活体"。

**为什么现有 CMS 解不了**：修订历史是"人改了才有版本"，没有"内容自己该更新了"
的感知。

**我们独有的筹码**：知识库 + AI 引擎 + 已有的定时巡检（cron）。可以让引擎
定期核对 evergreen 文章里的事实/数字/年份，过时就起草更新走审核。

**第一步**：给文章打"evergreen + 需保鲜"标记，cron 里加一条：对这些文章
用 AI 检出"可能过时的断言"，生成待审更新。

### 创新六：写一次，AI 编译到 N 个面（不是跨平台复制）

**趋势**：一个"内容意图"应当被 AI **编译**成各面原生形态——网页 / newsletter /
社媒长贴 / 短视频脚本 / 播客提纲 / Agent 答案，每种都是为该媒介重写的，
不是复制粘贴。这是"write once, compile everywhere"。

**为什么现有 CMS 解不了**：正文是一坨 HTML（见能力 1 的内核问题），没有
结构化源 + 品牌语气模型，"编译"无从谈起，只能"转发同一段字"。

**我们独有的筹码**：块模型（P2）+ **品牌语气模型**（下条）+ 已有的多平台推送
通道。凑齐就能做成真正的编译，而不是复制。

**第一步**：先做"一篇 → newsletter + 社媒三条"的 AI 编译（哪怕源还是 HTML），
跑通编译范式，再随块模型升级质量。

### 支撑性资产：品牌语气模型作为一等公民

上面多条（一/三/四/六）都依赖一件东西：**这个品牌/创作者的语气模型**——
一份被调过的、代表"我说话的方式"的资产，让所有 AI 操作（写作/个性化/
Agent 答话/多面编译）都像本人。现有 CMS 没有"你的语气"这个被管理的对象。
我们的生态里已有类似"写作风格"的雏形，应把它升级成 CMS 的一等资产，
供全站 AI 调用。**这是让所有 AI 生成物不跑偏、有辨识度的地基。**

## 把创新拧成一句话（新产品的存在理由）

> **别人的 CMS 帮你"发布页面给人看"。OpenFlow 帮你把内容变成一个活的、
> 懂访客、会自己达成目标、还能被 AI 直接调用的知识与销售系统。**

这句话里没有一个词是 WordPress/Ghost/Webflow 能说的——因为它们缺我们手里的

而是把这三样和内容焊在一起，做成上面六条。**近可落地的是创新一、二、四**
（筹码都现成），创新三/六等块模型，创新五最轻可先试。

## 内容生产的三种范式 → 我们的 CMS 具体能做什么

> 一个更锋利的生产视角：未来内容分三种——① AI 辅助下的**人工创作**、
> ② 面向 AI/agent 的**纯 AI 内容**、③ 人辅助 AI 的**全新内容**。三者其实是
> 同一条轴上的三个位置，轴就是**"人把关到什么程度"**。CMS 要围绕这条轴
> 重建，而不是围绕"编辑一个文档"。下面逐类给出我们能做的具体能力。

### 贯穿三类的结构升级（先立地基，三类都靠它）

1. **双重发布：每条内容 = 人看的渲染 + 机器读的结构**。同一份内容自动产出
   "人的页面"与"机器视图"（干净 Markdown + 结构化数据 + 标注），自动同步。
   这是范式②的载体，也是①③的产物出口。
2. **来源与把关等级作为一等字段**：每条内容记 `made_by`（human / ai / co）、
   `sourced_from`（引用源）、`human_oversight`（把关等级）。这既是范式③的
   安全机制，也是未来被 AI 搜索采信、以及合规标注的信任信号。
3. **内容生产线（pipeline）作为被管理对象**：把"选题→取材→成稿→核查→SEO→
   发布"做成可配置的流水线，AI 执行每一站、人在关口审批。CMS 从"管文档"
   升级为"管生产过程"。`GrowthEngine` 是这条流水线的雏形。

### 范式① AI 辅助下的人工创作 —— 把"想到"到"上线"的距离压到最短

人主导，AI 提速构思 / 素材 / 上线。能做的具体能力：

- **构思**：大纲不是"给个通用大纲"，而是**用我们自己的数据喂**——站内搜索里
  "问了但我们没好答案"的词、SEO 缺口、CDP 里最热的意图、转化过的选题角度。
  别人的 AI 大纲是凭空写，我们的是"你的受众正在找、而你没答好的"。
- **素材·视频转图文教程（你点的例子，做成旗舰）**：指一个视频 → 自动转写
  → AI 切成步骤 → ffmpeg 抽关键帧配图 → 组装成一篇带插图的分步教程（块模型）。
  一个录屏 10 分钟，产出一篇能发布、能 SEO、能 repurpose 的教程。**这是
  "AI 辅助创作"最有感知的一刀**，我们有媒体库 + AI，缺的是转写 + 抽帧管线。
- **素材·研究台**：拖进 PDF/网页/录音/竞品页 → AI 抽出事实/引用/数据/可用图
  → 编辑器旁的"素材盘"随取随用，每条带出处。作者不再来回切标签页找料。
- **插图**：按每段内容自动生成配图/示意图/封面（已有分享卡 + imagegen 雏形），
  从"找不到图"变成"每段都有图"。
- **上线**：一篇草稿 → AI 一次过补齐 SEO 字段、结构化数据、内链、alt、封面、
  slug、分类标签建议、以及一套 repurpose——**作者从"填表"变成"审核"**。
  发布前跑一遍"无出处断言"检查，缺源就拦。

### 范式② 面向 AI / agent 的纯 AI 内容 —— 给机器读的内容层

内容的受众是 AI，不是人。这是现有 CMS 完全的空白。能做的：

- **答案版自动生成（你点的 MD 版）**：每个页面自动产出一份干净的
  Markdown/纯文本"答案版",去壳留事实 + 结构 + 出处,挂在可预测的 URL 与
  llms.txt,并进 MCP 知识 API,供 AI 搜索与 Agent 直接取用。
- **结构化数据自动化（你点的自动增加）**：从正文自动生成并**持续维护**
  JSON-LD(Article/FAQ/HowTo/Product/Course),自动校验、内容变了就更新，
  不再靠人手填一个 structured_data 框。
- **面向 agent 的数字标记（你点的核心）**：给内容加一层机器可读标注——
  · **事实单元**:每个可引用断言带 confidence / source / freshness;
  · **可执行标记**:"预约咨询"这段挂上可被 Agent 调用的动作(接收款链接/表单),
    "这个产品"挂上 buy 动作——**内容不只是可引用,而是可被 Agent 执行**;
  · **实体链接**:人名/产品/概念链到规范实体(接作者档案/产品库)。
  这一步把网站从"一堆网页"变成"一组 Agent 可调用的知识 + 能力"。我们有
  `mcp-server` + 收款链接 + 作者档案,凑得齐"可引用 + 可执行 + 可链接"。
- **问答对自动派生**:从每页自动抽出"它回答了哪些问题",喂站点 Agent 与答案引擎。

### 范式③ 人辅助 AI 的全新内容 —— 人掌过程，AI 掌知识

人可能已无法亲自掌握该知识,但工程/营销/用户需要它。人退到**导演 + 质检**,
AI 干大部分活。关键不是"能不能生成",而是"**没有人担保知识,怎么让它可信、
不成 AI 垃圾**"。能做的:

- **强制接地生成(grounded)**:范式③的内容只能从"给定的源(知识库 + 检索到并
  引用的资料)"生成,**每个断言必须带源**,人的活是审源 + 抽检关键断言,
  而不是通读全懂。CMS 强制"无源不发"——这是让范式③安全的核心机制。
- **过程即模板(可复用的生产配方)**:人把一次成功的生产过程沉淀成配方
  (查这些源 → 这样成稿 → 这样核查),之后同类内容 AI 按配方批量跑,人只审关口。
  这就是把"人掌过程"产品化。
- **规模化 + 治理**:能批量产 500 篇(地点/产品/对比页),但每篇强制接地 + 去重 +
  差异化 + 进审核队列 + 抽样质检——**治理是产品,把它和 AI 垃圾农场区分开**。
- **只找人要判断**:CMS 主动标出"这几处只有你能拍板"(品牌调性、事实取舍、
  法律/承诺),把人的注意力集中在他真正有价值的地方,其余交给 AI。
- **把关等级透明化**:每篇标注人把关到什么程度,既对内管理质量,也作为对外
  (读者/搜索引擎)的信任信号。

### 回答"我们的 CMS 还能做什么"——按可行性排

**现成筹码、近可落地**:
1. 视频 → 图文教程管线(范式①旗舰,感知最强)
2. 每页"答案版 MD + 自动 JSON-LD"双重发布(范式②,接 mcp-server)
3. 面向 agent 的数字标记:先做"可执行标记"(内容里的动作接收款链接,范式②)
4. 来源/把关等级字段 + 发布前"无源断言"拦截(范式③安全底座,也服务①)

**要块模型或更多投入**:
5. 强制接地的批量生产 + 治理队列(范式③规模化)
6. 生产线/配方作为被管理对象(把 GrowthEngine 泛化成可配置流水线)
7. 研究台 / 素材盘(范式①取材)

### 一句话收拢这三类

> 现有 CMS 假设"内容是人写给人看的"。而未来是:**人、AI、人+AI 三种方式生产,
> 内容同时发给人和机器两类受众**。我们的 CMS 该做的,是围绕"**谁生产 ×
> 给谁消费 × 人把关多少**"这三条轴重建——这正是 WordPress 们的结构性盲区,
> 也正好压在我们 AI 引擎 + MCP 底座 + CDP 的筹码上。

## 小结与建议节奏

内容模块分三层看：
- **地基层（必须补，上量就撞墙）**：自定义内容类型 / 多语言 / FTS5 搜索。P0。
- **组合层（低成本高感知，把已有零件拼起来）**：付费内容、图片处理、
  落地页区块级定向、内容闭环指标、AI 内容运营。P1。
- **创新层（新产品的存在理由，重仓方向）**：内容即 Agent 底座、站点对话体、
  渲染时生成式个性化、目标制内容。先做筹码现成的创新一/二/四。

地基不补会流失现有用户，创新不做没有新用户来的理由——两条腿都要走，
但**叙事和差异化投入压在创新层**。
