# 深度竞品对标 · 02 用户数据 / CDP

> 坐标系见 `docs/VISION.md`。评级：🟢 达到主流 / 🟡 能用但浅 / 🔴 缺失或撞墙。
> 对标：Segment（身份 + destinations）、神策（事件分析 + 智能运营）、
> GrowingIO（无埋点 + 人群 + 广告激活）、mixpanel/Amplitude（自助产品分析 +
> 预测）、RudderStack（warehouse-native）。

## 一句话结论

CDP 是全线**最强**的模块，而且强得有含金量——**真身份图谱、实时进出群、
去重采集 + 事件字典、海量分析（漏斗/留存/RFM/LTV/归因/路径）、AI 洞察**，
这套在自建阵营里是碾压级的。但有**一个架构死结**和**一个战略空白**必须点破：
① 画像还存在单个 `profiles.json` 里，全量读写，这是比 events 更早撞的墙；
② 没有**人群激活（destinations / reverse ETL）**——分群圈出来了却推不出去到
广告/渠道，而这恰是 Segment/GrowingIO 的立身之本、也是"增长"定位的关键一环。
创新方向上，CDP 的真正跃迁不是"多几张图表"，而是**从给人看的仪表盘，变成
给 AI 消费的实时决策上下文**——这正压在我们的三样筹码上。

## 逐能力对标

### 1. 用户画像（Profile）— 🟢 内容强，🔴 存储撞墙

**我们的实现**：画像含 properties（四种更新语义 set/set_once/increment/append）、
行为摘要（computed traits）、scores、lifecycle、segment_memberships，
匿名→登录→跨端合并。字段模型是对的。

**判断**：画像的**内容模型**达到主流 CDP 水准（computed traits + 生命周期 +
分群成员关系）。但**存储是致命短板**：所有画像在一个 `profiles.json`，
`allProfiles()` 全量读进内存，任何一次画像更新、分群计算、计数都要
读/写整份文件。events 我上一轮已迁到 SQLite + 索引，**但 profiles 还是 JSON
单文件**——这是比 events 更早撞的墙（每来一个事件可能就 O(n) 重写整个文件）。

**竞品标杆**：Segment/神策用列存/数仓；再不济也是每画像一行可独立读写。

**建议（P0 架构）**：画像迁到 SQLite（一画像一行 + 索引 visitor/member/email），
`allProfiles()` 之外提供按需单取与分页。这是 CDP 能不能上量的**第一块地基**，
优先级高于任何新功能——和当初 events 索引同性质，但更紧迫（写放大更严重）。

### 2. 身份打通（Identity Resolution）— 🟢 真图谱，达到主流

**我们的实现**：`IdentityResolver` 建**身份图谱**（aliases.json），键含
visitor/member/email/phone/openid，支持 resolve（找规范身份）、merge（合并 +
吸收子画像 + 同步）、unifiedProfile、linkedVisitors。匿名→登录→微信 openid
一路合并。

**判断**：这是**真身份图谱**，不是玩具——多键、确定性合并、画像吸收、
反向同步都在。这块是我们的强项，达到 Segment 的确定性身份合并水准。

**竞品标杆**：Segment Identity（确定性 + 部分概率）、神策（一方 ID-Mapping）。

**差距**：只做**确定性**合并（靠共享键），无概率合并（跨设备无共享键时的
统计归并）——但对我们的场景，确定性足够，概率合并 ROI 低，**不建议做**。
真正可补的小点：合并的**可审计/可撤销**（合错了能拆），以及合并冲突策略
（两个都有 email 且不同时怎么办）。

### 3. 事件采集（Tracking）— 🟢 扎实

**我们的实现**：客户端 SDK（`cdp-track.js`）、服务端 track、`message_id` 去重
（`INSERT OR IGNORE`）、**事件字典 `EventDictionary`**（事件/属性的登记与治理）、
属性四语义。events 已在 SQLite + 我上轮加的索引。

**判断**：采集这层扎实——去重、字典治理（很多自建 CDP 没有事件字典，导致
埋点脏乱）、属性语义都有。达到主流。

**竞品标杆**：Segment（spec + Protocols 校验）、GrowingIO（无埋点/圈选）、
神策（埋点方案 + 元数据管理）。

**差距**：(a) **无"无埋点/可视化圈选"**——GrowingIO/神策的卖点，非技术用户
不写代码就能定义事件（在页面上点一下"这个按钮算一个事件"）；对"一个人运营"
价值大。(b) 事件字典缺**入库校验**（不符字典的事件是拦还是放）。

**建议**：P1 做**可视化圈选埋点**（前端选择器 → 事件定义），把埋点从"要写代码"
降到"点两下"，非常契合无团队用户。事件字典加一个"未登记事件"巡检即可。

### 4. 分群（Segmentation）— 🟢 实时进出群，达到主流

**我们的实现**：规则分群，**每个事件后增量评估**该用户的分群归属，
进群/退群实时触发 `segment_enter/segment_exit` 给 MA/flow 消费
（`evaluateUserSegments`）。另有 SegmentEngine（运营配置）与模板。

**判断**：**实时进出群 + 触发下游**是 CDP 的高阶能力，我们有，且对标 Segment
的 Audiences 实时性。分群→CRM 批量建线索（上轮已做）也通了一条激活路径。

**竞品标杆**：Segment Audiences、神策智能运营的实时人群、GrowingIO 人群。

**差距**：(a) 计算依赖全量 profiles（见能力 1 的存储问题，分群一多就慢）；
(b) 缺**人群规模预估/交并差**（建群时看不到"大概多少人""和另一个群的重叠"）;
(c) 无**人群随时间的趋势**（这个群在涨还是在缩）。

**建议**：存储修好后，补"建群实时预估人数 + 群规模趋势"，这是运营决策要看的。

### 5. 分析与洞察（Analytics & Insight）— 🟢 广到夸张，🟡 但不能自助探索

**我们的实现**：漏斗、留存、路径、RFM、LTV、AOV、渠道/营收归因、
生命周期分布、健康分、时段热力、会话深度、增长曲线……几十个分析方法；
`CdpInsight` 用 AI 自动生成洞察。

**判断**：**分析广度夸张**，覆盖了 mixpanel/神策的绝大多数报表，AI 洞察也是
真差异化。但有一个质的短板：**这些都是"预制报表"（固定参数的方法）**，
不是**自助探索**——用户不能像 mixpanel/Amplitude 那样，自由地"任意事件 ×
任意维度 × 任意分群 × 任意时间"拖出一个新分析。

**竞品标杆**：mixpanel/Amplitude 的核心正是**自助即席分析**（谁都能拖出
任意漏斗/留存/细分）；神策的事件分析模型同理。

**差距**：预制报表回答"已知问题"，自助探索回答"没想到的问题"。运营真正
值钱的洞察往往来自后者。这是 CDP 分析层的**范式差**，不是缺几张图。

**建议**：见创新层——**别去手搓一个 mixpanel 式的拖拽分析器**（重且未必打得过），
用我们的 AI 筹码做"**自然语言问数据**"，直接跳过拖拽这一代。

### 6. 人群激活 / Destinations（reverse ETL）— 🔴 战略空白

**我们的实现**：分群能触发 MA/flow、能批量建 CRM 线索（上轮做）、能发 webhook。
但**没有"destinations"这个一等概念**——把一个人群**自动、持续地同步**到
外部渠道（微信广告人群包、朋友圈/巨量/Meta 自定义受众、邮件工具受众、
短信名单）。`ActivationSystem` 是**兑换码**，不是受众激活。

**判断**：这是**战略空白**。Segment 的立身之本就是 destinations（数据进来 →
清洗统一 → 推到几百个下游）；GrowingIO/神策的"人群包一键推广告平台"是
国内增长团队的刚需。我们把人"圈出来了"却"推不出去"，闭环缺了最后一公里。

**竞品标杆**：Segment（200+ destinations）、GrowingIO/神策（广告平台人群包）。

**差距**：圈了人群只能站内用（MA/CRM），无法把"高价值流失用户"这个群推去
微信广告做再营销。对"增长 OS"定位，这是明显的缺口。

**建议（P1 战略）**：做一个**轻量 destinations 框架**：人群 → 映射 → 定时/实时
推到目标（先接微信广告人群包、通用 webhook/CSV、邮件工具）。哪怕先做
"人群一键导出为广告平台可用的名单 + 定时刷新"，就补上了最后一公里。

### 7. 隐私 / 合规 — 🟡 有基础

**我们的实现**：`PrivacySystem` 导出、删除、邮箱/手机脱敏；账号注销清 PII。

**判断**：GDPR 式的导出 + 删除 + 脱敏在，基础合规够。缺**同意管理
（consent / cookie 授权与采集开关联动）**、**数据保留策略（自动过期清理）**、
以及采集的**同意状态入画像**。

**竞品标杆**：Segment（consent management）、OneTrust 类。

**建议**：P1 补"同意状态"进采集链路（未同意不建画像/只留匿名），和数据保留
自动清理。出海（GDPR）与国内个保法都需要。

## 该补的优势 · 按优先级

1. **画像迁 SQLite** 🔴架构 —— CDP 上量的第一块地基，写放大严重，**P0**。
2. **人群激活 / destinations** 🔴战略 —— 补"圈了推不出去"的最后一公里，
   先接广告人群包 + 通用导出。**P1**。
3. **自然语言问数据**（替代自助拖拽分析）🟢创新 —— 用 AI 筹码跳过一代。**P1**。
4. **可视化圈选埋点** 🟡 —— 埋点从"写代码"降到"点两下"，契合无团队用户。**P1**。
5. **同意管理 + 数据保留** 🟡合规 —— 出海与个保法刚需。**P1**。
6. **建群人数预估 + 群趋势** 🟡 —— 运营决策要看，存储修好后做。**P2**。

## 创新方向：AI 让 CDP 必然变成什么

> 核心判断：CDP 的产物正在从**「给人看的仪表盘」**变成**「给 AI 消费的实时
> 决策上下文」**。这正是 VISION 里"给谁消费：人 vs 机器"这条轴，落到数据上。
> 现有 CDP（Segment/神策/mixpanel）都还在"把数据变成图表给人看"，这是范式盲区。

### 创新一：CDP 作为 Agent 的实时上下文（不是仪表盘，是决策供给）

**趋势**：画像最大的价值不该是让人盯着看，而是**当访客出现的这一刻，喂给 AI
去决定对他做什么**——现写哪句文案、推哪个产品、给不给折扣、要不要留资。
数据的消费者是决策 Agent，不是分析师。

**为什么现有 CDP 解不了**：它们的输出终点是报表/人群包，人再去配规则。
中间隔着"人看图→人配规则"，慢且不个性化到人。

**我们独有的筹码**：CDP 实时画像 + AI 引擎 + 站点 Agent/渲染时个性化（内容
模块创新二/三）。可以让画像成为一个**实时 context API**：任何前台位置、
站点 Agent、收款话术，都能取"这个人是谁、在哪一步、最可能要什么"，让 AI
当场决策。**没有任何 CDP 把画像做成"给 AI 的实时决策供给"。**

**第一步**：一个 `profile_context(visitorId)` 供给接口（身份 + 关键 traits +
分群 + 下一步倾向），先接站点 Agent 与落地页 AI 区块。

### 创新二：自然语言问数据（跳过"自助拖拽分析"整整一代）

**趋势**：运营不该学会搭漏斗/配维度，而是直接问"**为什么上周转化掉了**""
**哪个渠道来的人最值钱**"，AI 去查事件、算、并用人话解释 + 给行动建议。
mixpanel/Amplitude 都在往这加，但它们是"拖拽分析 + AI 辅助"，我们可以
"AI 优先"。

**为什么现有 CDP 解不了本质**：它们的分析是给分析师的工具；无团队的用户
既没时间学拖拽，也没分析师。

**我们独有的筹码**：全量事件在 SQLite（可被 AI 生成 SQL 查询）+ AI 引擎 +
已有的几十个分析方法（可作为 AI 的"工具"调用）。让 AI 把自然语言翻译成
对这些方法/SQL 的调用，回人话洞察。**直接跳过"手搓一个 mixpanel"。**

**第一步**：一个"问数据"框，AI 把问题映射到已有分析方法（getFunnel/
getRetention/getRevenueAttribution…）或安全的只读 SQL，返回结论 + 图 + 建议。

### 创新三：自主 CDP —— 数据自己行动，不只是告知

**趋势**：分群进出群不该只是"触发一个预设流程"，而是**进群这一刻，AI 判断
对这个具体的人此刻的下一最佳动作（next best action）并执行**——发券/推课/
留资/由销售跟进，因人而异。CDP 从"告知"进化到"行动"。

**为什么现有 CDP 解不了**：destinations 推的是"人群→渠道"的粗管道，
不是"人→此刻最该做的一件事"。规则式 MA 也做不到千人千面的当场决策。

**我们独有的筹码**：实时分群 + segment_enter 已接 flow（上轮验证）+ AI +
成交动作（收款链接）。把"进群→固定流程"升级为"进群→AI 决策 NBA→执行"。

**第一步**：segment_enter 时，除了跑预设流程，额外让 AI 基于画像产出一条
"此刻最该做什么"的建议（先人工确认，再逐步自动）。

### 创新四：LLM 驱动的预测与倾向（不建 ML 基建）

**趋势**：流失预测、LTV 预测、购买倾向（propensity），无团队用户没有数据科学
团队去训模型。LLM 可以**基于画像 + 行为序列直接给出倾向判断与理由**，
是一条绕开 ML 基建的务实路径。

**为什么现有 CDP 解不了（对我们的用户）**：神策/Amplitude 的预测要配数据/
建模，重；小客户用不起来。

**我们独有的筹码**：结构化画像 + 事件序列 + AI。让 AI 读一个人的画像 +
最近行为，输出"流失风险/购买倾向 + 理由 + 建议动作"，作为 computed trait
写回画像，供分群与激活用。

**第一步**：给画像加 AI 计算的 `churn_risk` / `buy_propensity` 两个软标签
（带理由），先在"高流失风险"人群上验证。

### 创新五：对话式补全画像（零方数据）

**趋势**：被动埋点只知道"他做了什么"，不知道"他是谁、想要什么"。站点 Agent
（内容模块创新二）可以在对话里自然地问、并把答案**结构化写回画像**（零方数据），
比猜准得多。

**我们独有的筹码**：站点 Agent + CDP 画像 + 事件字典（问到的属性有登记）。

**第一步**：站点 Agent 在合适时机问一两个关键问题（行业/预算/目标），
写回画像属性，立刻用于个性化与分群。

## 客户很需要、但都没有的（独特占位）

- **画像即决策供给**：别的 CDP 给你图表和人群包，我们给 AI 一个"此人此刻"
  的实时上下文，让每个前台交互都能当场因人而异——这是把 CDP 从"分析工具"
  变成"增长的神经系统"，无团队用户尤其需要（他们没有分析师去看图配规则）。
- **问数据代替学分析**：一个人运营，要的是"问一句得一个结论 + 一个动作"，
  不是学会搭漏斗。AI 优先的分析是我们能越级的地方。
- **数据会自己行动**：进群即 AI 决策并执行 NBA，把"洞察→行动"的人肉中间层
  抹掉——这正是"没有团队也能像有增长团队一样运转"的核心。

---

## 小结与建议节奏

CDP 是最强模块，但要先还一笔架构债、补一个战略空白，再谈创新：
- **地基（P0）**：画像迁 SQLite（写放大，比 events 更紧迫）。
- **战略补齐（P1）**：人群激活/destinations（圈了要推得出去）、同意/保留合规。
- **创新（重仓）**：画像即 Agent 实时决策供给、自然语言问数据、自主 NBA、
  LLM 倾向预测。**筹码全现成**，且和内容模块的站点 Agent/渲染时个性化同源——
  两个模块的创新其实指向同一个东西：**一个懂每个访客、当场决策的增长大脑**。
