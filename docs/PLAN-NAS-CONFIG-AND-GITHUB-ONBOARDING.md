## 二、本地开发配置优化（NAS 化）

### 2.1 目标与验收（DoD）

1. **公开面零隐私**：已跟踪文件、示例配置、日志样例无内网地址、账号、密钥路径、Zone/账号 ID、本机绝对路径；**历史提交亦已清理**；有守卫防回潮。
2. **零过时引用**：不出现指向退役主机、旧面板、旧端口、不存在目录的可执行指引（历史附录除外）。
3. **单一真源**：每类配置一个权威位置。
4. **路径可分辨**：宿主 vs 容器路径有明确写法。
5. **缺失即显式**：变量缺失要么失败并提示，要么明确降级。
6. **冷启动回放通过**：按文档从零走一遍，偏差为零或全部有据可查。

### 2.2 要做的事

#### A. 公开面脱敏 + 历史重写（P0）

**A1 清点与替换（工作树）**：按隐私类型（内网/公网地址、SSH 用户与端口、Key 路径、Zone/账号 ID、桶名、本机绝对路径、邮箱、内网主机名）逐条定位到文件:行，替换为占位符；脚本默认值改为空并在缺失时报错；示例配置只留占位。

**A2 历史重写（已批准）**，步骤与验收：

1. **冻结**：暂停部署与 push；通知所有使用方（含 AI 会话）"即将重写，请勿提交"。
2. **备份**：本地镜像是必须的——整仓备份 + 远端 `--mirror` 克隆，确保可回退。
3. **扫描基线**：对全历史跑隐私与密钥扫描，产出"必须清除"的字符串清单（地址、ID、路径、可能的凭据）。
4. **重写**：用 `git filter-repo`（或等价工具）按替换规则重写全部提交；同时清理已删除文件里的残留。
5. **验证**：对**重写后的每个提交**重跑同一套扫描，命中必须归零；抽查关键历史节点（tag 指向、发布点）内容正确。
6. **推送**：force push 所有分支与 tag；**tag 重建**（原 tag 指向旧对象会保留旧历史）。
7. **善后**：所有克隆失效 → 通知重新克隆；CI 缓存清理；GitHub 的旧提交缓存视图需向支持申请清理（可选，不阻塞）。
8. **守卫**：pre-commit + CI 增加"内部地址/本机路径/已知 ID"规则，防止回潮。

**风险与边界**：① 重写会改变所有 SHA，任何人基于旧 SHA 的分支/PR 都会断，需提前通知；② 3 个 Draft Release 需重建或重指向；③ 若后续发现凭据，**轮换优先于重写**（重写不能收回已泄露的密钥）；④ 重写后 `deploy.py --from-git` 等基于 SHA 的流程需重新验证。

**A3 执行记录（2026-11-23，工作树部分已完成）**

已做：16 个跟踪文件的占位符替换；4 个脚本改为"缺参即报错"（部署目标、CF Zone、R2 桶、退役主机同步脚本）；后台发信提示改为 SPF/DKIM 说明并删除服务器地址；`admin/utm-builder.php` 的本机路径兜底改为环境变量；新增 `scripts/check-public-surface.sh` 并接入 CI 的 `public-surface` job；`.env.example` 补必填项与占位（无真实值）。

待做：① **轮换 R2 访问密钥**（历史含真实密钥，见事实 26）并复核 CF Token 权限；② **历史重写**（需停部署窗口）；③ 本机 `.env` 补齐 `OF_DEPLOY_HOST` / `OF_DEPLOY_USER` / `OF_DEPLOY_ROOT`（用到 ops 与 CDN 脚本时再补 `OF_DEPLOY_OPS_ROOT` / `OF_CF_ZONE` / `OF_CF_ACCOUNT_ID` / `R2_BUCKET` / `R2_ENDPOINT`）；④ P2 的文档结构重写（旧 VPS 段落折叠为历史附录）。

#### B. 配置真源地图

四层（入口与部署器 / 运行时 / 凭据与第三方 / 服务器侧），每层记录权威文件、读取方、缺失行为、影响面、核对手段。产出 `docs/CONFIG-SOURCES.md`。

#### C. 路径双命名空间

规则：运维文档与部署器用宿主路径；站点内配置与代码用容器内路径或相对路径。判据："同一文件在两套命名空间下是否指向同一物"。

#### D. 环境变量分层

四类登记；定"对外可见性 / 优先级 / 缺失行为"。因仓库公开，部署目标类变量**不写默认值**，示例只给占位符。

#### E. 三种核对手段

静态扫描（退役主机/旧目录/旧端口/旧变量/隐私模式）→ 运行时自检（dry-run + 目标机只读探测）→ 文档回放（他人照文档走，只记录卡点）。

#### F. 替换节奏与影响面自查

先兼容 → 切默认与文档 → 清旧引用；每批一个提交 + 一个回滚点。每批填影响面表：页面 / 接口 / 后台 / 定时任务 / 兄弟产品 / 公开仓库，逐项验证。

#### G. 凭据治理

只存两处（Keychain / 本地 `.env`）；文档只写变量名与获取步骤；自检只输出"已配置/未配置/通过/失败"。

## 三、GitHub 新手引导

### 3.1 读者与上线定义

读者：有 VPS 但不懂 PHP 运维 / 只有 NAS / 只想先看效果。上线五项：HTTPS、后台登录、发内容、收留资、cron+备份（并会回滚）。

### 3.2 Demo 权限（设计已定）

#### 3.2.1 入口与申请

复用 `/enterprise.php` TOB 表单，增加"申请演示"选项与 `plan_type` 打标；保持现有蜜罐与 `leads.csv` 兜底；邮件通知运营。**必填**：企业名、联系人、企业邮箱（用于去重与预审）、手机（选填）、用途。

#### 3.2.2 审核与开通（我代定）

- **自动预审**：字段完整 + 企业域名邮箱（非公共邮箱）+ 未命中黑名单 + 该邮箱域名无现存空间 → 状态置"待开通"；否则"待审核"。
- **SLA**：1 个工作日内处理；超时在后台高亮。
- **开通**：后台一键（创建空间 → 写入种子 → 生成邀请码 → 设到期 +90 天 → 发邮件）。脚本仅用于批量或灾备。
- **凭据**：一次性邀请码（7 天有效、首次使用绑定会话），邮件模板 + 后台可复制；不发明文密码。
- **去重**：同一企业邮箱域名最多 1 个空间；第二单转人工。

#### 3.2.3 只读边界（允许模拟动作）

| 入口 | 处理 |
|---|---|
| 内容保存 / 设置修改 | **拒绝**，提示"演示环境只读" |
| 上传 | **拒绝**（或临时目录 + TTL 清理，不占配额） |
| 表单提交 | **模拟**：走完整校验，返回成功文案并标注"演示不会真实发送/入库"，不落库 |
| 自动化 / "跑一轮" | **模拟**：在隔离沙箱执行，结果仅当前会话可见，会话结束清空 |
| 订单 / 支付 | **拒绝**（可显示示例订单） |

### 3.3 部署方式与分发

**A. 源站形态（真正跑 PHP 的地方）**

| 形态 | 适用场景 | 前置条件 | 步骤要点 | 主要失败点 |
|---|---|---|---|---|
| Docker Compose | 有 Docker 的 Linux/NAS；**推荐默认** | Docker + Compose；端口；两个持久化目录 | 取代码 → 起容器 → 确认数据落宿主 → cron → 反代 TLS | 卷属主不对（保存无效）；端口占用；未挂卷丢数据 |
| 服务器原生 Apache | 传统 VPS、需与已有站点共存 | Apache + PHP 8.1+ + 扩展；`AllowOverride` | 站点根 → 权限 → 伪静态 → cron | 重写未生效（全站 404）；扩展缺失；同机站点互相影响 |
| Nginx + php-fpm | 已有 Nginx 体系 | Nginx + php-fpm；伪静态规则文件 | 站点根 → 伪静态 → 拒 `data/` 与 `.env` 直连 → cron | 规则与 `.htaccess` 漂移；美化 URL 失效 |
| **宝塔面板** | 有面板、想少敲命令 | 面板 + 可配 PHP 版本/扩展 | 建站指向仓库根 → 伪静态 → 属主 → 计划任务 | 面板默认伪静态不含项目规则；`data/` 被备份策略遗漏 |
| **1Panel** | 同上，偏容器化 | 1Panel + 应用商店/编排 | 编排或原生站点 → 目录挂载 → 反代 → 计划任务 | 容器 UID 与目录属主不一致；反代头缺失 |
| **NAS（群晖/威联通/fnOS）** | 家用/小团队 NAS | 容器管理套件；共享目录；内网反代 | 目录映射 → UID/属主 → 内网端口 → DDNS/Tunnel | 套件权限与容器 UID 冲突；误填容器内路径 |
| 本地 `php -S` | 只看效果 | 本机 PHP | 起服务 → 首页 → 向导 | 非生产，勿对外 |
| 共享主机（cPanel） | 便宜、无 root | 需支持重写 + 指定 PHP 版本/扩展 | **不承诺**，标"待验证" | 无法装扩展、改 vhost、cron 受限 |

**B. 接入层（叠加，不单独成立）**：Cloudflare（DNS/缓存/Tunnel）、反代 + 自动 TLS、对象存储、邮件发信、定时任务。每项必须写"不做会怎样"：不配 cron → 定时发布与自动化不转；不配 TLS → 后台登录不安全；不配反代头 → 回调与重定向错。

**分发四种**（已确认）：

| 形态 | 面向 | 要点 |
|---|---|---|
| clone | 开发者 | 分支/tag、升级路径 |
| Release 包 | 不装 git 的用户 | 版本号、校验和、解压即用、升级不覆盖 `data/`/`uploads/` |
| 容器镜像（GHCR） | NAS / 省事 | tag 策略、卷、环境变量、健康检查、多架构 |
| 一键脚本 | 零基础 | Ubuntu/Debian 优先、检测 Docker、幂等、失败可回退 |

### 3.4 快速部署主线（S1–S8）

| 步 | 做什么 | 完成信号 | 常见卡点 |
|---|---|---|---|
| S1 | 前置盘点（系统/版本/端口/域名/是否已有站点） | "能装/不能装"结论 | 端口占用、PHP 过低 |
