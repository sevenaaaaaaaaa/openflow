# 产品北极星（所有规划的共同前提）

> 每一份模块规划（`docs/AUDIT-0X-*.md`）都在这个坐标系下做，别各写各的。
> 本文只讲「我们为什么与众不同、往哪走」，不列具体任务。

## 一句话

**别人的产品帮你「用工具完成一件事」；OpenFlow 把网站的每一项能力——内容、
数据、触达、成交——焊成一个活的、懂访客、会自己达成目标、还能被 AI 直接
调用的增长系统。** 面向没有团队的一人公司 / 超级个体 / 创作者，我们常常是
他们的唯一解。

## 三样别人没有的筹码（一切创新都从这里长出来）

不做无源之水的「未来功能」。判断一个方向该不该做，先问：**它是否落在这三样
我们独有、而竞品结构性缺失的零件上？**

1. **CDP 实时画像**：匿名→登录→跨端合并的用户身份与行为，实时可查。
2. **常驻 AI 增长引擎**：不是「AI 按钮」，是每天自动选题/成文/巡检/优化的
   后台 Agent（`GrowthEngine`）。
3. **MCP / 知识底座**：`mcp-server` + 知识库，让系统的内容与能力可被 AI Agent
   直接查询与调用。

WordPress/Ghost/Webflow/Segment/神策/HubSpot 各强一块，但没有谁三样都有，
更没有谁把它们和「一个人就能跑完」焊在一起。**这是存在理由，也是护城河。**

## 判断新功能的两把尺

- **地基尺（守）**：不补，现有用户上量就撞墙（例：自定义内容类型、多语言、
  全文搜索）。必要，但不构成存在理由。
- **创新尺（攻）**：现有产品**结构上**解不了、AI 让它必然到来、且落在上面三样
  筹码上（例：内容可被 Agent 执行、渲染时生成式个性化、目标制内容）。
  **新用户来的理由在这里，叙事与差异化投入压在这里。**

两条腿都要走；但每份规划必须明确区分「这是守还是攻」，不许把修补当创新。

## 一个统一的内容/数据世界观（从内容模块提炼，适用全线）

未来的内容/数据分三种生产方式，本质是同一条轴——**人把关到什么程度**：

1. **AI 辅助人工创作**：人主导，AI 压缩「想到→上线」的距离。
2. **面向 AI/Agent 的纯 AI 内容**：受众是机器，不是人。
3. **人辅助 AI 的全新内容**：人掌过程与把关，AI 掌知识；靠「强制接地、无源
   不发」保证可信。

由此，产品围绕三条轴重建，而非围绕「编辑一个文档 / 看一张报表」：

> **谁生产 × 给谁消费（人 / 机器）× 人把关多少**

这套世界观先在内容模块落地（`AUDIT-01-CONTENT.md`），但**适用全线**：
CDP 的数据也要「给机器消费」（喂 Agent 决策）、MA 的内容也分三种生产方式、
Sales 的话术同理。后续每个模块审计，都在这套坐标系里找它的攻守两面。
