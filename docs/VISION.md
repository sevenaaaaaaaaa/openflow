# OpenFlow 产品北极星

> 本文定义长期不变的产品边界。各版本交付的能力见根目录 `CHANGELOG.md`。

## 一句话

**OpenFlow 是一套基于 TIPS、同时支持 Flow 与 Loop 的开源增长操作系统。**

它把用户触达、用户洞察、个性化运营和销售增强连接在同一套数据与业务能力上：有经验的人可以用 Flow 精确设计和稳定执行；缺少经验或人力的人可以用 Loop，让 TIPS Agent 在明确边界内组合能力、验证策略并持续优化。

## 不变的 TIPS 业务模型

- **Touch**：建立有效触达，让正确的人进入业务。
- **Insight**：从真实行为与成交结果中形成证据和判断。
- **Personalize**：对不同的人，在合适的时机采取不同动作。
- **Sell**：推动成交、交付和复购，并把成功与失败回流洞察。

TIPS 既是产品的信息架构，也是 Flow 的能力分类、Agent 的推理边界和完整工作流的质量标准。任何增长方案都必须说明触达谁、依据什么判断、如何差异化运营、怎样产生业务结果，以及结果如何回流。

## 两种长期并存的运行范式

### Flow · AITIPS Copilot

人掌握策略，使用节点、画布、规则和分支设计流程；AI 作为 Copilot 帮助搭建、检查、生成和优化；系统按照批准的流程确定性执行。

Flow 解决“把已知方法稳定执行”，适合成熟 SOP、高阶用户，以及交易、交付、通知等强调可预测性和合规性的业务。

### Loop · TIPS Agent

人定义目标、资源、预算和风险边界；Agent 读取真实业务状态，按 TIPS 制订策略，调用 Skills 与成熟 Flow，在 Harness 和 Policy 约束下执行或请求审批，再依据业务结果进入下一轮。

Loop 解决“知道想要什么，但不知道最佳路径”，适合跨模块协调、动态试验，以及缺少专职增长经验和人力的用户。

Loop 不是无限调用模型。它必须具备 Goal、State、Skills、Harness、Policy、Evaluation、Memory 与 Stop Conditions，并以真实业务结果而非模型自评判断效果。

## 两者没有高低之分

- Flow 不会被 Loop 淘汰；确定性业务永远需要可检查、可预测的流程。
- Loop 不应退化成画布上的 AI 按钮；它必须能够基于反馈形成和调整策略。
- 成熟 Flow 可以成为 Agent 可调用的可靠 Skill。
- 经过多轮验证的 Loop 可以固化为新的 Flow。
- 同一业务对象在两种模式中共享数据、权限、审计和执行能力，不维护两套实现。

由此形成产品的经验飞轮：

```text
人的经验 → Flow → Agent 的可靠能力 → Loop 组合与试验
        ↑                              ↓
        └────── 稳定策略固化为 Flow ──┘
```

## 产品首先服从业务

OpenFlow 不以 AI 覆盖率或交互新颖程度判断进步，而以业务实用性、稳定性和兼容性判断：

1. AI 不可用时，核心内容、数据、自动化和交易能力继续运行。
2. 可靠动作应固化为 Flow 或有契约的 Skill，不让模型重复发明。
3. 策略可以组合，执行不能绕过权限、同意、频控、预算和审批。
4. 高风险动作始终保留人工闸门；自治只能按工作流逐步提升。
5. 每项行动有证据、版本、成本、结果和审计记录，并可暂停、接管和恢复。
6. 默认保持 PHP + JSON/SQLite 的轻量兼容性，仅按真实规模信号升级底座。

## 目标用户与边界

优先服务一人公司、创作者、个人品牌和没有专职增长团队的小型组织。他们既需要一套能直接运行的业务系统，也需要 AI 弥补经验和人力不足。

OpenFlow 不与专业 BI、重型 CRM、通用电商或大型企业套件竞争单点深度。存在价值是把足够完整的 TIPS 能力、确定性 Flow 和受控 Loop 放在同一套本地优先系统中，减少拼接、配置和人工搬运。

## 判断新建设的四把尺

每项新建设必须同时回答：

1. **业务价值**：是否解决真实 TIPS 问题，能否定义可衡量结果？
2. **范式归属**：它属于 Flow、Loop、二者共享底座，还是只是重复入口？
3. **可靠边界**：失败、超时、权限、预算、审计和回滚怎样处理？
4. **验证阶段**：现在是 Built、Integrated、Used 还是 Proven？

不能回答以上问题的功能，不进入主路线。

## 远景

OpenFlow 最终交付的不是更多页面或一次性 AI 对话，而是一套属于每个组织的增长工作流资产：

- 人的经验可以沉淀和稳定执行；
- Agent 可以在 TIPS 边界内补足经验、组合能力和小步试验；
- 真实结果能够回流并形成记忆；
- 有效策略可以被固化、复用、分享和持续改进；
- 用户始终能够理解、接管和控制系统。

**最终目标不是让 AI 取代人，而是让增长经验可以稳定交付并持续复利。**

## 附：为什么增长需要一台「操作系统」

> 这一节原是 README 的开篇长文，2026-10 移到这里。README 现在是林下 Understory 的入口页。

AI Agent 时代，制约增长的根源已经不是能力不足，而是**协作与组织术的缺位**。

过去，一个人想做大增长，只有两条路：要么雇团队，把自己变成管理者；要么用一堆 SaaS，把自己变成操作员。前者成本高昂，后者把你切碎在工具之间。个体能成为超级个体，从来只是概率事件，背后真正的决定因素是：**那个直接责任人（DRI）能否围绕自己重新组织资源。**

OpenFlow 就是围绕这个命题造的系统。它把触达、洞察、个性化、销售装进同一个 TIPS 框架：四力不是四个功能区，而是一条反馈回路——成交与丢单的真相回流洞察，洞察调整内容与渠道。一个人拥有了系统，他的每一步努力才开始积累，而不是清零重来。

### 每个界面都是组织术，不是功能

- **今日主线**：全站信号不按功能模块分散，而是按「你」收口成一条行动脊柱：先处理钱与时效，再推进今日目标。你的注意力花在哪，增长就在哪。
- **AI 岗位**：不是跑一次的任务，是有 KPI、有工具边界、每天交班的数字员工。它接住你本来要雇人做的那部分；策略、审核、发布的决定权全程在你手里。
- **驾驶舱与 CDP**：KPI、漏斗、AI 解读在驾驶舱；每个访客的来源、行为、成交在 CDP 一人一册。没有真相回流，增长只是碰运气。
- **自动化画布**：拖拽触发器、条件、动作与延时，你的 SOP 变成系统确定性执行的 Flow。方法来自你，执行交给系统，留痕给你复盘。

### Flow 与 Loop：手动挡与自动挡

无论个体还是 DRI，最重要的永远是人：你的经验、你不可替代的价值、你独有的资源整合能力。所以每项能力都把追踪与决定权留给人：

- **Flow 是手动挡**：你设计节点、画布与规则，AI 只辅助搭建与检查，系统按你批准的流程确定性执行——适合已经知道怎么做的 SOP。
- **Loop 是自动挡**：你定义目标、预算与边界，Agent 在白名单工具里观察、执行、评估，中高风险回到你手里批准——适合知道目标但缺人手的探索。

OpenFlow 不相信 AI 能替你决定增长的意义。**挡位可以换，方向盘永远在你手里。**

### 自我进化（方向，不是现状）

自我进化的前提，是数据在系统里自由流动：内容表现、访客行为、成交真相、Agent 的每一步动作，全部回流到同一套 TIPS 数据模型。长期承诺是：部署了 OpenFlow 的人，随着数据积累，最终能炼化出一个完全符合自己的版本。同一份代码，每个 DRI 长出的系统各不相同。

### All-in-one 的边界

任何 All-in-one 都有边界。OpenFlow 做的，是把一个人「以后才需要」的系统能力提前兑现——你现在就有一个 beta 版的未来，然后按自己的节奏组合更深的产品：内容产能看风媒 MFlow，全域数据看触级 UserLoop，外部情报看洞澜 inFlow，变现看芭乐 Pay PayFlow，交付看林下学院 LearnFlow，投放落地页看魔块 WebsFlow；鹿蕊、松萝、成章、林可兔、零真组成偏本地的 Studio 工作台。完整矩阵见 [README](../README.md#产品矩阵)。

### 为什么核心永久开源

OpenFlow 的核心能力——包括 TIPS 范式——过去、现在、将来都以 MIT 协议开源。商业上的回报来自托管、定制与服务，与开源版的功能无关。欢迎任何善意的组织与个人 fork 出自己的版本。在 AI 时代，代码从来不是稀缺品，稀缺的是把经验沉淀为系统的范式。
