## 二、趋势调研：两个相关机会点

### 机会点 A（本轮选定）：Agentic Onboarding——从"教用户配置"到"Agent 替用户装配"

- AI 引导的初始化正在从"清单式引导"进化为"**AI 直接替用户把产品配置好**"：Aimdoc 把自己定义为"替用户完成设置的 onboarding agent"；Runloop 的 Repository Connect 主打"消灭数小时手工配置"的即时 Agent 装配；Unified.to（2026-04）提出 Agent 在运行时自选工具、跨系统执行，正在打破"集成必须用户自己配"的假设。业界尚无统一命名（"agentic onboarding / AI onboarding agents / instant setup"并存）——**正是窗口期**。
- 对 OpenFlow 的含义：产品自己的定位就是"门槛降低器"，而 189 项功能对新手是一道墙。「自动装配」骨架已在，缺的是**把"装配什么"知识化**——这就是候选池里的方向④「行业开局包」，但趋势给它一个更准的形态：不是静态模板，是**装配师**。

### 机会点 B（记录、缓立项）：数据合作社式基准网络

- "匿名贡献数据 → 换取同行对标"是 2026 年公认的数据网络效应护城河（更多贡献者 → 更厚基准 → 更强留客），买家在 2026 年"要求同行验证才肯谈 demo"；基准类数据还是 AI 引擎推荐的高引用素材（与 GEO 互相喂养）。SaaS Capital 的私有基准甚至已通过 Claude/ChatGPT 分发。
- **为什么本轮缓立项**：基准网络的前提是"有足够多活着的站点在产生数据"。当前激活基数撑不起基准的可信度——先解决"装了的人活下来"，再让他们互相比较。候选池把它从第 1 位移后，理由写进第八节。

## 三、圆桌第一轮：发散与交锋（纪要）

**CEO**：先摆一个尴尬：我们上周刚把 README 升维成"AI Agent 时代的增长 OS"，矩阵短票也通了——**兄弟项目的用户马上要从短票流进来，而他们的第一站是 189 个菜单**。入口层自称"门槛降低器"，但门槛现在是全系统最高的那一处。候选池里我把基准网络排第一，因为它是护城河；但今天我要自己打自己：**护城河需要先有活人**。趋势调研里那条"agentic onboarding 窗口期"让我更倾向先做激活。我真正的担心是：模板包这种东西 WordPress 有几万个主题了，凭什么我们的不是又一个模板市场？

**产品负责人**：CEO 的问题我接。我的答案预演：区别在"模板给你文件，我们给你**在跑的流程**"——装配完是真的 flow 在跑、真有待办在今日主线里。但先说我的顾虑：**这不是产品问题，是内容问题**。谁维护 20 个行业的包？包会不会三个月就过时？我的立场：宁可只做 3 个包，也不做 20 个半成品；另外我拒绝再开一个"向导弹窗"——装配产物必须落进今日主线，成为第一周的计划，而不是装完就散。

**增长负责人**：补一个漏斗事实：短票兑换只是**获客**，开机完成才是**激活**，现在中间是断的。我的候选本来是④行业开局包，但我要给 CEO 的"凭什么不是又一个模板市场"补一刀数据视角：模板市场的用户拿到主题就走了，因为他们的成功指标是"下载量"；我们的成功指标必须是**TTFV——从注册到第一条增长流程真正跑通的时长**。这条指标今天根本不存在，因为"第一条流程"对每个用户都长不一样。

**技术负责人**：可行性我先说好消息：「自动装配」v2.5 已经能从投喂生成 flow/目标/分群/内容/落地页/待办并逐个确认——**行业包本质上是"预填好的投喂 + 预设答案"**，装配引擎不用新写。无 Key 也能跑：晨会已有模板兜底先例，包的装配走确定性路径，AI 只做可选润色。但我要主动举红旗，这是本周 git log 里最疼的教训：**我们花了整整一轮清理 demo 残留**——如果开局包为了"看起来热闹"塞假业务数据，就是把刚清完的债再借回来。装配产物里不能有一行假订单假客户。

**客户成功负责人**：给你们真实声音。用户原话："我买了系统，然后有一百多个菜单，我不知道今天该点哪个。"我要的需求很朴素：**10 分钟内有第一次"它动了"的体验**。但我反对按行业做包——一人公司横跨花店、咨询师、播客主理人、跨境电商，行业是无穷集，而且花店和摄影师要的东西其实差不多：都是"卖作品/卖时间"。**真正决定他们要什么流程的不是行业，是生意的形状：卖课的、接咨询的、卖货的、卖订阅的。**行业只是皮，形状才是骨。

**主持人小结（第一轮分歧点）**：
1. CEO：护城河（基准网络）vs 激活（开局包）的先后；模板市场之问；
2. 产品：包是内容债风险，只做精品；产物必须进今日主线；
3. 技术：零假数据的红线；客户成功：**按"生意形状"分包，不按行业**。

## 四、收敛后的议题（第一轮 → 第二轮之间）

> **议题：开机即营业——「生意形状包 × Agent 装配师」**
>
> 一句话：新用户开机时只回答两个问题（你的生意是什么形状 + 你的第一目标），装配师据此把流程、分群、目标、落地页骨架、第一周计划**真实创建并落进今日主线**——10 分钟跑通第一条增长流程；行业作为包内的"风味层"可换皮，形状才是骨架。

对第一轮分歧的回应：
- 对 CEO：不做模板市场，做"装配后即运行"的活系统；基准网络缓立项但已接线（见第七节）。
- 对产品：只做 3+1 个形状包；包格式进 ADR；产物零假数据。
- 对客户成功：形状轴替代行业轴，包的数量收敛为有限集。

## 五、圆桌第二轮：质疑与补强（纪要）

**CEO（质疑 → 补强）**：我的反对：装配师如果只是"初始化向导"，用完即弃，撑不起"重要革新"四个字。补强把它升为常驻能力：**包不是一次性的，是系统对"你的生意"的第一份理解**——后续所有能力（晨会、岗位制、实验循环）都从"形状 + 目标"这份初始档案出发做个性化；用户生意变了（卖课的开始卖咨询），改档案即可重装配增量大项。叙事口径定为：**竞品卖功能清单，我们卖"第一周"**。矩阵层面这也是入口层的兑现——短票进来的人第一站不再是菜单，是开机。

**产品负责人（质疑 → 补强）**：两个反对。第一，向导必须**可跳过、可恢复、可重跑**——熟练用户第三次进来不能被 10 步向导绑架；老用户补做装配走设置页，不阻塞进入。第二，"为什么做这件事"必须跟着产物走：每个装配出的待办要带一句理由（"先建分群，因为后面 3 个流程都靠它圈人"）——一人公司要的不只是被伺候，是**边用边学会**，这决定了他第二年还在不在。补强：装配完成页即"第一周计划"，五条泳道进今日主线；包格式写 ADR-006（PackSpec：声明式 JSON，字段白名单，版本化）。

**增长负责人（质疑 → 补强）**：我的反对：TTFV 若定义为"注册到跑通"会在执行里被做小——把流程做短就行，作弊空间太大。补强口径：TTFV 拆两层——**机械 TTFV**（注册→装配完成）与**业务 TTFV**（装配→第一条真实业务动作发生：第一封邮件发出、第一篇文章发布、第一单成交）；北极星取后者。漏斗挂四层：短票兑换→开机完成率→首条业务动作率→D7 留存；包本身也进增长飞轮——每个包底部带"本包效果数据"（匿名聚合），装机量与效果互相证明。顺带：189 项功能总表刚做成文档，包的装配页直接按形状引用对应功能文档章节，激活与 SEO 一鱼两吃。

**技术负责人（反对 → 架构补强）**：零假数据红线我重新表述成可验收的规矩：**装配产物 = 结构（flow/分群/目标/落地页骨架）+ 草稿（内容进待审队列）+ 待办（今日主线），全程零业务假数据**——demo 纪律延伸到装配引擎，写进契约测试。架构四件套：
1. **`PackSpec`（docs/ADR-006 + lib/packs/*.json）**：声明式 JSON——形状档案、预设投喂、装配项清单、理由文案；版本化 + 健康检查（装配项引用的模块不存在即报红，防包腐化）；
2. **装配引擎 = 自动装配的预填层**：`lib/AssemblyEngine.php`（薄）——把 PackSpec 翻译成自动装配的既有输入，**不新写装配逻辑**；无 Key 走确定性路径全量可用，Key 恢复后 AI 只做"按用户已有素材改写文案草稿"，产物全部进待审；
3. **包注册表页**（后台）：安装/更新/回滚，沿用插件平台的回滚 UI 纪律；
4. **不做清单**：不做包市场/第三方分发（等自建包稳定）；不做跨形状自动推断（形状必须用户自答，猜错了全盘皆错）；装配不碰支付/群发等高风险动作（沿用行动网关审批门）。

**客户成功负责人（反对 → 补强）**：我的反对：3+1 个形状包上线后，最难的不是做出来，是**用对**——用户会选错形状。补强：装配第一步给"形状判断器"——两道是非题（你主要卖时间还是卖货？交付是一次还是持续？）即可落形状，错了可换；每个包自带 3 篇站内帮助文章（help.php + seed-help.php 管线现成），首周计划的每条待办链到对应帮助页。用户故事定稿：**第 1 分钟**答两道题；**第 10 分钟**装配完成、第一条流程在今日主线里亮起来；**第一天结束**发出第一封邮件或发布第一篇文章；**第一周末**晨会第一次点名："你本周的形状目标是 X，完成了 Y"。

## 六、最终提案：开机即营业（Boot-to-Business）

### 6.1 要解决的问题

1. **激活断崖**：矩阵短票把用户送到门口，189 项功能的菜单墙把人挡在里面；"门槛降低器"的定位缺第一公里兑现。
2. **TTFV 不可见**：系统没有"第一条流程跑通"的标准路径，激活率无法度量也就无法改善。
3. **知识不自持**：自动装配有引擎没弹药——装配什么、为什么这么装配的知识散落在文档与创始人脑子里。

### 6.2 革新方案（产品如何变化）

| 变化 | 用户看到什么 |
|---|---|
| **开机向导** | 两道是非题定形状（可跳过/可恢复/可重跑），10 分钟装配完成 |
| **装配产物落主线** | 第一周计划五条泳道进今日主线，每条待办带一句"为什么"并链帮助文档 |
| **3+1 形状包** | 课程型/咨询型/内容订阅型首发，电商型随后；行业为风味层可换皮 |
| **包注册表** | 后台安装/更新/回滚 + 包健康检查（引用失效即报红） |
| **形状档案常驻** | 生意形状+目标成为系统对用户的长期理解，晨会/岗位制/实验循环据此个性化 |

### 6.3 核心交互与架构要点

- 装配引擎是自动装配的**预填层**而非新引擎（`AssemblyEngine` 薄封装）；PackSpec 声明式 JSON、版本化、ADR-006 定契约。
- 零假数据红线：产物 = 结构 + 草稿（进待审）+ 待办（进主线）；契约测试守纪律。
- 无 AI Key 全量可用（确定性模板路径）；AI 仅做可选的草稿润色——与"AI 挂了基础业务照跑"的既定原则一致。
- 高风险动作（支付/群发/删除）装配一律不触碰，沿用 ADR-003 行动网关。

### 6.4 分阶段路线图

| 阶段 | 内容 | 出口判据 |
|---|---|---|
| **一（1 周）· 骨架** | ADR-006 PackSpec + AssemblyEngine 预填层 + 课程型包 v0 + 开机向导（可跳过） | 契约测试过；无 Key 环境全流程可装配；产物零假数据断言通过 |
| **二（1–2 周）· 三包** | 咨询型/内容订阅型包 + 装配产物全落今日主线 + 包健康检查 + 每包 3 篇帮助文 | 机械 TTFV 中位数 ≤ 30 分钟（内部实测） |
| **三（2–3 周）· 矩阵接线** | 电商型包 + 短票兑换成功页直入开机流程 + 业务 TTFV 埋点 + 晨会读形状档案 | 短票→开机完成率开始有数并被周报追踪 |
| **四（条件触发）· 个性化与基准** | AI 按用户素材润色包内草稿（全进待审）；**活跃站点 ≥ 100 时**启动⑦基准网络冷启动设计（匿名化"形状 × 首周激活率"为第一个基准指标） | 条件指标达标即立项 |

### 6.5 风险与护栏

| 风险 | 护栏 |
|---|---|
| 包腐化（模块迭代后包引用失效） | PackSpec 版本化 + 健康检查报红 + 契约测试 |
| 假数据回潮 | 零业务假数据红线写进测试；产物三分类（结构/草稿/待办） |
| 用户选错形状 | 两道是非题判断器 + 可换形状重装配（增量，不推倒） |
| 向导绑架熟练用户 | 可跳过/可恢复/可重跑；老用户走设置页 |
| TTFV 被做小 | 北极星取业务 TTFV（真实业务动作），机械 TTFV 仅作诊断 |
| 包成为内容无底洞 | 形状轴有限集（4 个）；行业只做风味层；先自建不开放市场 |

### 6.6 成功衡量指标

- **北极星**：业务 TTFV——注册后首个真实业务动作（首封邮件/首篇文章/首单）的中位时长；目标 ≤ 7 天，首周目标 ≤ 48h
- 过程：机械 TTFV 中位数、短票兑换→开机完成率、包装配完成率、形状换选率（选错率代理）
- 留存与变现：D7 留存（装配用户 vs 未装配用户分群对比）、包用户→付费转化、包底部效果数据（匿名聚合）

## 七、与既有路线的关系

- **七方向**：本轮 = **方向④行业开局包正式立项**，形态被趋势校准为"形状包 × 装配师"；⑤自优化实验循环可直接对"包内待办排序"做实验；⑦基准网络**缓立项但已接线**（阶段四条件触发 + 第一个基准指标已定）——候选池顺位的调整是刻意的：先激活、后对标，理由见第二节。
- **上期 AX 引擎**：正交不冲突——AX 服务"来访问的 Agent"，开机即营业服务"来创业的人"；AX 阶段一/二（不依赖 Key）可与本期阶段一并行施工。
- **矩阵三层口径**：本期是"入口层 = 门槛降低器"这一承诺的第一次产品化兑现；短票兑换（账号真源）→ 开机流程（激活）→ 晨会（留存）串成矩阵用户的完整首程。
- **红线的延续**：零假数据是 demo 残留清理工作的制度延伸；无 Key 可用是"AI 挂了基础业务照跑"原则的应用。
