## 二、趋势调研：两个机会点

### 机会点 A（本轮选定）：Agent 成为真实且在增长的访客群体

- **Agentic Commerce 协议混战但底层在铺**：ACP（OpenAI+Stripe，2025-09）、UCP（Google，2026-01，五个月内 8,000+ 商家接入）、AP2（授权验证层）构成"层叠蛋糕"；Stripe ACS 是当前最广的落地通道。但同期现实检验也很清醒：美国消费者采纳仍低、OpenAI Instant Checkout 2026-03 因商家参与不足回滚，重心转向**商品发现**。
- **AX（Agent Experience）作为 UX 的镜像学科已经命名**：AXO/AEO/GEO 三分，核心主张是"下一个客户是 AI Agent"——可发现性（agents 能否找到你）与可交互性（结构化数据、API、机器可读报价）；实测数据显示优化过的页面对 AI 流量转化显著更好。
- **对 OpenFlow 的含义**：交易协议层还早且碎片化（不该碰），但**"Agent 发现 → Agent 引荐 → 人来成交"的漏斗上半段已经在真实发生**。站长现在的系统对这段流量完全失明：CDP 把它当 bot 丢掉，GEO 投入没有归因闭环，货架对 Agent 不可读。

### 机会点 B（本轮记录、下轮候选）：协议观察哨与交易出口

当 ACP/UCP/AP2 中出现收敛赢家且真实订单需求出现时，"让 Agent 替人下单"才值得接。现在唯一该做的是**留一个出口**（destinations webhook 已具备），并持续观察。本轮不展开。

## 三、圆桌第一轮：发散与交锋（纪要）

> 规则：每人先报自己赛道上最疼的一件事 + 一个议题候选。允许互相拆台。

**CEO**：先泼冷水。最近三周我们做了 Teams+ 和适配器工场，都是"平台变重"的动作，而我们的身份是"一人公司的增长 OS"。七方向里 AI 岗位制是主打，它解决的是"站内 AI 替我干活"。我的候选议题是 direction ⑦——匿名基准网络，它有网络效应，是护城河。但我真正睡不着的是另一件事：**如果未来一半的发现流量走 AI Agent，而我们整个漏斗对此失明，那"增长 OS"这个名号就名不副实了**。可我又怕我们追一个 2025 年就画大饼、2026 年还在回滚的风口。

**增长负责人**：CEO 说到点子上了，但我的角度更疼：**GEO 是我们 v2.5 的专家基准之一，可它没有 ROI 闭环**。实体图、引用份额（share of voice）都在做，但"引用份额涨了 → 带来多少访客 → 几个成交"这条链是断的——因为 Agent 和 AI 引荐流量在 CDP 里被当 bot 扔了。我每周给站长看 GEO 报告，最后一列永远是空的。我的候选：**Agent 流量归因，把 GEO 的钱变成能算账的钱**。这是最小、最快、最确定的一步。

**产品负责人**：我反对把这做成"又一个模块"。今日主线是我们 v2.5 最硬的 UX 资产——全站信号收口成"立即/今日/本周"三条泳道。任何新能力如果自己开一个新入口，就是往这条脊柱旁边再钉一根钉子。另外我有个更根本的质疑：**我们的统一「人」对象是全系统的地基，Agent 没有稳定身份**——UA 可以伪造、会话转瞬即逝，往身份图谱里塞"Agent 画像"是在污染地基。除非有人能回答"Agent 的身份是什么"，否则我不签字。

**技术负责人**：我可以先回答产品的一部分：身份问题有解，但不是"画像"解。我更想说三个可行性事实。第一，**协议层碰不得**——ACP/UCP/AP2 还在混战，Instant Checkout 都回滚了，我们一个 PHP 单体去追移动靶是自杀。第二，检测层是可行的：主流 Agent 与 AI 爬虫（OpenAI/Google/Anthropic/Perplexity）都公布官方 UA 与 IP 段，服务端分类是纯 PHP 就能做的事，不需要任何新基础设施。第三，一个命名上的真雷：仓库里 `actor_type` 已经被决策记录占用（`DomainContract.php` 里 human/policy），CDP 这边要用新字段名，别撞车。我的候选：**机器可读货架**——UnifiedCatalog 已经聚合了四源商品，把它吐成 JSON feed + llms.txt + MCP 工具，一周的活，零架构风险。

**客户成功负责人**：给你们带真实用户的声音。一人公司站长问我的原话是："**怎么让 ChatGPT 推荐我的课？**"——他们不关心 ACP 还是 UCP，他们关心的是"被推荐"。而且我要替小流量用户说话：日 UV 一百的创作者，Agent 访客可能就两三个，值得为他们建一整套东西吗？我需要你们回答"现在做这个，用户第几分钟得到什么"。还有，**别再发新报表了**——我们刚把空态清零，别又造一堆"Agent 看板"让用户对着两行数据发呆。

**主持人小结（第一轮分歧点）**：
1. CEO 怕追风口 vs 增长/技术认为漏斗失明是现在进行时；
2. 产品质疑 Agent 身份不成立 vs 技术认为有"非画像"解法；
3. 客户成功要求"小流量用户第几分钟得到什么"，反对新报表。

## 四、收敛后的议题（第一轮 → 第二轮之间）

> **议题：AX 引擎——把 AI Agent 变成 OpenFlow 的一等访客**
>
> 一句话：让系统**识别** Agent 访客（不再当 bot 丢弃）、**归因** Agent 引荐（补上 GEO 的 ROI 闭环）、**服务** Agent 读取（机器可读货架）、并把这些全部收进今日主线——而对交易协议只做观察、不做实现。

选择它的理由，对着第一轮的三个分歧：

- 对 CEO：不做交易（避开回滚过的风口），做"发现→引荐"这段已经在发生的流量；护城河来自闭环而非单点。
- 对产品：不新增入口、不碰「人」对象——Agent 用会话级"访客种类"表达，不进身份图谱。
- 对客户成功：第一周交付的是"体检 + 三件可修的事"，不是报表。

## 五、圆桌第二轮：质疑与补强（纪要）

> 规则：针对收敛后的议题，每人至少提出一个反对意见或补强，不许只说"同意"。

**CEO（质疑 → 补强）**：我的反对：这听起来像一个 feature，不是一个革新。WordPress 明天就能出一个"AI Visibility"插件，我们的差异在哪？补强之后我签字：差异不在检测或 feed 这些单点，**在闭环**——检测、归因、优化、证明 GEO ROI，四环只在 OpenFlow 里是通的，因为我们恰好同时拥有 CDP、GEO 实体图和 MCP。我要求提案里写清楚护城河表述，并且把 AX 定为对外叙事的一部分："第一个把 Agent 当访客的增长 OS"。另外这个闭环恰好喂养 direction ⑦：**匿名化后的 AX 体检分就是基准网络的第一批天然指标**——排队中的方向不是被绕开，是被接上了。

**产品负责人（质疑 → 补强）**：我的反对维持了一半：Agent 不进身份图谱，这条写进验收标准。但我找到解法了：引入**会话级 `visitor_kind`（human / agent / bot）三值**，Agent 会话是一个轻量"伪访客"，只挂行为时间线、不参与身份合并、不进 CRM——等一个人类真的顺着 Agent 引荐来了，归因用"相关性标注"（该新客到访前 7 天内站点有过 agent 引荐事件），诚实标注置信度，不硬拗因果。UX 补强：AX 相关的行动（体检扣分项、可修事项）**一律走今日主线泳道**，新增的只有一个"Agent 访客动态"折叠面板；站点 AI 助手获得一个新姿态——**Agent 迎宾模式**，对被识别的合法 Agent 访客直接用 MCP 工具回答目录与报价，这本来就是 Flow/Loop 双模式的自然延伸：体检与货架是 Flow（确定性），迎宾是 Loop（受控循环）。

**增长负责人（质疑 → 补强）**：我的反对：别把"Agent 流量占比"当北极星——那是虚荣指标，Agent 来得多不代表生意好。补强后的北极星：**Agent 引荐新客数**（首次访问前 7 天内有 agent 引荐记录的注册新客）。漏斗口径四层：agent 流量占比（诊断）→ agent 引荐点击（过程）→ agent 引荐新客（北极星）→ 引荐新客的转化率与 LTV（质量）。再补一个立刻能兑现的：**GEO 报表最后一列终于有数了**——引用份额变化 ↔ 引荐流量变化的联动图，这是我向站长证明"GEO 的钱花得值"的第一张真图。

**技术负责人（反对 → 架构补强）**：我的反对：检测层天生可伪造，UA 欺骗会让"agent 流量占比"变成可以被刷的指标，这在一个带公开接口的产品里是真实风险。补强的架构立场：**所有 agent 判定都是"最佳努力 + 置信度标注"**——官方 UA + rDNS/IP 段 + 行为指纹（请求节奏、资源加载模式）多信号合成，低置信度只计入"疑似"，不进归因。架构四件套：

1. **`AgentGate`（lib/AgentGate.php）**：服务端访客分类，纯 PHP 多信号判定，写事件时打 `visitor_kind` + `agent_confidence`；对合法 Agent 放行并限速，对伪装 UA 提高审查；复用单 IP 限流的既有模式。
2. **`AgentCatalog`（lib/AgentCatalog.php）**：UnifiedCatalog 四源 → 机器可读货架：JSON feed（缓存友好、CDN 可分发）+ llms.txt 新章节 + MCP 新工具 `get_catalog` / `get_offer`（只读、白名单、零 PII）。
3. **CDP 增列不增表**：events 表加 `visitor_kind`，写入时分类，历史数据默认 human，报表可切换显示——统计污染可回退。
4. **明确不做清单**：ACP/UCP/AP2 的 checkout 实现；Agent 侧个性化（Agent 只见公开数据，出口脱敏先例已有 `siteagent_scrub`）；任何需要用户授权凭据的 Agent 动作。协议观察哨 = ADR 级别的一页纸 + destinations webhook 出口，等协议收敛且有真实需求再立项——符合"高风险动作必须过审批门"的既定护栏。

**客户成功负责人（反对 → 补强）**：我的反对：上面四位都在说系统，没一个人回答"日 UV 一百的创作者第几分钟得到什么"。补强后的用户故事：**第 1 分钟**——打开 AX 体检，5 分钟出分（结构化数据齐不齐、llms.txt 新不新鲜、货架可读不可读、实体图连没连），逐项可解释；**第 5 分钟**——今日主线出现"三件可修的事"（比如"你的课程价格对机器不可读"），每件一键修；**第 1 周**——GEO 周报第一次出现"AI 引荐"一列。话术也定了：对用户不卖"协议合规"，卖"**被 AI 推荐**"。对小流量用户的诚实回答：现在花 10 分钟做的准备，同时立刻拿到 GEO 归因反馈——两头都兑现，不是纯期货。最后一条护栏：所有 agent 相关数字必须带 `visitor_kind` 角标和可切换开关，误判可一眼看出、可回退，不让用户的漏斗数字悄悄变形。

## 六、最终提案：AX 引擎（Agent Experience Engine）

### 6.1 要解决的问题

1. **失明**：AI Agent / AI 爬虫流量被当 bot 丢弃，站长的 GEO 投入没有归因闭环（GEO 报表最后一列是空的）。
2. **不可读**：商品/课程/服务对 Agent 不可读——UnifiedCatalog 只有人看的界面，llms.txt 和 MCP 工具不覆盖货架。
3. **无准备**：交易协议正在铺底层（UCP 5 个月 8,000+ 商家），OpenFlow 没有出口也没有观察机制。

### 6.2 革新方案（产品如何变化）

| 变化 | 用户看到什么 |
|---|---|
| **访客三分类** | CDP 报表与漏斗出现 human/agent/bot 分流角标，可切换、可回退 |
| **AX 体检** | 5 分钟出分的可解释评分卡（结构化数据 / llms.txt / 货架可读性 / 实体图连通），扣分项直接变今日主线待办，一键修复 |
| **机器可读货架** | UnifiedCatalog → JSON feed + llms.txt 章节 + MCP `get_catalog`/`get_offer` 工具；Agent 与 AI 爬虫都能读 |
| **Agent 引荐归因** | GEO 报表新增"AI 引荐"列：引用份额 → 引荐流量 → 引荐新客 → 转化/LTV 四层漏斗，相关性标注置信度 |
| **站点 Agent 迎宾模式** | 合法 Agent 访客被识别后，站点 Agent 用 MCP 工具直接回答目录与报价（Loop 受控循环，只读） |

### 6.3 核心交互与架构要点

- 一份代码、零新依赖：`AgentGate` + `AgentCatalog` 两个纯 PHP 类，复用既有 EventStore/UnifiedCatalog/MCP 注册表/单 IP 限流/出口脱敏。
- 不碰地基：不进身份图谱（新字段 `visitor_kind` 避开已占用的 `actor_type`）、不新增导航入口（行动走今日主线泳道）、不改存储架构。
- 护栏全部沿用既定机制：只读白名单工具、风险审批门（ADR-003 行动网关）、诚实降级、契约测试先行（新字段与新工具都进契约套件）。

### 6.4 分阶段路线图

| 阶段 | 内容 | 出口判据 |
|---|---|---|
| **一（1 周）· 看见** | `visitor_kind` 增列 + `AgentGate` 分类 + 报表分流角标；历史默认 human | 契约测试过；生产流量分类置信度分布健康（疑似占比 < 30%） |
| **二（1–2 周）· 可读** | `AgentCatalog` feed + llms.txt 章节 + MCP 两工具 | 机器校验 feed 与实体图一致；MCP 契约测试过 |
| **三（2–3 周）· 闭环** | AX 体检评分卡 → 今日主线三件事 → 一键修复；GEO 报表"AI 引荐"四层漏斗 | 体检分与修复动作全链路走通；归因相关性标注上线 |
| **四（观察哨，不定期）· 出口** | ACP/UCP/AP2 跟踪一页纸（ADR 级）+ destinations webhook 交易出口预留 | 协议收敛赢家出现 **且** 出现真实 Agent 订单需求，才立项 checkout |

### 6.5 风险与护栏

| 风险 | 护栏 |
|---|---|
| UA 伪造刷"agent 流量"指标 | 多信号 + 置信度分级；低置信只入"疑似"，不入归因；限速复用既有模式 |
| 归因硬拗因果 | 只做"相关性标注"并诚实标置信度；北极星定义为引荐新客而非成交 |
| 隐私泄露给 Agent | Agent 只见公开数据；零 PII 出口；`siteagent_scrub` 先例延伸 |
| 协议漂移追不动 | 本轮零协议实现；观察哨模式；出口留 webhook 不留承诺 |
| 统计污染用户漏斗 | `visitor_kind` 角标 + 一键切换显示 + 可回退；契约测试守口径 |
| 小流量用户觉得无关 | 第一周交付体检+修复（10 分钟见效），不交付报表 |

### 6.6 成功衡量指标

- **北极星**：Agent 引荐新客数（周）
- 过程：agent 流量占比与质量分布（置信度加权）、AX 体检分的站点均值提升、货架 feed 被 MCP/已知 AI 爬虫的调用次数
- 闭环证明：GEO 引用份额变化 ↔ 引荐流量的联动相关；引荐新客的注册→成交转化率与 30 日 LTV
- 商业：AX 作为付费档差异化卖点后的转化影响（与 pricing 校准工作衔接）

## 七、与既有路线的关系（衔接，不推翻）

- **七方向创新**：不重复、不断代。①AI 岗位制（站内 AI 替我干活）与 AX（外面的 Agent 来找我做生意）是一枚硬币的两面；⑤自优化实验循环可对 AX 修复动作做实验化；⑦匿名基准网络获得第一批天然指标（匿名化 AX 分排名）——本轮等于给排队方向 ⑦ 递了第一块砖。
- **B 路线 / 多租户**：零冲突。AX 全部能力在单租户内闭环，每租户一个 SQLite 的细胞式架构不受影响。
- **高危护栏**：交易协议只观察不实现，与 ADR-003（行动网关）、ADR-004（只读 Loop 运行时）的既定立场一致。
- **当前运营现实**：服务器 DeepSeek Key 失效期间 AI 产出链路停摆——AX 阶段一/二全部是确定性 PHP 工作，**不依赖 AI Key**，正好是 Key 恢复前的理想施工内容。
