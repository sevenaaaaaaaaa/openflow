# OpenFlow 功能缺口分析

> 本文基于对当前代码的实地核查（不是凭印象），从两个视角找缺口：
> 真实用户旅程里会绊脚的地方，以及与竞品（HubSpot、Pipedrive、有赞/微盟、
> GrowingIO/神策、Intercom、Ghost）对照下的功能差距。每一条都标了证据出处。

## 先说结论

OpenFlow 的功能广度已经非常罕见——内容、SEO/GEO、CDP、MA、CRM、电商、
课程、社区、插件生态在一个 PHP 单体里打通，很多单点能力（画像、分群、
归因、A/B 置信区间、个性化推荐、内容版本 diff、出站 webhook 签名）都做到了
竞品水准。所以缺口不在"少了哪块大功能"，而在三类地方：

1. **治理与可信度**——审计、权限、安全的深度跟不上它管的钱和数据的量级；
2. **真实旅程里的断点**——几个高频路径体验没闭环；
3. **竞品的运营提效功能**——不影响能不能用，但影响"一个人能不能扛下来"。

下面按优先级排。

---

## P0 · 该优先补的（影响可信度与安全）

### 1. 审计日志形同虚设

**现状**：全仓 `AuditLog::log()` 只有 5 处调用（其中 2 处还是本轮才加的
退款和分群导入）。这意味着——授予会员等级、安装/卸载插件、改系统设置、
删文章、改会员余额、发全站广播、导出用户数据——**全都没有留痕**。

**为什么是 P0**：这个系统管着分销佣金、作者分成、退款、会员 PII。
一旦出现"谁把这个订单退了""谁改了这条佣金""数据是谁导出的"这类问题，
现在无从追溯。对标 HubSpot / 有赞，敏感操作留痕是合规底线，不是加分项。

**建议**：不需要新框架。`AuditLog::log($action, $category, $details)` 已经有了，
把它接到本轮刚加了 CSRF 校验的那批 mutation 点即可——那些点正好是
"值得记的操作"的全集。约半天工作量，收益极高。

### 2. 没有二次验证（2FA）

**现状**：`admin/login.php` 有数学验证码 + IP 限速（5 次/15 分钟）+ bcrypt，
基线不错，但**没有 TOTP/2FA**（全仓搜 `totp/otp/2fa` 无结果）。

**为什么**：后台一个账号能退款、能装插件（=执行代码）、能导出全部用户数据。
密码一旦泄露就是全盘。竞品（HubSpot、Salesforce、有赞）后台标配 2FA。

**建议**：加一个可选的 TOTP（`otpauth://` + 6 位码），复用现有 session。
中等工作量，建议至少给 admin 角色开。

### 3. 权限只有两个硬编码角色

**现状**：`role_perms()` 里只有 `admin` 和 `marketing` 两个角色，权限清单
写死在 `admin/config.php`。没有自定义角色，也没有后台配权限的界面。

**为什么**：稍大的团队就会遇到"运营只能碰内容、财务只能看订单、
外包只能发文章"的诉求。现在要么给全量 admin（过度授权），要么改代码。
Pipedrive/HubSpot 的自定义角色是团队协作的基础。

**建议**：把权限矩阵从代码挪到 `data/roles.json`，加一个角色管理页。
中等偏大工作量，但一旦团队上量就是刚需。

## P1 · 真实旅程里的断点（影响体验）

### 4. 站内搜索是朴素子串匹配

**现状**：`lib/SearchEngine.php`（63 行）用 `mb_stripos` 在 JSON 里逐条扫，
无相关性排序、无分词、无容错、无高亮。文章一多，搜索基本不可用。

**对标**：Ghost/WordPress 都有全文索引。SQLite 自带 FTS5，改造成本不高。

**建议**：给文章/产品/课程建 FTS5 虚拟表，搜索走 `MATCH` + rank。
能顺带解决 CDP 那套查询之外的又一个"数据一多就慢"的点。

### 5. 表单没有条件逻辑

**现状**：`admin/forms.php` 的字段是平铺的，没有"选了 A 才显示 B"的跳转逻辑
（搜 `conditional/skip_logic` 无结果）。

**对标**：Typeform、HubSpot Forms、金数据都有条件显示/跳题。
对"线索资格预筛"这种核心获客场景，缺它会让长表单转化率明显偏低。

**建议**：字段结构加 `show_if` 规则，前端按规则显隐。中等工作量。

### 6. 没有在线客服 / 统一会话收件箱

**现状**：有企业微信消息（`wechat-messages`），但**没有网站上的实时聊天
挂件，也没有把表单提交、评论、私信、微信消息汇到一处的统一收件箱**。

**对标**：这是 Intercom、HubSpot Service Hub、有赞客服、微盟客服的核心。
对"官网获客 + 转化"定位的产品，访客想问一句话却找不到人，是直接的漏斗流失。

**建议**：先做轻量版——一个站内聊天挂件 + 一个后台会话列表，
消息落 SQLite，复用现有站内信。这是能明显提升转化的一块，但工作量偏大，
可作为一个独立里程碑。

### 7. 邮件营销缺调度与送达治理

**现状**：`lib/MailCampaign.php` 有退订管理（好），但没看到**定时/排队群发、
退信(bounce)处理、抑制名单(suppression)、DKIM/SPF 校验**。发送依赖
Mautic/BillionMail 外部服务，自身这层的可运营性弱。

**对标**：任何邮件营销工具都要处理软硬退信与抑制名单，否则发着发着
域名信誉就崩了。

**建议**：至少接住 bounce/投诉，维护一份抑制名单，发送前过一遍。
中等工作量，优先级取决于邮件是不是主要触达渠道。

## P2 · 竞品的运营提效功能（锦上添花）

这些不影响"能不能用"，但影响"一个人/小团队能不能高效扛下来"，
也是竞品常被拿来对比的点：

| 能力 | OpenFlow 现状 | 竞品参照 | 差距 |
|---|---|---|---|
| 线索自动分配 | 无（手动填 owner） | Pipedrive 轮询/规则分配 | 团队协作时靠人分单 |
| 销售管道自动化提醒 | 有阶段但无"X 天未跟进"提醒 | HubSpot 任务提醒 | 线索容易躺死 |
| 报表自定义 | 固定报表 + 订阅（已有） | Looker/HubSpot 自定义看板 | 想看的维度得改代码 |
| 移动端 / PWA | 无 manifest/SW | 多数 SaaS 有 App/PWA | 手机上管理体验弱 |
| 内容协作 | 有版本 diff（已有），无锁/评论 | Notion/飞书文档协作 | 多人同编会覆盖 |
| 积分兑换商城 | 有 MallSystem 基础 | 有赞积分商城 | 可继续做深 |

其中"**X 天未跟进提醒**"性价比最高：本轮 A2 已经让画布能读
`crm.days_since_followup` 字段，触发器已经具备，只差把它配成一条默认自动化。
半天就能落地，直接降低线索流失。

---

## 建议的推进顺序

1. **审计日志接线**（P0-1，半天）——接到本轮已加 CSRF 的 mutation 点，
   最小改动、最高可信度收益。
2. **X 天未跟进自动提醒**（P2，半天）——复用已就绪的画布 CRM 字段，
   立竿见影降低线索流失。
3. **搜索升级 FTS5**（P1-4，1–2 天）——解决又一个"数据一多就废"的点。
4. **2FA + 自定义角色**（P0-2/3，各 2–3 天）——团队一上量就是刚需。
5. **表单条件逻辑**（P1-5）与**在线客服/统一收件箱**（P1-6）——
   后者工作量大，建议单独立项，但对"官网获客"定位是转化杠杆最大的一块。

前两项我可以现在就做，都是半天级、复用已有能力、风险低。要不要我接着上？

## 附：本轮已确认"不是缺口"的能力

为免重复造轮子，这些经核查已具备且达标：CDP 画像/分群/生命周期、
多触点归因、A/B 的 Wald 置信区间与显著性判定、个性化推荐与排序
（`Personalizer`）、内容版本 diff（LCS）、出站 webhook 的 HMAC 签名与
入站验签、账号注销 + PII 清理（`PrivacySystem`）、定时报表订阅、
登录限速 + 验证码 + bcrypt、插件生态（SDK + 三个官方示例）。
