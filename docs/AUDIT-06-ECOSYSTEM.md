# 深度竞品对标 · 06 开发者 / 创作者生态（→ OIA：One is All）

> 坐标系见 `docs/VISION.md`。评级：🟢 达到主流 / 🟡 能用但浅 / 🔴 缺失或撞墙。
> 对标：WordPress 插件/主题生态、Shopify App Store、Substack/Ghost（创作者）、
> Gumroad/Whop（数字商品）、HuggingFace / GPT Store（AI 资产）。

## 一句话结论

现有的一切生态，都是**分开设墙**的三个世界，而每道墙都把「参与」挡在了
「生产/营销」之外：

- **开发者生态 · 门槛太高**：要懂代码、懂 API、懂发布规范（WordPress 插件、
  Shopify App）。绝大多数有想法的人**跨不过写代码这道墙**。
- **创作者生态 · 太重**：要持续产出、要运营、要涨粉（Substack/YouTube）——
  「创作者」是一份全职负担，不是「参与」。
- **作者/知识生态 · 太高端、离生产和营销太远**：署名、专栏、出版那一套，
  高冷、慢、且作者只管写，**离「把它变成能卖的东西、能被人用到的东西」隔着十万八千里**。

**OpenFlow 的破壁点 = OIA（One is All）**：**只要你参与，你就同时是开发者、
是创作者、是作者——一次加入，全平台赋能。** 你写一篇内容，它同时可以是知识、
是能被 Agent 调用的技能、是能上架卖的商品；你有个想法，AI 帮你把它变成插件；
你做的任何东西，平台的增长大脑自动帮你分发、营销、变现。**不分身份、不设三道闸、
不让「参与」和「生产/营销」之间隔着墙。**

**诚实说现状**：破壁的**筹码已经埋好，但墙还立着**。代码里 AI 已经能从一句话
生成 skill 和 plugin（`SkillGenerator`，这是把「开发」降到「描述」的钥匙）；
但身份上仍是**三道独立的闸**——`admin/developers.php` 是单独的「开发者入驻审核」
（member 要单独申请 `developer_status` 走审核）、作者是另一套 `AuthorSystem`、
skill/主题上架又走生态市场审核。**筹码是 OIA 的，架构还是「三个世界」的。**
这份审计要说清：怎么用已有筹码，把三道墙拆成一扇门。

---

## 定位裁剪刀（承接 VISION）

不卷 WordPress 生态的规模、不卷 Shopify App Store 的审核工业化、不卷 GPT Store
的模型能力。我们卷的是唯一一件别人结构上做不到的事：**把「开发者/创作者/作者」
三种高墙身份，坍缩成一个零门槛的「参与者」——参与即被全平台赋能。**
凡「为某一种身份单独建一套生态/审核/工具」的先怀疑；凡「拆墙、让一次参与
同时获得三种身份的能力与回报」的才是主战场。

## 逐能力对标（先诚实评现状）

### 1. 开发者接入：从「写代码」到「描述需求」— 🟢 有真突破（AI codegen）

**我们的实现**：`PluginSystem`（do_action/apply_filters 钩子引擎）+ `PluginSDK`
（`PluginContext`：on/filter/config/menu/httpPost/renderSettings，把插件开发收成
一套干净 API）；更关键的是 `SkillGenerator`——`skill_generate` / `skill_generate_plugin`
**用 AI 从一句自然语言描述，直接生成 skill / plugin 的结构与内容**。

**判断**：这是**真突破，也是 OIA 的技术地基**。WordPress/Shopify 的开发者墙
是「你得会写代码」；我们用 AI 把这道墙降到「你会描述需求」。**这意味着
『创作者』天然就能是『开发者』——不需要另一批人、另一种技能。** 这条别人
（在位生态）结构上补不上，因为他们的生态是围绕「专业开发者 + 审核」建的。

**竞品标杆**：WordPress（插件 API + 文档，面向程序员）、GPT Store（配置 GPT，
但只能配不能生成可执行逻辑）。

**差距（诚实）**：(a) 生成质量/安全需护栏（现在直出 JSON，缺沙箱/校验/版本）；
(b) 无插件依赖/版本/兼容性管理；(c) 无开发者文档门户/API 说明站。
但方向对——**把「开发」降到「描述」，是攻，是差异化的核心。**

### 2. 贡献物即资产：技能/插件/主题/内容 — 🟢 底子好，但各是各的

**我们的实现**：`SkillSystem`（skill 有 prompt/tool/workflow 三型，可 publish/
execute/rate/install，**技能是可执行的**）、`ThemeSystem`（预设 + 自定义主题）、
`PluginSystem`（插件）、内容（文章/知识）。

**判断**：**「你做的东西是活的资产」这件事，底子很好**——技能能被执行、被评分、
被安装，不是躺着的文件。但**四类资产各走各的系统、各有各的后台**
（`plugins.php`/`themes.php`/`marketplace.php`/内容后台），**没有一个统一的
「我贡献的一切」视图**。一个参与者做了一篇内容 + 一个技能 + 一个主题，
他看不到「我的贡献」是一个整体。

**竞品标杆**：HuggingFace（模型/数据集/Space 统一在个人主页下）。

**差距**：缺统一的「创作者/开发者主页」把一个人的所有贡献物聚合。

### 3. 上架 / 审核 / 分发 — 🟡 能上，但审核是人肉、分发靠列表

**我们的实现**：`MarketplaceSystem` 聚合浏览（mkt_categories/assets/search/stats）、
`developers.php` 审核开发者、skill/主题走「生态市场待审核」。

**判断**：**上架链路通了**（提交→审核→上架→浏览），但审核是**纯人肉**、
分发是**固定列表 + 热度排序**——没有质量把关的智能、没有为每个贡献物找到
对的用户的分发（这一条正是 AUDIT-05 平台级 AI 分发要解决的，两块是同一件事）。

**竞品标杆**：Shopify App Store（审核工业化 + 榜单 + 编辑推荐）。

**差距**：审核与分发都还是「前 Agent 时代」的人肉/规则——见创新层与 AUDIT-05。

### 4. 身份：会员 / 开发者 / 作者三道闸 — 🔴 这就是那三堵墙

**我们的实现**：普通会员（`MemberSystem`）→ 要当开发者得申请 `developer_status`
走 `developers.php` 审核 → 作者是另一套 `AuthorSystem` 身份 → 上架商品又是
另一层。**三种身份、三套数据、三道闸。**

**判断**：**这正是你点破的「壁垒」在代码里的样子。** 一个人想「既写点东西、
又做个小工具、还上架卖」，现在要跨三道门、被三次审核、在三个后台之间穿梭。
**架构层面把「参与」拆成了三种高墙职业**——这与 OIA 完全相反。

**竞品标杆**：所有在位生态都这样分（Substack 只管创作者、WordPress.org 只管
开发者、Gumroad 只管卖家）——**没有谁把三者合一，这正是我们的空位。**

**建议**：见创新层——**一个身份、一次加入、三种能力全给**。

### 5. MCP / 知识底座：贡献物可被 AI 调用 — 🟢 独有，且是复利引擎

**我们的实现**：`mcp-server.php` 把站点能力暴露成 MCP 工具（articles/members/
leads/orders/search/sentiment/**skills_list/skill_execute**）；`KnowledgeSystem`
知识库带语义检索 + 向量嵌入。**别人贡献的技能，能通过 MCP 被外部 Agent 直接调用；
别人写的内容，进知识库喂 Agent。**

**判断**：**这是别人完全没有的一层**，也是 OIA 最深的价值——**你的每一次贡献，
不只是躺在货架上，而是变成整个系统（和外部 Agent）能调用的能力/知识，
贡献之间还会互相复用。** 贡献即复利，不是贡献即库存。

**竞品标杆**：GPT Store（能被 ChatGPT 调，但封闭在一家）、
HuggingFace（资产可下载，但不是「即刻成为你站点 Agent 的能力」）。

**差距**：现在 MCP 暴露的是**平台级**能力；还没做到「每个参与者的贡献自动
成为可被调用的能力单元 + 自动进他自己那份增长闭环」。见创新层。

## 创新层：OIA —— 一次参与，同时是开发者/创作者/作者，全平台赋能

> 前五个模块把「增长大脑」建起来、下放到平台上每个创作者（AUDIT-05）。
> 生态这块是最后一块拼图：**把「谁能参与、以什么身份参与」这道门也拆了**——
> 让参与本身零门槛，让一次贡献同时获得三种身份的能力与回报。

### 洞察：三种生态的墙，本质是「分工时代」的遗产

开发者/创作者/作者之所以是三个世界，是因为**过去它们需要三种不同的专业能力**：
写代码、做内容运营、做知识生产。分工必然设墙。**但 AI 把这三种能力的门槛
同时踏平了**——AI 能把「描述」变成「代码」（`SkillGenerator` 已经在做）、
能把「想法」变成「内容」、能把「内容」变成「可调用的知识/技能」。
**当生产门槛塌了，分工的墙就没有存在理由了。** OIA 不是一句口号，
是「AI 抹平生产门槛」这个事实的必然产物——**谁先拆墙，谁就拿到零门槛参与的生态。**

### 创新一：一个身份 —— 参与即三位一体（拆掉三道闸）

**做什么**：取消「会员→申请开发者→作者」的三套割裂身份，合成一个
**「参与者（Builder）」**身份。你一加入，就**同时**拥有：写内容（作者）、
做技能/插件/主题（开发者）、上架变现（创作者/卖家）的全部能力和入口——
**不再申请、不再三次审核、不再三个后台。** 一个统一的「我的工作台」，
一个统一的「我的贡献」主页。

**为什么在位者做不到**：Substack/WordPress/Gumroad 的产品边界就是单一身份，
合并意味着重做整个产品。我们是围绕一个统一系统新建的，**三种能力本就在同一个
后台里**（内容 + SkillGenerator + Commerce），合并是拆墙，不是重造。

**第一步**：把 `developer_status` 审核闸去掉/降级为「安全护栏审核」（审代码安全，
不审「你配不配当开发者」），三个后台入口收进一个「参与者工作台」。

### 创新二：把「开发」降到「描述」—— 人人都是开发者（放大已有筹码）

**做什么**：把 `SkillGenerator` 从一个后台功能，升级为**每个参与者的默认能力**：
「描述你想要的工具 → AI 生成 skill/plugin → 沙箱试跑 → 一键发布」。
配上生成物的**安全护栏**（沙箱执行、权限声明、AI 预审），让「不会写代码的人
也能贡献可执行的能力」成为常态。

**为什么这是攻**：这是 OIA 技术上成立的关键——**如果开发还需要写代码，
『创作者=开发者』就是空话。** 只有当 AI 把开发降到描述，一个只会写内容的人
才可能顺手做出一个技能。**这把「开发者生态门槛太高」这堵墙，从根上拆了。**

**第一步**：参与者工作台里放一个「描述即造」入口（复用 `skill_generate` /
`skill_generate_plugin`），加沙箱 + 权限声明 + AI 安全预审三道护栏。

### 创新三：一次贡献，全平台赋能 —— 拆掉「作者离营销太远」的墙

**做什么**：你做的任何东西（内容/技能/插件/主题/商品），**自动接进整套增长大脑**——
自动进知识库喂 Agent（知识）、自动暴露为 MCP 可调用能力（开发者价值）、
自动被平台的 CDP/MA 分发给对的人、自动获得 AUDIT-05 说的「每个创作者的
AI 增长团队」（选题/定价/复购/千人千面分发）。**参与者只管做，营销/分发/变现
由平台的增长大脑替他跑完。**

**为什么在位者做不到**：Substack 的作者写完还得自己涨粉、WordPress 的开发者
上架完还得自己推广——**在位生态只提供「货架」，不提供「增长」。** 而我们
整套系统就是增长引擎（前五个模块），把贡献物接进去是自然延伸。**这一条
直接拆掉「作者/创作者离生产、营销太远」那堵墙——参与和被赋能之间，不再有距离。**

**第一步**：贡献发布时默认三个开关全开——「进知识库 / 暴露为 MCP 能力 /
纳入平台 AI 分发」，参与者可关不可缺。

### 创新四：贡献即复利 —— 生态自我增强的飞轮

**做什么**：因为每个贡献物都进了知识库 + MCP + 增长大脑，**贡献之间会互相复用、
互相增强**：A 做的技能被 B 的插件调用、C 写的内容成为 D 的 Agent 答案的来源、
平台的 Agent 用大家的贡献变得更聪明，又反过来帮每个参与者卖得更好。
配合已有的 `GrowthFlywheel`/`GrowthEngine`，让生态形成**越多人参与、
每个人被赋能越强**的正反馈。

**为什么这是终局**：在位生态是「货架越长，单个创作者越淹没」（负外部性）；
OIA 生态是「参与者越多，公共知识/能力池越厚，每个人的 Agent 越强」（正外部性）。
**这是把网络效应从『平台受益』改写成『每个参与者受益』——这才是拆墙之后
真正的护城河。**

## 我们能做什么 · 按可行性排

**现成筹码、近可落地：**
1. **参与者工作台 v1**（创新一）：三个割裂入口（内容/技能/商品）收进一个统一
   工作台 + 一个「我的贡献」主页；`developer_status` 审核降级为安全护栏。**攻，P1**。
2. **「描述即造」+ 护栏**（创新二）：把 `SkillGenerator` 提到工作台首位，
   加沙箱执行 + 权限声明 + AI 安全预审。**攻，P1**——OIA 的技术命门。
3. **贡献自动三通**（创新三第一步）：发布时默认接入 知识库 / MCP / 平台分发。
   `KnowledgeSystem` + `mcp-server` + CDP/MA 全现成。**攻，P1**。

**要更多投入：**
4. 生成物安全体系（沙箱、权限模型、AI 审核 + 人工关口）——OIA 规模化的前提。**P1–P2**。
5. 贡献复利飞轮（创新四）：贡献互调 + 公共能力池 + `GrowthFlywheel` 联动。**P2**。
6. 版本/依赖/兼容管理、开发者文档门户（守，规模化后必要）。**P2**。

## 小结

- **三堵墙**：开发者（门槛太高）、创作者（太重）、作者（太高端、离生产营销太远）——
  在位生态分开设墙，把「参与」挡在「生产/营销」之外。代码里现状也确实是三道闸
  （`developers.php` 审核 + `AuthorSystem` + 市场审核）。
- **OIA = One is All**：一个身份、一次加入、三种能力全给，全平台赋能。
  不是口号，是「AI 抹平生产门槛」的必然产物——**谁先拆墙，谁拿到零门槛生态。**
- **四拆**：① 合三身份为一个「参与者」；② 把开发降到描述（`SkillGenerator`
  已有雏形，人人是开发者）；③ 一次贡献全平台赋能（接进增长大脑，拆掉离营销太远
  的墙）；④ 贡献即复利（越多人参与，每个人被赋能越强的正反馈飞轮）。
- **筹码已埋、墙还立着**：破壁的钥匙（AI codegen + MCP/知识底座 + 增长引擎）
  都在，缺的是把「三个世界」的架构合成「一扇门」。
- **收束到全系列**：内容（生成）× CDP（上下文）× MA（决策）× Sales（成交）×
  电商（把增长大脑下放给每个创作者）× 生态（拆掉参与的门槛，让人人零门槛进来、
  一次贡献全平台赋能）——**同一个增长大脑，先服务一个人，再下放给一群人，
  最后向所有人零门槛敞开。** 至此六个模块指向同一个终局：
  **一台懂每个人、会判断、会行动、能下放、且越多人用越强的增长引擎。**
