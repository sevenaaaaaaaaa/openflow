# 安装完成后的第一小时

> 前提：已完成 `/setup-wizard.php`（环境检查 → 站点设置 → 管理员）。这一步的目标不是"能打开"，而是"能放心用"。

## 1. 上线体检（8 项，逐项打勾）

| 项 | 怎么验 | 不通过的样子 |
|---|---|---|
| 站点地址 | 后台设置里的站点地址与实际访问域名一致 | 分享链接指向 localhost |
| HTTPS | 外网用 https 打开，无混合内容警告 | 浏览器提示不安全 |
| 后台登录 | `/xmp/login` 能进，能打开内容列表 | 登录后白屏或 500 |
| 数据可写 | 后台保存一次设置，刷新后仍是新值 | "保存成功"但值没变 |
| 定时任务 | cron 每分钟请求 `/api/cron.php`，日志有记录 | 队列一直等待 |
| 发信 | 发一封测试邮件，能收到且不进垃圾箱 | 收不到或进垃圾箱 |
| 静态资产 | 页面样式正常，Network 里版本号与当前一致 | 旧样式、错位 |
| 备份 | 打包 data 与 uploads，能解开 | 备份文件 0 字节或解压失败 |

八项全过再继续；有红项先按[故障排查](troubleshooting.md)处理。

## 2. 前三个动作

1. **发一条内容**：后台新建 → 发布 → 前台能看到。目的：跑通写路径与前台渲染。
2. **收一条留资**：建一个表单或留资入口，自己提交一次，后台能看到记录。目的：跑通线索落盘。
3. **开一条自动化**：建一条定时/触发任务，等它跑一轮。目的：确认 cron 与队列真的在转。

做完这三个动作，系统的最小闭环（内容 → 触达 → 线索）就通了。

## 3. 第一周

- 每天看一眼错误日志 `data/php-error.log`。
- 把备份复制到另一台机器或对象存储（同盘备份等于没有备份）。
- 记录当前版本号；升级前先按[升级与回滚](upgrade-rollback.md)备份。

## 4. 遇到问题

先查[故障排查 Top 10](troubleshooting.md)。仍解决不了时，提问带三样：
①现象与复现步骤 ②错误日志相关片段 ③版本号与部署形态。缺这三样，排障只能靠猜。
