# 故障排查 Top 10

> 用法：先按"现象"定位，再按"自查顺序"一条条排除；每条都给了判断依据，不要跳步。
> 排查前先看 `data/php-error.log`（没有就说明请求没到 PHP 或目录不可写）。

## 1. 全站 404 / 除首页外都打不开

原因：URL 重写没生效。
自查：Apache 确认 `AllowOverride All` 且 `mod_rewrite` 已开；Nginx 确认用了 `deploy/nginx.site.conf` 的 `try_files` 规则；确认站点根指向仓库根，而不是它的子目录。

## 2. 500 Internal Server Error

原因：PHP 版本过低、扩展缺失或文件权限不对。
自查：`php -v` 是否 8.1+；扩展 pdo_sqlite/sqlite3/gd/mbstring/curl/openssl 是否在；`data/` 与 `uploads/` 是否 Web 用户可写；最后看 `data/php-error.log` 的异常栈。

## 3. 后台登录不进去

原因：安装没完成、会话写不进去、或密码错误。
自查：先访问 `/setup-wizard.php` 看是否仍提示未安装；再确认 `data/` 可写（session 与用户表都在这里）；最后用安装时设的账号重试。

## 4. 后台保存"成功"但数据没变

原因：`data/` 属主不对，PHP 写不进去（最典型的静默失败）。
自查：看 `data/*.json` 的属主是不是 Web 用户；用 `ls -l data` 对照；修正后重新保存一次并回读。

## 5. 改了样式/脚本，浏览器还是旧的

原因：版本号没变 + CDN/浏览器缓存。
自查：确认页面引用的版本号已更新；确认静态资源同步（CDN 场景）与缓存已刷新；用无痕窗口复核。

## 6. 表单提交了但收不到

原因：邮件通道没配好，或落盘目录不可写。
自查：看后台表单/线索是否有记录（落盘兜底）；再看邮件配置与发信日志；确认 `data/` 可写。

## 7. 定时任务不跑

原因：cron 没装、URL 错、或被防火墙拦。
自查：`crontab -l` 是否有每分钟请求 `/api/cron.php` 的条目；手动 `curl` 一次看返回；看站点日志是否收到请求。

## 8. 图片/上传文件不显示

原因：`uploads/` 权限、路径大小写、或 CDN 未同步。
自查：直接访问文件 URL 看是否 404/403；检查 `uploads/` 属主与权限；CDN 场景确认已同步。

## 9. 邮件进垃圾箱

原因：发信域名的 SPF/DKIM/DMARC 不完整。
自查：按邮件服务商文档检查 SPF、DKIM、DMARC；注意这与网站域名的 A 记录无关，不要给发信域名加 A 记录。

## 10. 升级后白屏或报错

原因：新旧版本不兼容、缓存未清、或数据被覆盖。
自查：先看 `data/php-error.log`；再按[升级与回滚](upgrade-rollback.md)退回上一版；确认升级过程没有覆盖 `data/` 与 `uploads/`。

## 还是解决不了

带三样东西提问：①现象与复现步骤 ②`data/php-error.log` 相关片段 ③版本号与部署形态。没有这三样，排障会变成猜。
