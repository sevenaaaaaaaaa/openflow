# 配置真源地图（CONFIG-SOURCES）

> 目的：任何一个人（或 AI 会话）要改配置时，先在这里查到"权威位置、读取方、缺失行为、影响面、怎么核对"。
> 规则：本文只写**位置与语义**，不写具体值；真实值只在两类地方——本机 `.env`（gitignored）或系统钥匙串。
> 维护：新增/迁移一个配置项时，必须同时更新本文与 `docs/ENV-MATRIX.md`。

---

## 1. 四层地图

| 层 | 权威位置 | 读取方 | 缺失行为 | 变更影响面 | 核对手段 |
|---|---|---|---|---|---|
| L1 入口与部署器 | `scripts/deploy.py`、`deploy/sync.sh`、`deploy/*.py` | 开发者本机；CI 只读 | 部署目标缺失 → **直接报错退出**（不回落默认主机） | 所有部署动作；发布流水线 | `--dry-run` 全量 + 只读探测 |
| L2 运行时 | `admin/config.php`（真实环境变量 → 仓库根 `.env` → 代码默认） | 所有 PHP 页面与 API | 目录回落项目根下 `data` / `uploads`；站点地址回落请求 Host | 全站读写、缓存、上传、多租户 | 起服务 + 安装向导 + 关键页 smoke |
| L3 凭据与第三方 | 本机 `.env`、系统钥匙串（服务名见部署文档）、`data/cloudflare.json`（历史回退） | 部署器、R2 同步、CF purge、离线备份 | 缺 R2/purge 凭据 → 部署以**退出码 3**失败 | CDN 一致性、备份可用性 | 只读自检：只输出已配置/未配置/通过/失败 |
| L4 服务器侧 | NAS 上的 vhost / 反代 / cron / systemd / 属主（**不在仓库**） | 服务器自身 | 缺 cron → 定时发布、队列、AI 岗位、备份不转 | 线上行为，且改动无版本记录 | 登录机器只读核对 + 一轮任务执行记录 |

## 2. 单一真源规则

| 配置类别 | 唯一真源 | 其余位置只能 |
|---|---|---|
| 部署目标（主机/用户/端口/站根/ops 根） | 本机 `.env`（`OF_DEPLOY_*`） | 引用变量名；**不得写默认值** |
| 凭据（R2 / CF / 离线备份） | 本机 `.env` 或钥匙串 | 引用变量名 + 获取步骤 |
| 站点地址 | 后台"站点配置"写入的 `data/settings.json`（`SITE_URL` 可覆盖） | 文档写"部署后在后台填" |
| 数据/上传目录 | `OF_DATA_DIR` / `OF_UPLOAD_DIR`（缺省为项目根下同名目录） | 文档写相对语义 |
| 运行时环境 | `OF_ENV`（缺省按 Host 是否 localhost 判定） | 文档只解释判定规则 |
| 多租户 | `OF_MULTI_TENANT` + 两个 tenant 根 | 文档写"默认关闭" |

## 3. 逐层清单

### L1 部署器
- `scripts/deploy.py`：目标常量、`.env` 解析、钥匙串回退、部署白名单、属主/权限、R2 与 purge 串联、`--init-env` 引导。
- `deploy/sync.sh`：`.env` 加载（`set -a`）、gitleaks 闸门、commit/push、调用部署器、`ops/` 单独同步（走 `OF_DEPLOY_OPS_ROOT`）。
- `deploy/*.py`：R2 Worker 部署、视频上传、资产同步——账号与桶一律来自环境变量/`.env`。
- `sync-decks.sh`：退役主机的遗留脚本，改为必须由 `OF_LEGACY_*` 提供目标，否则拒绝运行。

### L2 运行时
- `admin/config.php`：错误级别、session、时区、路径常量、多租户切目录。
- `data/settings.json`：站点名/站点地址/安装标记（安装向导写入）。
- `setup-wizard.php`：环境检查 → 站点设置 → 管理员创建。

### L3 凭据
- `.env`：gitignored；模板 `.env.example` 只放占位符。
- 钥匙串：macOS 兜底通道，服务名与条目名见部署文档。
- `data/cloudflare.json`：历史本地凭据，仅作 purge 回退；新配置不要再写这里。

### L4 服务器侧
- vhost/反代、`cron.d`、systemd、容器挂载与属主；改动必须同步写进 `docs/RUNBOOK-NAS.md`（待建）。

## 4. 核对手段（三条交叉）

1. **静态扫描**：退役主机、旧目录、旧端口、旧面板路径、隐私模式各一条检索式；改动后重跑，命中应为 0（守卫 `scripts/check-public-surface.sh`，CI 已接入）。
2. **运行时自检**：`deploy.py --dry-run` 全量 + 目标机只读探测（目录、属主、端口），输出"计划 vs 实际"。
3. **文档回放**：让没做过的人严格照文档操作，只记录"卡在哪、文档怎么写、实际是什么"，不现场答疑。

## 5. "过时"判定标准

满足任一即判过时：指向已退役主机/端口/面板；指向不存在的本地目录；引用的变量名已不在代码中；步骤产物与当前架构不符；出现内部地址、账号 ID、本机路径等不应公开的信息。

## 6. 变更影响面自查（每批改动前填）

| 维度 | 自查问题 | 验证 |
|---|---|---|
| 页面 | 哪些前台页会读被改的配置 | 关键页 200 + 标题抽查 |
| 接口 | 哪些 API 依赖它 | 一次只读 + 一次写入 |
| 后台 | 保存/上传/设置是否仍生效 | 真改一次并回读 |
| 定时任务 | cron/队列是否仍能跑 | 看一轮执行记录 |
| 兄弟产品 | 共享 vhost/别名/插件是否受影响 | 各别名入口 200 |
| 公开仓库 | 新内容是否含隐私/内部拓扑 | 守卫脚本重跑 |

## 7. 已知漂移（待收敛）

- `.env` 有两份解析实现（PHP 与 Python），语法边界与优先级需对齐成一份规范。
- 属主/权限相关默认值仍在 `deploy.py` 内（按目标机而定），文档未说明何时需要覆盖。
- `data/cloudflare.json` 作为 purge 回退来源，与".env 单一真源"存在重叠。
- 服务器侧配置（L4）仍无版本记录。
