## 一、经营驾驶舱：一个人怎么看全局？

### 理论基础：**经营的五维决策模型**

一人公司的经营决策，归根结底在回答五个问题：

```
┌──────────────────────────────────────────────────────┐
│  全局维度 → 我的生意整体健康吗？（一眼看出健康度）    │
│  渠道维度 → 哪个渠道在贡献最多/最少？（资源分配依据）│
│  用户维度 → 我的用户是谁、在哪个阶段？（用户战略）   │
│  产品维度 → 哪个产品/服务最赚钱？（定价/砍产品决策）│
│  预警维度 → 哪里要出问题了？（提前干预）            │
└──────────────────────────────────────────────────────┘
```

**驾驶舱 = 这五个维度的实时仪表盘**

每个维度包含：
- **核心指标**：1-2 个必看数字（不要超过 5 个，否则人不看）
- **趋势信号**：同比/环比涨跌（告诉你方向，而非绝对值）
- **下钻入口**：点进去能看明细（不要在仪表盘里堆明细）

#### 经营驾驶舱面板设计（理论框架）

```
┌─────────────────────────────────────────────────────────────┐
│                    经营健康度（五维雷达图）                   │
│         获客效率 · 转化效率 · 用户留存 · 产品贡献 · 利润   │
├──────────┬──────────┬──────────┬──────────┬─────────────────┤
│ 全局KPI  │ 渠道归因 │ 用户分群 │ 产品贡献 │    预警中心    │
│ ·今日营收│ ·自然流量│ ·新用户  │ ·热销商品│ ·退款率异常    │
│ ·今日利润│ ·社媒    │ ·活跃用户│ ·滞销商品│ ·转化率下降    │
│ ·MOU    │ ·SEO/SEM │ ·付费用户│ ·课程完课│ ·渠道流量骤降  │
│ ·NPS    │ ·直接    │ ·流失用户│ ·咨询转化│ ·库存/额度告急 │
└──────────┴──────────┴──────────┴──────────┴─────────────────┘
```

## 二、CDP：用户数据怎么用才有价值？

### 理论基础：**用户生命周期 × 数据三层次**

#### 用户生命周期四阶段

```
访客 → 注册用户 → 活跃用户 → 付费用户
       (首次识别)  (持续使用)  (产生价值)
         ↓           ↓          ↓
      ID Mapping   用户分群    用户画像
```

#### ID Mapping（身份合并）

**理论**：同一用户在不同触点（网页、APP、小程序、客服、邮件）产生不同 ID，必须合并为同一用户。OpenFlow 的 ID 策略：

```
第一方 ID：cookie（匿名）→ session → 登录后绑定 member_id
事件级 ID：每次埋点的 uid → 自动合并到 member_id
归因 ID：推荐码/UTM → 绑定来源渠道
```

#### 用户分群（Segmentation）

**理论**：分群的目的不是"分类"，而是**差异化运营**。每个分群应该对应一个可执行的运营动作。

```
行为分群：最近活跃 / 休眠 / 流失风险 / 高价值
价值分群：潜在客户 / 试用用户 / 付费用户 / VIP
阶段分群：新手期 / 成长期 / 成熟期 / 衰退期
```

#### 用户画像（Profiling）

**三维画像模型**：
- **人口统计**（who）：姓名、公司、职位、来源
- **行为特征**（how）：活跃度、偏好内容、消费习惯、互动频率
- **价值评估**（worth）：RFM 评分、CLV 预测、推荐意愿

## 三、营销自动化：触点怎么规划？

### 理论基础：**触点生命周期 × 触发条件 × 执行动作**

#### 触点类型分类

```
按用户阶段分：
  认知触点：首页访问、文章阅读、社媒互动
  考虑触点：下载资料、看案例、读定价页
  决策触点：注册、加入购物车、提交表单
  使用触点：登录、功能使用、帮助文档
  留存触点：续费、推荐、反馈

按渠道分：
  站内：页面事件、按钮点击、表单提交
  邮件：打开、点击、退订
  短信：送达、回复
  社媒：互动、分享
```

#### 触点属性定义

```json
{
  "id": "page_view_about",
  "type": "认知触点",
  "channel": "站内",
  "event": "page_view",
  "condition": {"page": "/about"},
  "weight": 1,
  "decay_hours": 72
}
```

#### 预制工作流模板（6 个核心场景）

1. **新用户欢迎序列**：注册 → 欢迎邮件 → 引导读入门课 → 首次登录提醒
2. **弃购挽回**：加购未付 → 1h提醒 → 24h优惠 → 3天最终提醒
3. **流失召回**：30天未登录 → 优惠券 → 7天未用 → 人工跟进
4. **付费用户升级**：基础版使用30天 → 看高级功能 → 试用提示
5. **推荐人激励**：推荐码使用 → 被推荐人注册 → 推荐人通知 → 佣金到账
6. **续费提醒**：到期前7天 → 3天 → 1天 → 过期 → 宽限期通知

## 四、用户洞察：该看什么报表？

### 理论基础：**经营者视角的三个认知层次**

```
第一层：发生了什么（描述性分析）
  - 今日/本周/本月 KPI 概览
  - 用户增长趋势
  - 营收趋势
  - 渠道归因

第二层：为什么会这样（诊断性分析）
  - 转化率下降的根因分析（哪个环节漏了）
  - 用户流失画像（谁在流失、为什么）
  - 产品/课程的投入产出比

第三层：接下来该做什么（决策性分析）
  - 哪个渠道值得追加投入
  - 哪个用户群该推升级
  - 哪个产品该砍掉或优化
  - 定价调整建议
```

#### 预制报表清单（10 种核心报表）

| 类型 | 报表名 | 回答什么问题 |
|---|---|---|
| 全局 | 日/周/月 KPI 仪表盘 | "生意整体怎么样" |
| 全局 | 经营健康度雷达 | "五维哪个最弱" |
| 渠道 | 渠道 ROI 矩阵 | "哪个渠道最赚钱" |
| 渠道 | 自然搜索排名变化 | "SEO 做得怎么样" |
| 用户 | RFM 分层报表 | "谁是高价值用户" |
| 用户 | 用户旅程转化漏斗 | "哪里在漏人" |
| 用户 | 流失用户画像 | "谁在流失、为什么" |
| 产品 | 产品/课程营收贡献 | "哪个产品最赚钱" |
| 产品 | 内容 ROI（阅读→转化） | "哪篇文章带来付费" |
| 预警 | 异常告警日报 | "今天有没有异常" |

## 五、功能组合方案

### 理论基础：**场景 × 规模 × 预算 = 功能集**

| 方案名 | 目标用户 | 启用模块 | 禁用模块 | 性能优化 |
|---|---|---|---|---|
| **个人版** | 一人公司、超级个体 | CMS + SEO + CDP基础 + MA基础 + 电商 | 高级CDP、企业级CRM、实时分析 | 关闭事件字典、简化画像 |

## 六、增长规则引擎：怎么做到实用？

### 理论基础：**增长规则 = 触发条件 × 建议动作 × 执行方式**

现有问题：信号收集→形态分析→泛化建议，链条太长且建议空泛。

**改造方向**：直接绑到真实业务事件，给出可执行的建议。

```
规则 = WHEN（何时触发）× WHAT（建议什么）× HOW（怎么执行）

示例规则：
WHEN 流失用户 > 100 且无召回流程
  → WHAT：建议创建流失召回流程
  → HOW：一键导入预制模板，派生到自动化

WHEN 某文章浏览量 > 1000 但转化率 < 1%
  → WHAT：该文章缺少转化钩子
  → HOW：建议在文章末尾插入相关产品卡片

WHEN 推荐码使用率 > 10% 但佣金转化率 < 5%
  → WHAT：推荐码有流量但没转化
  → HOW：检查被推荐人注册→付费路径是否有断点
```
