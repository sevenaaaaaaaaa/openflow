# 深度竞品对标 · 03 营销自动化 / 个性化

> 坐标系见 `docs/VISION.md`。评级：🟢 达到主流 / 🟡 能用但浅 / 🔴 缺失或撞墙。
> 对标：HubSpot Workflows、Braze（Canvas / Journeys）、神策智能运营、n8n。

## 一句话结论（先把靶子换对）

**营销自动化本身不是核心，个性化才是。** 这不是措辞问题，是范式问题：
- 自动化（画布/流程）只解决**转化效率**——把人工的重复触达自动跑起来；
  它不解决增长的根，因为它对一千个人做的还是同一套（或几套）预设动作。
- **真正提升销售转化率的是个性化**——千人千面地对的人、在对的时刻、说对的话、
  给对的东西。而个性化过去始终没做透，卡在两点：**策略依赖人的经验**，
  **画布要一个节点一个节点配、门槛极高**。
- 这两点，恰恰是**人一定不如 Agent** 的地方：千人千面的策略与决策，人配不过来、
  也没那么多经验；Agent 可以。**所以个性化对 AI 的需求最高——这才是"AI Agent
  时代原生系统"的真正含义**：不是给老范式加个 AI 按钮，是让 Agent 取代
  "人预先连好每个决策"的画布。

我们现有的 MA（基础画布 + 触发-动作 + 规则式个性化）是**老范式里的一个轻量实现**——
和 HubSpot/Braze/n8n 同一个品类，只是更轻。诚实地讲它不该被"做得更全"，
而该被**跃迁**：从"人连流程图"进化到"Agent 千人千面地决策"。而这一跃，
正好把内容、CDP、Sales 三个模块的创新收束成同一个东西——**一个增长大脑**。

---

## 定位裁剪刀（承接 VISION）

别去卷 HubSpot/n8n 的节点丰富度与流程复杂度——那是"给有营销团队的人配复杂
自动化"的赛道，我们打不过也不该打。我们卷的是：**一个没有营销团队的人，
洞察出来后，几分钟把个性化策略落地**。凡"让画布更强大"的建议先怀疑；
凡"让 Agent 替人决策、缩短落地"的才是主战场。

---

## 逐能力对标（先诚实评现状）

### 1. 可视化画布（Canvas）— 🟡 是真画布，但动作贫、门槛在

**我们的实现**：`CanvasSystem` 有 nodes（触发/动作/条件/延时/通知）+ edges
（条件分支），支持顺序/分支/并行；条件节点能**实时读 CRM 字段**（stage/score/
owner/value/days_since_followup 等，上轮 A2 做的），比较算子齐（eq/gte/in/…）。

**判断**：结构是真的（分支 + 延时 + 实时条件），但**动作类型很贫**——基本只有
send_email / notify / delay / condition。没有"打分/打标/改阶段/加券/推送/
webhook/等待事件/A/B 分流"等常见动作。而且它仍是**要人连线配节点**的东西——
门槛问题一点没解决。

**竞品标杆**：HubSpot Workflows（几十种动作 + 分支 + 等待）、Braze Canvas
（旅程编排 + 频控 + 多渠道 + 实验）、n8n（几百集成节点）。

**差距**：动作维度浅；且**范式上就是"人配流程"**，见下文——这才是根本。

### 2. 触发-动作自动化（Automation）— 🟢 触发面广

**我们的实现**：`AutomationSystem` 触发类型广——form_submit / page_view /
purchase / course_* / segment_enter / segment_exit / role_selected / tool_use …；
`FlowSystem` 是全局事件总线（flow_handle）。三件套（Canvas/Automation/Flow）
分工清楚。

**判断**：触发覆盖到位（尤其 segment_enter/exit 接了 CDP 实时分群，这条链是通的）。
这块的"接线"其实是我们的强项——事件-触发-下游都打通了。

**竞品标杆**：HubSpot/Braze 的触发同级；n8n 更偏系统集成触发。

**差距**：动作端和"决策端"薄——触发到了，之后做什么还是预设的固定动作。

### 3. 个性化 / 推荐（Personalization）— 🟡 有，但全是规则

**我们的实现**：`Personalizer` 从偏好画像出发，推荐文章/产品/课程、相关内容、
`personalizedCta`、`rankForProfile`；`DynamicContent` 规则式动态内容
（dynamic-rules.json）；`PromoSystem`（上轮做）区块级定向。

**判断**：**个性化能力存在，但全是"规则/相似度"驱动**——按偏好标签匹配、
按规则显示。这正是"过去的个性化做不透"的写照：**它能对不同分群显示不同东西，
但决策逻辑是人预先写死的规则**，不是针对"这一个人此刻"的判断。达不到
"千人千面地对的人说对的话"。

**竞品标杆**：Braze（人群 + Liquid 个性化 + 智能渠道/时机）、
HubSpot（smart content 按属性变）、神策（智能推荐/智能运营）。

**差距**：都还在"规则/分群个性化"层，包括竞品——**真正"AI 逐人决策"的个性化，
全行业都没做透**。这恰是我们该抢的位置（见创新层）。

### 4. 渠道与触达（Channels）— 🟢 广，依赖外部

**我们的实现**：邮件（Mautic/BillionMail）、短信、微信、通知渠道、campaigns、
频控（`FrequencyCap`）。

**判断**：渠道面广、有频控（很多自建 MA 没有频控，导致骚扰）。深度（送达治理、
智能时机、渠道择优）依赖外部 MA。

**竞品标杆**：Braze（多渠道 + 智能时机 send-time optimization + 渠道择优）。

**差距**：缺"智能发送时机""跨渠道择优"——但这些也该是 Agent 决策的一部分，
不必单独做成规则功能。

## 范式判断：可视化画布是"前 Agent 时代"的产物

把上面串起来看，会发现一个更根本的事实：**整个"可视化自动化画布"品类
（HubSpot/Braze/n8n/神策，也包括我们现在的 Canvas），是一个时代的产物——
那个时代，机器不会自己判断，所以必须由人把每一个"如果…就…"预先连成流程图。**

这个范式有三个天花板，且是结构性的、加功能补不上的：

1. **只优化效率，不解决增长**：流程图对一千个人跑的是同几套预设，本质是
   "把群发做得更聪明一点"，不是"对每个人做对的事"。
2. **门槛与经验依赖**：要配好流程，既要懂工具（连节点），又要有营销经验
   （知道该连什么）。无团队的用户两样都缺。
3. **节点爆炸**：真要千人千面，得为无数情形各连一条分支——人力上不可能。

**结论**：把画布做得更强（更多节点、更多动作），是在一个有天花板的范式里
内卷。真正的破局是**换范式**——用会判断的 Agent，取代"人预先连好每个决策"。

## 创新方向：从"人连流程图"到"Agent 千人千面地决策"

> 这是全系列最重要的一节，因为它把内容、CDP、Sales 的创新收束成一件事。

### 核心：把 MA 从"流程执行器"变成"增长大脑"

不再让人连流程图，而是给 Agent 一个**目标**（这个人转化/这批人复购/这条线索
成交）和一套**可用动作**，让它**针对每一个人、在每个时刻，自己决定下一最佳动作
并执行**。这需要四样东西——**而这四样正是我们四个模块各自的创新，本就是一体**：

- **看得懂人**：CDP 实时画像 = Agent 的决策上下文（CDP 创新一）。
- **写得出内容**：渲染时生成式个性化 = Agent 现场产出这个人该看的文案/落地页
  （内容创新三）。
- **做得成交易**：收款链接/留资等可执行动作 = Agent 的手（Sales × 内容创新②
  的"可执行标记"）。
- **会判断决策**：MA 从触发-动作，升级为"Agent 读画像 + 目标 → 决定 NBA →
  调上面三样执行 → 看结果再决策"的闭环。

**一句话**：别人的 MA 是"你画一张流程图，系统照着跑"；我们的是"你定一个目标，
Agent 替你千人千面地把它跑成"。**这就是"AI Agent 时代原生"**——不是老画布 +
AI 按钮，而是 Agent 站在画布的位置上。

### 为什么 HubSpot/Braze 结构上做不到这一点

它们的**核心资产就是那张画布**——产品、定价、用户心智、生态全建在"人配流程"
上。给画布加 AI（帮你写文案、建议下一节点）是**外挂**，因为一旦"Agent 直接
决策"取代画布，它们的整个产品形态与商业模式就被掏空。**在位者的核心资产
恰是它转型的枷锁**。我们没有这个包袱——我们本就是围绕 CDP + AI 引擎 + MCP
新建的，可以直接把 Agent 放在决策位。这是新产品对在位者的结构性机会。

### 落地路径：渐进自治（不是一步到全自动）

全自动决策有品牌/花钱/翻车风险，务实的路是**分级放权**（也是我一贯的旁路+
护栏做法）：

1. **Agent 提议，人批准**：进群/触发时，Agent 基于画像给出"对这个人此刻最该做
   什么 + 理由"，人一键采纳。（筹码现成：segment_enter 已接 flow + CDP + AI）
2. **护栏内自动**：低风险动作（推荐内容、站内提示、打标）Agent 直接执行，
   高风险（发钱/群发/改价）留人工关口。
3. **目标制自治**：给一批人设目标 + 预算/频控护栏，Agent 自主决策并持续优化，
   人只看结果与例外。（对齐内容创新四"目标制内容"、CDP 创新三"自主 NBA"）

### 画布不废——降级为"可解释轨道"与兜底

Agent 决策不能是黑箱。保留画布作为**可解释、可审计、可干预**的一层：
Agent 的决策渲染成一条可视轨迹（为什么对这个人做了这件事），人能看、能改、
能加护栏；没配 Agent 或 Agent 不确定时，回落到人配的确定性流程。**从
"人必须连"变成"人可以看和纠"。**

## 我们能做什么 · 按可行性排

**现成筹码、近可落地：**
1. **NBA 提议器**：segment_enter/关键事件时，Agent 读画像 + 目标，产出"下一最佳
   动作 + 理由"，人一键采纳。（CDP + AI + flow 全现成，是"Agent 决策"的第一形态）
2. **画布补关键动作**：打标/打分/改阶段/加券/推送/webhook/等待事件——让现有
   画布先够用（守），同时为 Agent 提供"可调用的动作库"（攻的基建）。
3. **规则个性化 → AI 个性化**：把 `personalizedCta`/`DynamicContent` 从规则匹配，
   升级为"AI 按画像现写"（接内容创新三的 AI 区块）。

**需更多投入：**
4. 渐进自治的护栏与目标制回路（预算/频控/关口 + 效果闭环）。
5. Agent 决策的可解释轨道 UI（画布降级为观测与干预层）。

## 小结

- **换靶子**：MA 的核心不是自动化，是个性化；个性化最需要 AI，因为它是人
  （配节点、靠经验）一定做不好、而 Agent 能做的事。
- **换范式**：不卷画布的节点丰富度（有天花板的内卷），把 Agent 放到决策位，
  从"人连流程图"到"Agent 千人千面地决策"。
- **这是收束点**：内容（生成）、CDP（上下文）、Sales（动作）、MA（决策）四个
  模块的创新，本就是同一个"增长大脑"的四个器官。MA 是把它们接成回路的那颗心脏。
- **对在位者的结构机会**：HubSpot/Braze 的核心资产是画布，Agent 决策会掏空它，
  所以它们只能外挂 AI；我们没包袱，可以直接原生。这就是"AI Agent 时代原生系统"
  这句话真正的、可辩护的含义。
