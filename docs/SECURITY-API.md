# API 权限矩阵

> 92 个 API 端点谁能调。后台页面 `/xmp/api-permissions` 可逐个调整，改完立即生效。
> 实现见 `lib/ApiPolicy.php`，执行点在 `admin/config.php` 末尾。

## 为什么会有这一层

后台页面的权限一直是有的——**169 / 191** 个页面做了 `require_perm` 判断，做得不差。
但 **API 层此前只有 1 / 92** 个端点做权限判断。

这不是理论风险。就在补这层之前，从里面挖出了三个「公开 + 免登录 + 每次花钱」的 AI 端点，
其中一个还会把**公司知识库**注入上下文回答匿名请求，并且能**真的创建自动化流程**。

## 为什么不是改 92 个文件

所有 `api/*.php` 的第一行都是 `require_once admin/config.php`——**这是一道现成的统一关卡**。
在关卡里按脚本名查一张表就行：

- **92 个端点文件一个都没动**，也就不存在"漏改了一个"
- 新增端点自动纳入（默认公开），不会因为忘了加检查而裸奔
- 想改哪个，改表就行，不用碰代码

和当初把 CSRF 收口到 `require_login` 是同一个套路：**在唯一必经之路上做事，
比在一百个地方各做一遍可靠。**

## 四个档位

| 档位 | 含义 | 判定 |
|---|---|---|
| `public` | 访客可访问 | 不拦。前台渲染、埋点、订阅、退订这些本来就该开放 |
| `member` | 需前台会员登录 | `member_current()` |
| `admin` | 需后台登录 | 后台 session；还可再要求某个具体权限，那样 marketing / sales 角色会被按权限区分 |
| `token` | 机器对机器 | **本层不拦**。端点自带密钥或签名（如微信服务器验证要求可匿名访问），只做登记，免得两套校验互相打架 |

## 默认取值的原则

> **默认不改变现有行为。**

只有**明确是后台工具**的端点才标 `admin`，判定标准很死：
**逐个 grep 过调用方，确认只有 `admin/` 下的页面在调**。
只要有一个前台页面在调，就不进表——**宁可漏收，不可误伤**。
其余一律 `public`，也就是跟改之前一模一样。

这条原则由 `tests/api_policy_test.php` 第 1 组**自动核对**：
凡是标成非 public 的端点，必须没有任何前台调用方。
以后谁往表里加一条标错了，测试就红——不靠人记得去查。

当前结果：**21 个端点需要身份**（改之前是 1 个）。

### 保持 `public` 的两个值得说的

- **`site-agent`**——它**本该公开**（访客要用的客服）。靠的是另一层保护：
  单 IP 10 分钟 20 次限流 + 访客侧独立的 AI 日额度。
  档位和限流是两件事，别用档位去解决限流的问题。
- **`wechat` / `wecom`**——微信服务器验证**要求可匿名访问**，标成 `token`：
  端点自带签名校验，本层不重复拦。

## 三种执行模式

| 模式 | 行为 |
|---|---|
| `enforce` | 真拦（默认）|
| `observe` | **只记录会拦谁，不真拦** |
| `off` | 整个机制不生效 |

> **上线不放心，就先切 `observe` 跑两天。**
> 它不拦任何请求，只把"本来会被拦的"记进后台那张表。
> 确认没有误伤自己的前台，再切回 `enforce`。
> 这是改访问控制的标准做法——**先看，再拦**。

后台那页的「拦截 / 观察记录」会显示端点、原因和来源页。
**如果看到自己前台的正常功能出现在里面，说明那个端点的档位定高了**，
回上面把它调回「公开」即可，立即生效。

## 怎么调整

后台 → 安全 → **API 权限矩阵**（`/xmp/api-permissions`）：

- 92 个端点一张表，档位和权限逐个下拉可改
- 改过默认值的会标「已自定义」
- 改完**立即生效**，不用重启、不用改代码
- 自定义保存在 `settings.json` 的 `api_policy` 字段，不动默认表

## 验收

`tests/api_policy_test.php`（52 项）。最关键的两组：

- **第 1 组**：自动核对"标成非 public 的端点没有任何前台调用方"。
- **第 11 组**：真的起一个本地服务器发 HTTP 请求——匿名打被锁端点必须 401、
  公开端点必须 200。**纯函数对不代表守卫真的挂上了**：
  脚本名识别、session、exit 时机，只有真发一次请求才知道。

## 留痕：同一道关卡顺带补上

后台的留痕早就是**结构性**的——`audit_auto()` 挂在 `require_login()` 里，
每个改状态的后台请求都会自动记，还带参数脱敏（密码 / token / 卡号一律抹成 `***`）。

但 `require_login()` 的注释里明写着「API 不调用它」——所以
**API 层一直是留痕的盲区**：谁通过接口改了什么，查不到。
这和权限是同一个形状的洞，就用同一道关卡补上：

| 档位 | 留痕 |
|---|---|
| `public` | **不记**。埋点、订阅这类高频匿名请求全记会把日志冲垮，而且本来也无名可查 |
| `member` / `admin` | 记（仅写操作）|
| `token` | **记**。webhook / cron / 数仓导出改的数据，机器改的也得查得到 |

只读请求不记。脱敏与"什么算写操作"的判定和后台**共用同一份实现**
（`audit_redact()` / `audit_write_verb()`），免得两边理解不一致。

## 顺带清掉的一个隐患

仓库根目录曾躺着一份 `config.php`（1849 行）——**是 `admin/config.php` 的旧副本**：

- 无人 include，`.htaccess` 也不路由到它
- 它 `require` 的 `seo-functions.php` / `review-lib.php` 只存在于 `admin/` 下，
  真被 include 会当场 fatal
- 但它带着一套**没有 CSRF 收口、没有自动留痕**的旧权限代码

最危险的地方不是它能被执行，是它**看起来像活的**——有人会照着它改，
或者把它当成权限逻辑的参考。已删除；`tests/api_policy_test.php` 里加了断言防止它回来。
真要找回：`git show <删除前的提交>:config.php`。
