# OpenFlow 产品战略升级方案（产品文档 v1.0）

> 定位：AI 时代的网站增长操作系统
> 商业模式：开源平台 + 插件/Skill 售卖平台 + API 聚合服务 + 定制咨询/落地服务
> 目标：超越市场平均水平的增长操作系统，而非功能累积体

---

## 0. 现状诊断（根因）

当前平台的本质问题是「需求累积」而非「产品设计」，四个根因：

1. **无统一信息架构（IA）**：入口按系统领域堆砌，不按用户任务组织
2. **功能孤岛**：获客→转化→留存→变现→传播 没有串成闭环链路
3. **商业模式未贯穿**：底层能力（插件/skill/API/咨询）不是一等公民，未贯通全站
4. **对外体验缺失**：后台深度能力没有外化为前端可感知的价值

---

## 1. 信息架构重构：从「功能堆」到「任务流」

### 1.1 后台顶级入口（重构后）

保留 5 大模块作深度管理，新增「工作台」为默认首页：

```
工作台（默认）   → 今日待办 · 实时指标 · AI洞察 · 快捷任务
Touch（内容触点） → 内容生产全链路
Insight（数据洞察）→ 用户与增长分析
个性化           → 转化与自动化
Sales（商业）     → 商业中心（商品/订单/分销/生态）
Settings         → 平台配置
```

### 1.2 任务流重组（同一任务不再跨模块）

| 任务 | 当前分散入口 | 重构为 |
|------|------------|--------|
| 发布内容到全网 | 文章编辑→日历→分发→社媒 | **内容工作台**（创作→预览→分发→效果） |
| 了解用户 | CDP→画像→分群→实时 | **用户洞察台**（画像→行为→洞察→分群） |
| 做增长实验 | 落地页→CRO→A/B→自动化 | **增长实验台**（假设→实验→优化） |
| 变现 | 商城→分销→激活→会员 | **商业中心**（商品→定价→订单→分成） |
| 开发者 | 插件→skill→API→生态 | **开发者中心**（发布→管理→收益） |

## 2. 商业模式闭环（最高优先级）

### 2.1 目标四支柱架构

```
┌──────────────────────────────────────────────────┐
│              商业中心（统一结算层）                  │
│   商品模型 → 订单 → 支付 → 交付 → 分成 → 结算       │
├──────────────┬──────────────┬─────────────┬───────┤
│ ① 开源平台    │ ② 生态商店    │ ③ API聚合    │ ④ 咨询落地│
│ 开源版+商业版  │ 插件/Skill/   │ 数据/能力API  │ 诊断→方案 │
│ 能力分级       │ 主题发布购买   │ 订阅售卖      │ →实施服务 │
└──────────────┴──────────────┴─────────────┴───────┘
```

### 2.2 数字商品模型（核心数据结构）

新建 `data/products.json`，统一四类资产：

```json
{
  "products": [{
    "id": "prod_xxx",
    "type": "skill|plugin|theme|api_plan|consultation",
    "asset_id": "skill_xxx",           // 关联具体资产
    "title": "AI 增长诊断 Skill",
    "description": "...",
    "pricing": {
      "mode": "one_time|subscription",
      "price": 99,
      "period": "month|year",          // 订阅周期
      "trial_days": 7,                 // 试用
      "free": false
    },
    "author": "user_xxx",              // 作者
    "commission_rate": 0.7,            // 作者分成比例
    "status": "draft|published|off",
    "sales_count": 0,
    "rating": 4.5,
    "created_at": "..."
  }]
}
```

### 2.3 购买与交付闭环（新建 `lib/CommerceSystem.php`）

```
购买流程：
用户点击购买 → 创建订单(goods_type=product)
  → 支付(虎皮椒/微信支付)
  → 支付回调 shop_mark_paid
  → 按 goods_type 自动交付：
      skill     → 写入 members.unlocked_skills + 下载
      plugin    → 生成安装包/授权码
      api_plan  → 激活 ApiKeyAuth 套餐配额
      theme     → 解锁主题
  → 记录分成（作者佣金入账）
  → 发送通知/邮件
```

### 2.4 开发者分成结算（新建）

- `lib/CommissionSystem.php`：订单成交 → 按 commission_rate 结算作者 + 平台抽成
- 作者中心：我的资产/销售额/佣金/提现申请
- 前端 `member.php?view=developer`：开发者仪表盘

### 2.5 API 套餐售卖（升级 ApiKeyAuth）

- ApiKeyAuth 增加 `plan_id`、`quota`、`expires_at` 字段
- 新增 `api_plan` 商品类型：按调用量/月费售卖
- 前端 `api-console.php`：注册→领 Key→选套餐→试调

## 4. 后台体验优化

### 4.1 AI 配置重构（`admin/ai-config.php`，最高优先）

现状：多行表单堆，无校验无预设。
重构：
1. **预设供应商模板**：OpenAI/DeepSeek/Kimi/豆包/元宝/GLM 一键选择预填 URL+模型
2. **测试连接按钮**：填 Key 后立即验证（调 AiCenter::chat 试发）
3. **用量看板**：各 provider 调用次数/费用/失败率（读 ai 日志）
4. **模型下拉**：预置常用模型 + 自定义
5. **全局提示词管理**：分场景（标题/摘要/评分/洞察）预置模板

### 4.2 工作台（默认首页 `admin/workspace.php`）

聚合：
- 今日待办（内容日历+审核+待跟进线索）
- 实时指标（RealtimeData::local）
- AI 运营洞察（CdpInsight）
- 快捷入口（写文章/发内容/加线索/查实时）
- 系统健康（备份/存储/错误日志）

## 8. 开放问题（已决策）

| 决策点 | 结论 |
|--------|------|
| 支付方式 | **双轨**：虎皮椒（先上线）+ 微信支付直连（后续补） |
| 资产上传 | **双通道**：后台 zip 上传（管理）+ 前端开发者自助上传（带审核流） |
| API 计费 | **双模式**：Go 模式=按月订阅（含 5 小时/天/周频率上限）；Zen 模式=按调用量计费 |
| 开源版边界 | 核心全开源；变现靠生态商店（skill/插件/主题）+ API 聚合 + 咨询落地服务 |

### API 套餐计费模型（Go / Zen 双模式）

```
Go 模式（订阅制，适合稳定调用）
├── 月费：¥X/月
├── 配额：每 5 小时上限 N 次 · 每天上限 M 次 · 每周上限 K 次
└── 超出：按量加收 或 限流

Zen 模式（按量计费，适合弹性/测试）
├── 预充值余额
├── 按每次调用扣费（按端点/模型差异化定价）
└── 余额不足自动降级为免费档或停用
```
