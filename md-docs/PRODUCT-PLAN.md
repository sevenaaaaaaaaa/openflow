## 十三、产品体验整合：三条主线（核心方法论）

> 功能已很散，靠"主线"串起来才有竞争力。OpenFlow 以 **Flow（流动）** 为主轴，
> 把 40+ 页面重组成三条闭环，每条线每步都有数据 + 操作入口，运营每天打开就知道下一步。

### 主线 A：内容流（Content Flow）— 从洞察到互动
知识库 → 创作（文章/课程/资料） → 发布 → 分发（SEO/公众号/邮件/直播/Campaign） → 互动（评论/点评/社区） → 回收洞察（分析反哺创作）
- 联动：发布自动 IndexNow（flow_content_published 已接）
- 入口：admin/flow.php

### 主线 B：数据流（Data Flow）— 从匿名到画像
埋点（track.php） → CDP 建档 → 识别（注册/登录合并） → 行为打标/评分 → 线索 → CRM 管道 → 成交
- 联动：行为自动打标 + 评分 + 识别合并（flow_handle 已接）
- 入口：admin/flow.php + admin/cdp.php

### 主线 C：价值流（Value Flow）— 从免费到复购
免费内容 → 培育（自动化/画布） → 转化（课程/咨询/订阅/直播） → 会员权益 → 复购/推荐
- 联动：支付 → CDP LTV + 积分 + 站内信；行为 → 积分；事件 → 通知（已接）
- 入口：admin/flow.php + admin/membership.php

### 已落地的跨模块联动（FlowSystem 统一事件总线）
| 触发 | 联动动作 |
|---|---|
| 埋点 page_view/course_view 等 | CDP 建档 + 打标 + 评分 |
| 表单提交 | 自动生成 CRM 线索 + CDP 关联 + 自动化触发 |
| 资料下载 | 线索门禁 + CDP 打标 + 积分 |
| 注册/登录 | CDP 匿名→已知合并 + 积分 |
| 订单支付 | CDP 打标 + LTV + 积分 + 站内信 |
| 文章发布 | IndexNow 收录 |
| 咨询/直播/投稿 | 站内信自动通知 |

2. **结算模型**（复用现有 shop/xfpay + 分销佣金）：
   - 付费 Skill：作者分成 80%，平台 20%
   - 打赏：全额作者（平台免抽佣）
   - 插件订阅：月/年付，作者 70%
3. **作者账户**：member 增加 `developer` 角色字段 + 余额 `developer_balance`，可提现（复用 ambassador 提现流程）。
4. **数据表**：`data/marketplace/sales.json`（skill_id → 订单）、`data/marketplace/developers.json`。
5. **后台**：`admin/marketplace.php?tab=developers` 作者列表、销售额、结算记录。

**实施步骤**：
- [ ] ① developer 角色 + 余额字段（MemberSystem）
- [ ] ② 付费 Skill 下单 API（复用 shop_create_order，goods_type=skill）
- [ ] ③ 作者收益入账 + 提现审批
- [ ] ④ 后台作者管理

### B. 插件/技能付费（P1）
在 Skill 资产上加 `price` 字段：
- `price=0` 免费；`price>0` 需购买后安装/执行。
- 付费技能在前台市场显示价格 + 「购买并安装」。
- 复用现有订单系统（course_id 扩展为 `skill:{id}` 或 `plugin:{id}`）。
- 已购用户技能库直接解锁，未购用户提示购买。
- 平台抽佣按 A 的模型。

### C. 作者主页（P1）
- 前台 `/author.php?id={developer_id}`：作者介绍、已发布技能/插件/主题、评分、粉丝数、累计安装。
- member 增加 `bio`、`avatar`、`website` 开发者资料字段。
- 市场资产卡点击作者名 → 跳作者主页。
- 激励闭环：作者主页是沉淀粉丝与口碑的核心载体。

### D. 市场 AI 运营建议（P1）
复用现有 AI 能力，为运营提供智能决策：
1. **AI 选品**：分析市场下载/评分数据，AI 生成「本周热门趋势」「推荐开发方向」（哪些技能缺口大）。

## 十六、自我进化（自生长系统）

### 定位

OpenFlow XMP 不是一次性交付的工具，而是**会随使用生长的系统**。核心区别：
- **不是客制化**（从预设选项里挑选），而是**生长**（从行为中涌现结果）
- **部署后的第一天**它还是「出厂形态」，从那天起记录你的每次使用、采纳、忽略、偏好
- **每个人最终长成不同的形态**——内容型站会长成内容中心型，销售型站会长成商业转化型

### 三层架构（已落地）

| 层次 | 模块 | 职责 |
|------|------|------|
| 自我进化 | SelfEvolve | 自动体检（错误/404/空数据/性能）+ 迭代建议 + 价值排序 + 关联诊断 |
| 生长引擎 | GrowthEngine | 行为信号 + 形态画像 + 个性权重 + 时间线 + 形态对比 + 周期报告 |
| 人机协同 | SafeFix | 生成补丁 → 人工确认 → 应用 → 回滚（绝不自动改代码） |

### 已实现的能力

1. **自动体检**：PHP/JS 错误、404 路由、空数据模块、页面性能
2. **价值排序建议**：`严重度 × 个性权重 × 复发趋势 × 影响面`
3. **关联诊断**：症状链（空数据→404）+ 高频错误源定位
4. **建议转任务 / 修复验证 / 建议过期**
5. **形态画像**：五种形态（内容中心/增长驱动/商业转化/社区运营/开发者友好）
6. **人机协同修复**：补丁 diff 预览 + 人工确认 + 备份 + 回滚
7. **形态驱动前台**：学院「为你推荐」随形态变化

### 下一步方向（待评估）

- 建议规则可配置（阈值/权重后台可调）
- 生长数据导出/迁移
- 半自动修复扩展更多规则（仍人工确认）
- 形态驱动扩展（首页/课程/生态模块排序联动）
- 多角色形态（站点级 + 角色级双层画像）
