01 · 范式
同一套系统，两种挡位

手动挡 Flow · 自动挡 Loop

Flow · 手动挡

你设计流程，系统确定性执行

节点、画布、规则、分支都由你定；AI 只当 Copilot，帮你搭、帮你查、帮你优化。适合已经跑通的 SOP，以及交易、交付、通知这类要求可预测与合规的业务。

可检查可预测可回滚
Loop · 自动挡

你定目标与边界，Agent 自己找路径

读真实业务状态 → 按 TIPS 订策略 → 调用 Skills 与成熟 Flow → 在策略约束下执行或请求审批 → 用业务结果进下一轮。适合「知道想要什么，但不知道最佳路径」。

有目标有预算有停止条件

挡位可以换，方向盘永远在你手里。成熟 Flow 会变成 Agent 的 Skill；验证过的 Loop 固化成新的 Flow——经验因此可以复利。

「拔掉任何一个」不是口号

它靠四个结构性决定，而不是靠承诺。

机制怎么做的

代价也说清楚

不需要你把现有栈推倒

你已有的怎么办我们接管的那一段

三种合作深度：叠加（一样不动，只补接缝）→ 替换（接管其中一段）→ 私有化（整套进你的机房）。

03 · 落地
30 / 90 天

试点只跑一个场景，验收只认三样。

Day 0 – 7
诊断与基线

看真实数据与现有流程，找出「最该交给 Agent 的那一段」，并定 3 个可量化基线。

我方：1 名交付 + 产品直连
你方：1 名能拍板的 DRI
Day 8 – 30
试点：一个场景、一条链路

在沙盘先跑，再上生产；只做一个场景，做到能回滚、能审计、有人能接手。

交付物：可运行链路 + 交接文档
验收：跑通 / 可回滚 / 能接手
Day 31 – 90
扩展与固化

第 2–3 个场景接入；把验证有效的 Loop 固化成 Flow，写进你们的 SOP。

你方：每周 2 小时对齐
退出条件：你不需要我们也能跑

03 · 边界
把丑话说在前面

我们不做的事、需要你配合的事、
以及现在还没有的东西。

我们不做

  • 不替代中大型企业的全套 BI / 重型 CRM / 通用电商
  • 不承诺还没做出来的功能（见 P18 右列）
  • 不接管你的数据所有权，也不做数据倒卖

需要你配合

  • 一个能拍板、且愿意每周花 2 小时的 DRI
  • 一个真实场景 + 现有数据（哪怕是 Excel）
  • 允许先沙盘后生产，别拿线上当试验田

已知缺口

  • 无独立安全审计 / 等保
  • 无 SLA 承诺文件
  • 客户案例尚未获授权公开
  • 统一登录 / 统一计费未定

这几条我们会写进合同附件；能提前说清的，不在交付时吵。
